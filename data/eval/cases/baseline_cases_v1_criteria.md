## 2. CSV 형식

열 5개: `qid, question_text, trap_types, trap_evidence, note` (UTF-8, BOM 없음, LF, 48행)

| 열 | 내용 |
|---|---|
| `qid` | 양식 문항 ID. **결합 키.** A 라벨 CSV 가 `(stage, qid)` 로 행을 식별하므로 별도 라벨 참조 열을 두지 않는다 |
| `question_text` | 양식 `Question.text` 원문 |
| `trap_types` | §3 의 7개 값 중에서만. 복수면 `;` 로 잇는다. `normal` 과 `no_evidence` 는 **단독**이다 |
| `trap_evidence` | `<파일명>:p<쪽>:"<인용>"`, 여럿이면 ` \| ` 로 잇는다. **쪽은 1-기준**(`p1` = 첫 쪽). 증빙이 없는 행은 `증빙없음` |
| `note` | 원본에서 확인한 **사실만**. 맨 앞에 `evidence=none.` 또는 `evidence=present.` 접두를 붙인다 |

**단계 열은 두지 않는다.** 단계 구분은 A 라벨의 `stage` 가 들고 있다.
**단계에 따라 사실이 달라지는 행은 `note` 에 두 단계 사실을 모두 적는다**(이 세트에서 단계에 따라
달라지는 문서는 `13` 하나뿐이고, `14`~`18` 은 두 단계에 모두 있다).

### 2.1 `note` 작성 규칙 — 라벨은 A 의 소유다

- `note` 에 **응답의 옳고 그름을 판단하는 문장을 쓰지 않는다.** 어떤 응답이 맞다/틀리다, 보류가 맞다,
  확정이 가능하다는 서술을 넣지 않는다.
- 쓰는 것: ① 무엇이 있고 무엇이 없는지(조항·기록의 존재·부재) ② 기간·사업장·분모·인원 같은 수치
  ③ **문서가 스스로 밝힌 범위 문구**(`<문서> 가 스스로 밝힌 범위: …` 형태로 출처를 붙인다)
  ④ 고객 요청서(`00`)가 지정한 범위.
- 생성기가 금지어(`올바른`, `확정 불가`, `확정 가능`, `틀린다`, `정답`)를 검사한다. 하나라도 걸리면
  CSV 를 만들지 않고 종료 코드 1.

### 2.2 기계 검증

CSV 는 생성기(`make_cases_csv.py`, 저장소 밖 `outputs/eval/_scripts_P3-1/`)가 만들고 아래를 검사한다.
하나라도 실패하면 파일을 쓰지 않는다.

1. 48행이 양식 문항과 1:1 (누락·초과 0)
2. `trap_evidence` 의 **모든 인용이 해당 원본 PDF 의 해당 쪽 텍스트에 문자열로 존재**
3. `trap_types` 가 허용 7값 안
4. `no_evidence` ↔ `trap_evidence` 교차: `no_evidence` 인데 인용이 있으면 실패, 인용이 없는데
   `no_evidence` 가 아니면 실패
5. `normal` 단독성
6. `note` 접두가 `evidence=none.` / `evidence=present.`
7. `note` 금지어 0건

## 3. `trap_types` — 7개 값과 표시 조건

함정 유형은 **원본 문서와 고객 요청서의 성질**이고, 특정 시스템의 응답 결과가 아니다.
분류는 실행 전에 확정하며 결과를 보고 다시 분류하지 않는다.

| 값 | 표시 조건 |
|---|---|
| `denominator_meaning` | 같은 지표 이름에 **분모가 다른 수치가 둘 이상** 원본에 있고, 각 분모 정의가 원문에 적혀 있다 |
| `partial_scope` | 증빙 문서가 **스스로** 포함하지 않는 범위·측면을 명시한다(§3.3) |
| `period_mismatch` | 원본에 **"이 기간 값으로 요청·지표 기간을 대체할 수 없다"는 문구가 명시**돼 있다(§3.1) |
| `conducted_vs_completed` | 원본에 **"실시·참석·전달 기록만으로 완료·이수를 확정하지 않는다"는 문구가 명시**돼 있다 |
| `single_policy_multi_yes` | 존재형 문항이고, 규정 문서(`06`·`10`·`11`)의 조항이 **그 문항 주제의 일부라도 직접 다루어** 규정만으로 "예"가 가능하며, 그 규정이 "보유만으로 실시·준수가 입증되지 않는다"고 스스로 명시한다(§3.2) |
| `no_evidence` | 세트에 **그 문항 주제 자체를 다루는 기록·규정 조항이 없다**(§3.2 경계) |
| `normal` | 증빙이 있고 위 함정 유형 어디에도 해당하지 않는다(§3.4) |

### 3.1 `period_mismatch` — 좁은 정의 (확정)

**"4월 월간 증빙이다"라는 사실만으로는 표시하지 않는다.** 원본에 기간 대체 불가가 명시된 행만 표시한다.

이유: 고객 요청서(`00`)가 A-01·A-02 를 **2026년 4월·김해 제1공장으로 지정**했으므로 그 범위의 월간
증빙은 기간 불일치가 아니다. 반면 `01`·`03`·`06`·`12` 는 "월 값으로 연간을 대체할 수 없다" /
"지정한 한 주의 기록만 포함한다"를 각각 명시한다. 이 명시가 있는 행만 표시했다.

고객 요청서는 이전 세트와 sha256 이 같아(§1.2) A-01~A-08 의 기간·사업장 지정이 그대로다.
그래서 이 정의를 새 세트에도 그대로 적용했다.

### 3.2 `single_policy_multi_yes` 와 `no_evidence` 의 경계 (확정)

**기준: 문항 주제의 일부라도 직접 다루는 조항이 있으면 `single_policy_multi_yes` 를 유지한다.
주제 자체를 다루는 조항이 없을 때만 `no_evidence` 다.**

- 조항이 문항 주제의 **일부만** 다루어도(예: 여러 구성요소 중 하나) 규정만으로 "예"가 나올 수 있으므로
  함정으로 표시한다. 덮이지 않은 구성요소는 `note` 에 "…기록·조항은 없다"로 적는다.
- 반대로 주제를 가리키는 조항이 **아예 없으면** 인접한 다른 주제의 조항이 있어도 `no_evidence` 다.
  이때 `trap_evidence` 는 `증빙없음` 으로 비우고, 인접 조항이 무엇이고 무엇이 없는지를 `note` 에 적는다.
- **운영 기록이 생겨 "규정 1건으로 예가 된다"는 구조 자체가 깨진 행은 이 유형을 떼고** 남은 함정 축으로
  표시하거나 `normal` 로 둔다.

### 3.3 `partial_scope` 를 적용한 '측면'

작업지시서 §4.1 표의 예시는 사업장·에너지원 범위였다. 이번 세트에서는 **문서가 스스로 밝힌 "포함하지
않는 범위"가 아래 측면에도 걸렸고, 같은 조건(문서 자체의 명시)으로 표시했다.**

| 측면 | 뜻 |
|---|---|
| 사업장 | 두 공장 중 한 공장만 포함한다고 문서가 밝힌 경우 |
| 기간 | 한 달·한 주만 포함한다고 문서가 밝힌 경우 |
| 에너지원 | 전력만 환산 가능하고 다른 에너지원은 환산 계수를 제시하지 않는다고 문서가 밝힌 경우 |
| 처리경로 | 외부 위탁분만 포함하고 내부 재투입분은 제외한다고 문서가 밝힌 경우 |
| 분모 구성 | 비율의 분자·분모 구성 요소를 문서가 한정한 경우 |
| 위험 요인 종류 | 기계 위험만 평가하고 전기·화학·인간공학 요건은 종합 판정하지 않는다고 문서가 밝힌 경우 |
| 리스크 영역 | 안전보건 리스크만 평가하고 전사 법규 준수 결론을 대신하지 않는다고 문서가 밝힌 경우 |
| 공개 정보 종류 | 전달·공개한 정보의 종류를 문서가 한정한 경우 |
| 공급사 관리 단계·공급망 계층 | 전달·수령까지만 기록하고 자격·허가 확인을 의미하지 않는다고 문서가 밝힌 경우 |

측면을 늘릴 때의 조건은 바뀌지 않았다 — **문서가 스스로 밝힌 문구가 있어야 한다.**
"요구를 다 못 채웠다"는 내 판단만으로는 표시하지 않는다(그런 행은 `note` 에 부재 사실만 적는다).

### 3.4 `normal` 판정 기준

아래 두 조건을 **모두** 만족할 때만 `normal` 이다.

1. 문항이 요구한 구성요소가 원본에 전부 있다(기간·사업장 범위 포함).
2. 그 증빙 문서가 **그 문항에 대해** 범위·한계 문구를 달지 않았다. 문서의 한계 문구가 **다른** 문항을
   겨냥하는 경우는 `normal` 을 막지 않는다.

`normal` 은 억지로 만들지도 빼지도 않는다. 새 문서가 닿았지만 구성요소가 덜 찬 행은 `normal` 로
올리지 않고 해당 함정 유형으로 둔다.

### 3.5 분류 범위 규칙 (재작성 시 적용)

이전 세트 기준 분류를 새 세트로 옮길 때 쓴 규칙이다.

1. 새 문서(`14`~`18`)가 증빙을 공급하는 행은 **새 원본 기준으로 다시 분류**한다.
2. 새 문서가 닿지 않은 행은 이전 분류를 유지한다. §3.2 기준상 의심되는 행은 바꾸지 않고 '후보'로만
   기록한다(§4.2).
3. 검사에서 내려온 결정은 그대로 적용한다(§4).

## 6. 이 문서가 정하지 않는 것

- **정답 라벨.** `expected_decision`·기대값·기대 근거는 A 가 소유하는 라벨 파일에만 있다.

- 대조군 프롬프트. `data/eval/prompts/baseline_prompt_v1.md` 는 공통 답안 형식 합의 후 별도로 커밋한다.
- 표현 규칙: 이 세트는 **팀이 만든 가상 자료**다. 결과를 "일반 AI 대비 N배" 같은 일반화로 쓰지 않는다.
