# 작업지시서 — 비정형 OCR(gpt-4.1-mini) 신뢰도 측정

> 발행: 2026-07-12 / 담당: (팀원 이름 기입) / 목표 기한: 결선 제출 전
> 배경: 정형 OCR은 `docs/OCR_정확도_측정결과_2026-06-23.md`로 3/3 측정됐으나,
> **비정형(gpt-4.1-mini) 채널은 채점셋도 측정 수치도 아직 없다.** 이는 "정성 항목 자동화"
> 로드맵의 명시적 블로커다 — 지금은 정성 항목을 자동 채울지 HITL로 넘길지 판단할 근거가
> 수치로 없다. 심사 예상 질문("정성 항목도 AI가 뽑는다는데 얼마나 믿냐")과 사업화
> 절단선(정량 자동 / 정성 HITL) 결정 양쪽의 방어 작업.

## 0. 시작 전 필독 (30분)

1. `docs/OCR_정확도_측정결과_2026-06-23.md` — 정형 측정의 기준선·표 형식. 이 문서와
   **같은 형식**으로 결과를 낼 것.
2. `scripts/ocr_accuracy_eval.py` — 정형 채점 스크립트. 비정형 채점기는 이 패턴을 확장한다.
3. `esgenie/ssot/ocr_router.py`의 `extract_unstructured`(L1237)·`_extract_unstructured_text`
   ·`_map_vlm_json`·`_augment_unstructured_clauses`. **핵심: 비정형 출력은 정형과 다르다.**
   - `OcrExtraction.metrics`(`ExtractedMetric`: value/unit/kesg_code_guess/confidence) = 정량
   - `OcrExtraction.clauses`(`ExtractedClause`: section/text/kesg_code_guess/rba_code_guess) = 정성
   - 엔진 = `gpt-4.1-mini-text` via Azure. 정형(템플릿·결정적)과 달리 **LLM 생성물이라
     환각(문서에 없는 내용 창작) 리스크가 있다.** 이 작업의 진짜 초점이 여기다.
4. `docs/labeling_rubric.md` — 라벨 기준·JSONL 스키마. 정성 사실 라벨링에 준용.

**핵심 원칙(정독):** 정형은 "숫자 하나가 맞나"만 보면 되지만, 비정형은 채점 축이 4개다
(라우팅 / 정량 / **정성 충실도+환각** / 신뢰도 캘리브레이션). 정성 충실도를 안 재면
이 측정은 반쪽이다. `clause.confidence`가 아니라 `metric.confidence`만 있는 점도 유의
(정성 신뢰도 신호 부재 자체가 발견 사항이 될 수 있음).

작업은 A·B·C 세 트랙으로 분리된다. A가 최우선(채점셋 없으면 B·C 불가).

## A. 비정형 라벨셋(정답셋) 구축 — 최우선

**왜**: 측정할 정답이 없다. 정형은 시연증빙 3종에 인쇄값 정답이 있었지만, 비정형은
정답셋 자체를 새로 만들어야 한다.

**할 일**:
1. 비정형 문서 **8~12개** 확보. 유형 다양화: 안전보건위원회 회의록·비상대응 매뉴얼·
   사내 환경/윤리 규정집·인권정책서·환경방침 등. **기존 `시연증빙세트_한울정밀공업/`의
   정성 문서 재활용 + 신규 확보.** 디지털 PDF와 스캔본(이미지)을 **섞을 것** — 스캔본이
   Upstage OCR→LLM 경로라 품질이 다르게 나올 수 있고, 그 차이를 재는 게 목적.
2. 문서마다 정답 3종을 사람이 작성:
   - **(가) doc_type 정답** — 라우팅이 맞아야 할 목표 타입.
   - **(나) 정량 정답 목록** — 문서에 실제 있는 수치 `(kesg_code, 값, 단위, 허용오차)`.
     정성 문서엔 수치가 0개일 수 있음(그것도 정답 = "정량 0건이어야 정상").
   - **(다) 정성 핵심사실 목록** — 문서가 실제로 담은 핵심 클레임 5~10개를 한 줄씩
     (예: "비상대응 절차에 대피 경로·집결지 명시", "노사협의회 분기 1회 개최 규정").
     이게 정성 recall/환각 채점의 gold다.
3. **두 명 독립 작성 → 불일치만 합의**, 일치율(%) 기록. 특히 (다) 핵심사실은 주관이
   들어가니 루브릭 기준을 명시하고 벗어난 개인 판단 금지.
4. `data/benchmark_ocr/unstructured_gold.json`로 저장(스키마는 B에서 스크립트와 함께 확정).

**금지**: 정답을 LLM 출력 보고 역으로 맞추기(순환). 정답은 **원문 문서만 보고** 먼저 짠다.

## B. 비정형 채점 스크립트 — 차순위(A와 병행 가능)

**왜**: 4개 축을 자동 집계해야 재현·재측정이 된다.

**할 일**: `scripts/ocr_unstructured_eval.py` 신설(`ocr_accuracy_eval.py` 패턴 확장).
축 4개를 각각 출력:

1. **doc_type 라우팅 정확도** — `route_document()` 결과 vs (가). 정형과 동일 방식.
2. **정량 수치 정확도** — `extract_unstructured().metrics`를 (나)와 대조(값·단위·허용오차).
   정형 스크립트의 `find`/허용오차 로직 재사용. **환각 수치(문서에 없는 값 창작) = false
   positive로 별도 집계.**
3. **정성 충실도(핵심)** — `extract_unstructured().clauses`를 (다)와 대조:
   - **recall** = gold 핵심사실 중 clause로 잡힌 비율(문자열 매칭 대신 사람 판정 또는
     LLM-as-judge 보조 — 판정 방식은 문서에 명시).
   - **환각률(precision 반대)** = 생성된 clause 중 **문서에 근거 없는** 주장 비율. 이게
     정성 자동화 가부의 결정타.
4. **신뢰도 캘리브레이션** — `metric.confidence`를 정답 여부와 대조해 ECE/reliability.
   `esgenie/evaluate.py`의 ECE·부트스트랩 로직 재사용 가능(입력 어댑터만 작성).
   clause엔 confidence 필드가 없으므로 정성은 캘리브레이션 대신 recall/환각률로 갈음하고,
   **"정성 신뢰도 신호 부재"를 한계로 기록**.

**주의**: 스크립트는 mock에서도 배선이 돌아야 함(`ESGENIE_FORCE_MOCK=1`). mock 수치는
무의미하니 리포트엔 실키 결과만 싣는다(정형 문서와 동일 원칙).
