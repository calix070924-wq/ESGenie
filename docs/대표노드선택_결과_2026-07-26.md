## 2. 작업 1 — 코드 부여 불일치 원인 (가설 반증)

**증상**: 동일 hint `Scope 3 온실가스 배출량 연결(일부)`이 2022년은 E-3-2, 2023·2024년은
E-3-1로 갔다. Scope3 값 3,344,082 / 3,136,024가 Scope1+2 후보 풀을 오염시켰다.

**사용자 가설(사전 통보된 확신도 중간)**: `_resolve_kesg_code` 사전 매칭과 LLM
`kesg_code_guess`의 경합. → **반증됨.**

```
resolve_kesg_code('Scope 3 온실가스 배출량 연결(일부)') == ('E-3-2', 0.9, 'exact')
```
사전은 세 노드 모두에 대해 E-3-2를 정확히 돌려준다. LLM 경합도 없다.

**실제 원인** — `ocr_router._backfill_kesg_codes`의 선착순 점유 가드:

1. 첫 번째 metric이 E-3-2를 받는다 → `taken_codes = {'E-3-2'}`
2. 두 번째·세 번째 metric(hint 완전 동일)은 `code in taken_codes`로 **skip** → `kesg_code_guess = None`
3. 코드 없는 metric이 `evidence_graph`로 내려가 `_HINT_TO_KESG` 폴백에 걸린다
4. 그 사전에서 `'온실가스'` → **E-3-1**

즉 중복노드 방지 가드가 다연도 표(같은 hint, 연도별 값)를 중복으로 오판했고,
그 부작용으로 하류 폴백이 다른 코드를 붙였다. 고치기 전에 end-to-end로 재현했다.

**수정**: `taken_codes: set[str]` → `taken_by_label: dict[str, set[str]]`.
라벨(`_normalize_label`)이 같으면 점유 여부와 무관하게 같은 코드를 준다.
다른 라벨의 점유는 종전대로 차단한다(지정폐기물 → E-6-1 유령 중복노드 가드 유지).

회귀: `TestCodeAssignmentConsistency::test_same_hint_always_resolves_to_same_code`(동일 hint 3건 → `{E-3-2}`),
`test_different_label_still_cannot_steal_taken_code`(기존 가드 보존).

## 3. 작업 2 — 공용 선택 함수와 두 호출부

신규 `esgenie/ssot/node_select.py`:

| 함수 | 역할 |
|---|---|
| `select_representative_node(code, nodes, *, report_year=None)` | 대표 노드 1개 또는 `None` |
| `is_derived_hint(hint)` | 파생·비실적 판정(테스트·감사용 공개) |
| `normalize_to_item_unit(code, value, unit)` | `(값, 단위, 플래그)` — 작업 3 |

우선순위(앞에서 갈리면 뒤는 안 본다):

```
1) 파생·비실적 hard 배제        감축·효과·예상·증감·원단위·목표·제로화·회수량 … (21종)
2) 코드별 negative keyword       E-3-1 ← Scope 3·1+2+3 / E-5-1 ← 재활용 …
3) 지표 계열 (신규)              E-6-1 발생량>배출량>처리량 / E-3-1 지역기반 우선 …
4) 세부 분해 (신규)              PPA·녹색요금제 / 매립·소각·미폐기 / 일반·지정 폐기물 …
5) 집계                          합계·총계·총 > 구분어 없음 > 국내(별도)·자회사·사업장
6) 단위 정합                     항목 단위 동일 > 환산 가능 > 그 외 (E-4-1 TJ 우선)
7) 연도                          report_year 근접 — **최후 tie-breaker**
8) 동률/후보 0                   None → 미공시 + confidence_flag
```

호출부 2곳(대칭):

| 파일 | 지점 | 변경 |
|---|---|---|
| `esgenie/ssot/ssot_pipeline.py` | `_merge_ssot_evidence` → `ocr_repr` | `_repr_key` 클로저 삭제, 공용 함수 호출 |
| `esgenie/layer3_detect.py` | `_score_d1_numeric` G5 | `min(compat, key=…)` 삭제, 공용 함수 호출 |

`scripts/inspect_ledger_provenance.py`도 같은 함수를 부르도록 고쳤다. 스크립트가 옛 연도
규칙식을 복제해두면 규칙 교체 후에도 원장에 없는 노드를 `←원장선택`으로 찍어 관찰이

### 8단계(미공시 폴백) — 구현 확인

전 후보가 1·2단계에서 배제되면:
- `select_representative_node` → `None`
- 원장: `result.mapped`에 코드를 **만들지 않는다**(정량 항목에 `"문서 조항 확인"`을 채우면
  미공시가 공시로 위장된다 — 승격 분기에 `if repr_node is None and not text_ids: continue` 추가)
- `confidence_flags[code] += ["no_representative_node"]` + `notes` 1줄
- **노드는 그래프에 그대로 남는다**(폐기 금지 — 감사추적)
- D1: `node is None` → 비교 스킵(오탐 안 냄)

회귀 4건: `TestUndisclosedFallback`.

### 작업 2-3 — `report_year 최근접` 강등

`feature/ledger-provenance`가 넣은 연도 규칙은 7순위 tie-breaker로 내렸다. 주석도 갱신했다.
`tests/test_ledger_provenance.py::TestRepresentativeNodeSelection`의 기대값은 유지되지만
**작동 이유가 달라졌다** — 그 테스트들은 hint 없는 얇은 노드를 쓰므로 3~6축이 전부 동률이라
연도 축까지 내려간다. docstring에 이 사실을 적었다.

`test_ledger_and_d1_pick_the_same_node`은 선택식을 복제하는 대신
`select_representative_node`를 직접 호출한다 — 복제하면 대칭 단언 자체가 무의미해진다.

## 7. 사용자 검증 커맨드 (라이브 1회)

```bash
python3 scripts/inspect_ledger_provenance.py --ticker 012330 --areas E \
        --json outputs/ledger_provenance_012330_v3.json
```

L0+L1만 돌고 L2~L5(LLM)는 타지 않는다 — 비용은 OCR 1회.

**기대값** (§1 표와 동일):

```
[E-3-1] ... 원장 : 396152.0 tCO2eq   (항목 단위 tCO2eq)
[E-4-1] ... 원장 : 7497.0 TJ         (항목 단위 TJ)
[E-5-1] ... 원장 : 1992921.0 ton     (항목 단위 ton)
[E-6-1] ... 원장 : 72463.0 톤        (항목 단위 톤)
[E-7-1] ... 원장 : 150670.0 kg       (항목 단위 kg)
[E-7-2] ... 원장 : 555124.0 kg       (항목 단위 kg)
```

요약 줄 기대값:

```
  선택 규칙 불일치(구조적 D1 오탐 후보): 0개 []
  원장 단위 ≠ 항목 단위: 0개 []
  비교 노드 없음(claim만 존재): 0개 []
```

- `선택 규칙 불일치`는 이제 **구조적으로 0**이어야 한다(두 경로가 같은 함수를 호출).
  0이 아니면 대칭이 깨진 것 = 회귀다.
- `원장 단위 ≠ 항목 단위`는 5개 → **0개** 기대. `⚠단위불일치` 마크가 사라진다.
- `no_representative_node` 플래그는 이 회사 E영역에서 **발생하지 않는다**(12코드 전부 선택 성공).
  뜨면 해당 코드의 후보가 전부 파생·비실적이라는 뜻이므로 hint를 확인해야 한다.

라이브 결과가 위와 다르면 v2 → v3 사이에 OCR 산출물이 달라진 것이므로, 값이 아니라
**어느 축에서 갈렸는지**를 먼저 봐야 한다(`hint` 컬럼이 출력에 그대로 찍힌다).

## 8. 후속 — 원장·D1 대칭의 남은 구멍 (2026-07-26 2차)

### 8-1. 문제: 공용 함수를 공유해도 대칭이 성립하지 않는다

§3에서 "두 호출부가 같은 함수를 부르므로 `선택 규칙 불일치`는 구조적으로 0"이라고 썼다.
**그 주장은 불완전했다 — 두 호출부가 다른 후보 풀을 넘긴다.**

| | 후보 풀 |
|---|---|
| 원장 `_merge_ssot_evidence` | `origin in (ocr_structured, ocr_unstructured)` + `node.metric` **정확 일치** |
| D1 `_score_d1_numeric` | `graph.search_nodes(keywords=[c])` — **DART 노드 포함**, substring 매칭 → claim 단위 필터 |

재현 (`test_symmetry_holds_when_dart_node_is_in_the_pool`):

```
풀: OCR  '용수 사용량(취수량) 국내(별도)'   623,648   (집계 축 2 = 부분)
    DART '용수 사용량(취수량) 합계'       1,992,921   (집계 축 0 = 총량)

원장 (OCR만)      →   623,648
D1   (DART 포함)  → 1,992,921     ← 같은 규칙, 다른 노드
```

현대모비스 E영역에서는 안 터졌다 — DART가 E 코드를 하나도 안 채워서 v2 JSON의 190개
노드가 **전부 `ocr_unstructured`** 다(측정 확인). 두 풀이 우연히 같았을 뿐이다.
DART 정규식이 채우는 코드(E-3-1·E-4-1·E-5-1·E-6-1)나 구조화 API가 채우는 G 코드에서는
재현된다. 기존 `TestLedgerD1Symmetry` 3건이 OCR-only 풀만 써서 못 잡았다.

이건 이번 트랙이 만든 회귀가 아니라 원래 있던 구멍이다. 다만 "대칭이 핵심 산출물"이라고
선언한 이상 여기까지 닫아야 §3의 주장이 성립한다.

### 8-2. 해결: 규칙을 두 번 돌리지 않고 결정을 공유한다

**풀 구성을 통일하지 않았다.** 원장이 OCR-only인 건 의도적 설계다 — DART 값은 이미
`report.kesg_data` → `result.mapped` 경로로 들어와 있고 OCR 승격은 그걸 보완하는 구조라,
DART 노드를 원장 풀에 넣으면 같은 데이터를 두 경로로 이중 처리하게 된다.

대신 원장의 **결정**을 그래프에 기록하고 D1이 그것을 따른다. 규칙을 두 번 돌리는 대신
결과를 공유하므로 풀이 달라도 구조적으로 어긋날 수 없다.

| 지점 | 변경 |
|---|---|
| `evidence_graph.EvidenceGraph.__init__` | `self.representative_node_ids: dict[str, str] = {}` 추가 — `report_year`와 같은 '레이어 간 합의' 슬롯 |
| `ssot_pipeline._merge_ssot_evidence` | 대표 노드를 고를 때마다 `graph.representative_node_ids[metric] = picked.id`. 미공시(None)는 기록하지 않는다 |
| `layer3_detect._score_d1_numeric` | `_ledger_representative()`로 기록을 먼저 찾고, 없으면 기존 `select_representative_node` 폴백 |
| `layer3_detect` (신규 헬퍼 2개) | `_repr_ids(graph)` · `_ledger_representative(graph, code, compat)` |

D1의 조회 순서:

```
1) representative_node_ids에 c가 있고 그 노드가 claim 단위 호환(compat)에 있으면 → 그 노드
2) 없거나 단위 비호환 → select_representative_node(c, compat) 폴백
   단위 비호환일 때는 detail에 "{code}: 원장 대표노드와 단위 비호환 → 폴백" 기록
```

단위 비호환 시 폴백하는 이유: 원장은 항목 정의 단위로 정규화(`normalize_to_item_unit`)해
저장하지만 노드 자체는 원 단위다. claim이 다른 환산군이면 그 노드로는 비교가 무의미하다.

**D1 축의 의미·가중치·점수식은 건드리지 않았다.** 교차 비교(`cand_codes`) 로직도 그대로다.

### 8-3. 관찰 지표가 자기 자신을 검증하고 있었다

`scripts/inspect_ledger_provenance.py`가 `ledger_pick`과 `d1_pick`을 **같은 인자로 같은
함수에 두 번** 넘겼다(§3에서 스크립트를 공용 함수로 고칠 때 생긴 것). 그래서
"선택 규칙 불일치 0개"는 항상 참이고 아무것도 검증하지 않았다. §7에서 이 줄을
기대값으로 제시한 것도 그래서 무의미했다.

각 호출부의 실제 풀 구성을 흉내내도록 고쳤다:

```python
ledger_pool = [n for n in nodes if n.origin in ("ocr_structured", "ocr_unstructured")]
d1_pool     = graph.search_nodes(keywords=[code])   # DART 포함, 단위 필터는 claim이 없어 생략
```

노드 줄 마크도 3종으로 늘렸다 — `←원장풀선택` / `←D1풀선택` / `★원장기록`.
세 값이 일치하는지 눈으로 확인할 수 있고, `★원장기록`은 실행 중 실제로 기록된 값이라
스크립트의 풀 재현이 원장과 어긋나면 `record_mismatch`로 드러난다.

요약 줄 문구도 정확한 이름으로 바꿨다:

| 이전 | 현재 |
|---|---|
| `선택 규칙 불일치(구조적 D1 오탐 후보)` | `풀 구성 차이로 갈리는 코드` |
| — | `원장 대표노드 기록 없음(D1 폴백 경로)` |
| — | `스크립트 재현 ≠ 실행 기록` (0이 아니면 스크립트가 틀린 것) |

### 8-4. 회귀 테스트 3건 — 구현 전 실패 확인

`TestLedgerD1Symmetry`에 추가. **작업 전 3건 실패(`AttributeError: 'EvidenceGraph' object
has no attribute 'representative_node_ids'`) → 구현 후 3건 통과**를 확인했다.
스탠드 실행으로 재확인: 변경 stash 시 24 passed, 복원 시 27 passed.

| 테스트 | 고정 내용 |
|---|---|

### 8-6. 사용자 검증 — §7 기대값 갱신

같은 커맨드(§7)를 쓰되 요약 줄 기대값이 달라졌다:

```
  풀 구성 차이로 갈리는 코드: 0개 []
  원장 대표노드 기록 없음(D1 폴백 경로): 0개 []
  스크립트 재현 ≠ 실행 기록: 0개 []
  원장 단위 ≠ 항목 단위: 0개 []
  비교 노드 없음(claim만 존재): 0개 []
```

- `풀 구성 차이로 갈리는 코드`: **현대모비스 E는 0개**가 나와야 한다. v2 JSON 190개 노드가
  전부 `ocr_unstructured`라 두 풀이 실제로 같기 때문이다(측정 확인). 이 회사에서 0이 나오는
  것은 "대칭이 검증됐다"는 뜻이 **아니다** — 갈릴 조건 자체가 없다. 대칭 검증은 8-4의
  DART 혼합 테스트가 한다.
- 0이 아닌 코드가 나오면 그건 기록 공유가 실제로 일하고 있는 지점이다. 노드 줄에서
  `←원장풀선택` / `←D1풀선택` / `★원장기록` 세 마크를 비교하면 어느 노드로 수렴했는지 보인다.
- `스크립트 재현 ≠ 실행 기록`이 0이 아니면 **스크립트의 풀 재현이 틀린 것**이다(원장 로직이
  아니라 관찰 코드를 고쳐야 한다).
- DART가 E 코드를 채우는 다른 회사(예: `--ticker 051910`)로 돌리면 풀 차이가 실제로
  드러날 수 있다. 그때 `풀 구성 차이` > 0 + `스크립트 재현 ≠ 실행 기록` = 0이면 정상이다.
