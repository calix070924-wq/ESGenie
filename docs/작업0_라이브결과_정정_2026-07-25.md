# 작업0 라이브 결과 — 경로 가설 반증 + 진짜 병목 확정

2026-07-25 · 현대모비스(00164788) E 영역 · `outputs/ledger_provenance_012330.json`

## 1. 내 경로 판정이 틀렸다 (정정)

`docs/역추적_claim오염_경로분리_2026-07-25.md`는 오염이 **[A] DART 정규식과 [B] OCR 양쪽에서
나온다**고 판정했다. 라이브 결과는 그렇지 않다.

```
[B] OCR 노드 승격 (게이트 통과): 12개
[A] DART 정규식: 0개
```

**E 영역 12개 항목 전부 [B]다.** DART 정규식은 이 회사 E에서 한 개도 채우지 않았다.

| 역추적 판정 | 실제 |
|---|---|
| 용수 114,884 = [A] 정규식 | **[B]** — 114,884는 2024 ton **노드로 그래프에 존재**한다 |
| Scope1+2 4.0 = [A] 정규식 | **[B]** — 2023 `4.0 ton CO2eq` 노드 |
| 에너지·Scope3 = [B] | [B] (맞음) |

오판 이유: 원장 114,884 ≠ D1 노드 623,648을 보고 "값이 다르니 다른 소스"라고 추론했다.
실제로는 **같은 노드 풀에서 서로 다른 노드를 골랐던 것**이다. 값 불일치는 소스가 둘이라는
증거가 아니라 선택이 흔들린다는 증거였다.

## 2. 그래서 작업1~3은 이 케이스의 D1을 못 내린다

| 작업 | 이 실행에서 | 이유 |

| 1 우선순위 역전 | **미발동** | 강등 대상인 `SOURCE_DART_REGEX` 항목이 E에 0개 |
| 2 대표노드 통일 | **효과 0** | 선택 규칙 불일치 0개 — 원장·D1이 이미 같은 노드를 고름 |
| 3 정규식 방어선 | **무관** | E를 정규식이 안 채움 |

셋 다 구조적으로는 유효하다(다른 회사·G 영역·OCR 실패 시 [A]가 값을 채우는 경로는 실재).
다만 **현대모비스 E의 D1=100에 대해서는 아무 것도 하지 못한다.** 이 부분은 내 진단 오류다.

## 3. 진짜 병목 — 오염이 아니라 **선택 실패**

정답이 그래프 안에 있는데 대표값이 다른 노드를 집는다.

| 코드 | 원장이 고른 값 | 그래프에 있는 정답 | 라벨링 근거 |
|---|---|---|---|
| E-3-1 Scope1+2 | **1,493** (2025) | **3,560,074** (2024) | §3-6 총 온실가스 배출량 |
| E-5-1 용수 | **623,648** (2024) | **1,992,921** (2024) | §3-7 취수량 2024 합계 |
| E-4-1 에너지 | **431 TJ** (2024) | 7,929 TJ (2024) | §3-7 총량 9,075 TJ |
| E-6-1 폐기물 | **1,693** (2025) | 52,806 (2025) 로 보임 | — |

**추출은 성공했다. 선택이 실패했다.** L0 표 구조 복원(PR #43)이 값을 제대로 뽑아왔다는 뜻이기도
하다 — 3,560,074·1,992,921 둘 다 라벨링에서 확인한 정답이고 노드로 살아 있다.

### 왜 못 고르나 — 한 코드에 노드가 수십 개

```
E-3-1 : 75개 노드   (2019~2025, 사업장별·범주별·연도별이 전부 한 코드)
E-4-1 : 20개
E-5-1 : 17개
```

2024년 E-3-1만 봐도 535 / 8,367 / 68,714 / 371,059 / 3,136,024 / 3,560,074 … 가 나란히 있다.
사업장별 값, Scope 구분, 소계, 총계가 **구분 없이 같은 코드**로 들어간다.
현재 선택 규칙은 **연도 하나뿐**이라 같은 연도 안에서는 사실상 임의 선택이다.
라벨링 §3-5(법인별 12컬럼)가 지목한 문제가 노드 레벨에서 그대로 재현됐다.

### report_year=2025가 함정

보고서 **발간연도**이지 **실적연도**가 아니다. 2025 노드는 부분값·분기값이고 연간 실적은
2024에 몰려 있다. E-3-1이 1,493(2025)을 고른 게 정확히 이 때문이다.
**작업2에서 내가 넣은 `report_year` 최근접 규칙은 이 경우 오히려 파편을 고르게 만든다.**
D1의 G5도 같은 전제를 공유하므로 같이 틀린다.

### E-3-2 Scope3 = 14,160,000, period 2019, 노드 1개

라벨링 §3-7의 각주 "1,416만 tCO2eq(원소재 배출 예상치 포함)". 실측 3,136,024는 E-3-1 쪽
노드로 들어가 있다. period 2019는 오파싱으로 보인다 — **G4는 미래 방향만 막고 과거는 안 본다.**

### 단위 불일치 3건 (실측)

- `E-7-1` 대기오염물질: 항목 kg vs 원장 ton — **1,000배**
- `E-7-2` 수질오염물질: 항목 kg vs 원장 ton — **1,000배**
- `E-6-1` 폐기물: `ton` vs `톤` — 표기 차이(무해, 정규화만 필요)

## 4. 다음 작업 (우선순위 재배치)

### 1순위 — 대표값 선택 규칙 (총량·전사 노드 식별)
연도 규칙만으로는 못 고른다는 게 실측으로 확정됐다. 필요한 건 "이 노드가 총계인가"를 가르는
신호다. 후보 순서:
1. **hint 기반** — `총·합계·전사·Total` 등이 원 metric_hint에 있는지. 가장 직접적
2. 형제 노드 중 **다른 값들의 합에 가까운 값**(소계 관계 이용)
3. 위 둘로 안 되면 **미공시 처리** — 잘못된 값보다 낫다(§3-1 원칙)

### 0-b 선행 (라이브 1회 추가) — hint 분포 확보
1순위 설계에 hint가 필요한데 **이번 실행에서 hint가 전부 빈 문자열로 나왔다.**
원인: `EvidenceNode`에 `metric_hint` 필드가 없고 원 hint는 `raw_text`에
`"{hint}={value}{unit} ({file})"` 형태로 들어 있다(`evidence_graph:352`). 스크립트가 없는 필드를
읽고 있었다 — 수정 완료(`_hint_of`). 재실행하면 hint와 **동일 연도 형제 노드 수·값 범위**가
함께 나온다.

```bash
python3 scripts/inspect_ledger_provenance.py --ticker 012330 --areas E \
        --json outputs/ledger_provenance_012330_v2.json
```

### 2순위 — report_year를 실적연도로 재정의
발간연도 대신 (ㄱ) 노드가 가장 많이 몰린 연도 (ㄴ) DART 사업연도 중 택일. D1의 G5와 원장이
같은 기준을 쓰도록 한 곳에서 정한다.

### 3순위 — 단위 정규화
항목 단위로 환산해 저장(kg↔ton). 현재는 `units_compatible`이 통과시켜 놓고 환산은 안 한다.
