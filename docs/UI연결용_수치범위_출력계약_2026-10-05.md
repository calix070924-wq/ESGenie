# UI 연결용 수치·범위 출력 계약 (2026-10-05)

- 대상 코어: `codex/fix-numeric-scope-output-20261005`(최종 코드 `329daa7`)
- 검증 기록: `docs/수치범위_최종출력_검증기록_2026-10-05.md`
- 이 문서는 UI가 읽을 필드와 기대 표시를 정한다. 화면 디자인·새 기능은 다루지 않는다.
- 최종 UI에 적용한 뒤 화면과 다운로드가 일치하는지 확인하는 것은 UI 마무리의 완료 조건이다(§5).

## 1. 확정 상태 표시 계약

0 판정은 `EvidenceNode.boundary.provenance[]` 중 `source == "zero_evidence"` 기록에서 읽는다(필드 `status`·`cause`). 원장·답변에 이어지는 표시는 아래와 같다.

| 상태 | 원장(`resolved_facts[code]`) | 답변(`Answer`) | UI에 보일 것 | 하지 말 것 |
|---|---|---|---|---|
| CONFIRMED | 값 유지, `scope_source_only` 없음 | 기존 판정(`compared` 등) | 값 + 원문 범위(`boundary_label`) | 확인된 범위(`boundary_label`)보다 넓게 표기(연간·전사) |
| SOURCE_ONLY | 값 유지 + 플래그 `scope_source_only` + `scope_notes`(미확정 사유) | `comparison="scope_unconfirmed"`, `comparison_label="범위 확인 필요"`, `review_note`에 사유 | **같은 행에** 값과 "범위 확인 필요" + 사유를 함께. 참고값 표시는 허용 | '대조 완료'·'자가신고 일치'·합산·검증 완료 근거로 사용 |
| REJECTED | 대표값 아님(노드 없음) | 해당 값이 답변에 없음 | 확인 목록(`review_findings`, `check_reason="zero_not_in_evidence"`)에 사유·원문 위치 | 답변·합계에 되살리기 |
| UNRESOLVED·값 없음 | 대표값 아님 | 증빙 대기/데이터부족 | 무엇을 확인하지 못했는지(확인 목록) | 명시적 0으로 채우기 |

`SOURCE_ONLY` 사유(`cause`)와 사람이 읽는 문구(`scope_notes`의 출처 `ocr_router._ZERO_KEPT_CAUSES`):

| cause | 뜻 |
|---|---|
| `period_not_stated` | 원문에 기간 표기가 없음 |
| `report_year_only` | 요청이 보고 연도뿐(원문은 그해 월·기준일·연도 표기) |
| `site_not_stated` · `source_site_only` | 사업장 표기 없음 · 원문이 특정 사업장 |
| `fiscal_period_undefined` · `fiscal_year_abbreviated` | `FY2026` 구간 미정의 · `FY26` 연도 미연결(2026-10-05 신설) |
| `quarter_undefined` · `quarter_months_not_stated` | `Q1` 연도·시작월 없음 · `2026년 1분기` 월 미기재(신설) |

`source_conflict`(원측정값 상충)와 `scope_source_only`는 독립 플래그다. 둘 다 있으면 둘 다 보인다(상충이 더 강한 `mismatch`).

## 2. UI가 읽을 필드

### 답변(`ResponseSheet.answers[]`, `result.json` 의 `sheet`)

| 필드 | 용도 |
|---|---|
| `value`·`unit`·`display_value` | 값(`display_value`는 `29.3 % (2026년)` 형식 — 연도는 보고 연도이며 측정 범위가 아니다) |
| `status`·`badge` | `verified`/`self_reported`/`flagged`/`insufficient`/`hitl_required` |
| `boundary_label`·`boundary`·`completeness` | 측정 범위(`2026-04-01~2026-04-30 · 월간 · 제1공장 · … · 부분`). 값 옆에 같이 보인다 |
| `comparison`·`comparison_label`·`comparison_reason` | 비교 상태 4종(`compared`·`scope_unconfirmed`·`not_comparable`·`mismatch`)과 사유 전문 |
| `review_note` | 라벨 + 사유 + 범위 노트 한 줄(중복 제거됨). Excel·PDF '측정 범위/검토'·'근거/비고'와 같은 문구 |
| `confidence_flags` | `scope_source_only`·`source_conflict`·`incomplete_scope`·`partial_value`·`derived` |
| `scope_notes` | 범위·미확정 사유 문장 |
| `self_reports[]` | 회사 답변 원값(`value`·`unit`·`raw`·`source`·`boundary`·`context`). `context`에 `question_id`·`request`·`source_note`·`source_ids`·`value_trace[]`·`evidence_basis` |
| `comparisons[]` | 비교 기록. 회사 답변 추적은 `claim_value`·`evidence_value`·`traced_node_id`(같은 값의 다른 지표 근거 노드) |
| `flags[]` | 사람 읽는 경고(짧게: `자가주장 검토필요: …`, `범위 확인 필요: …`) |
| `evidence_links[]` | 산정 근거: `file_name`·`page`(**0-기준**, 화면은 +1)·`bbox`(0~1 정규화)·`quote`·`node_id`·`relative_path` |
| `reference_links[]` | 값 산정에 쓰지 않은 보완 대상 근거(산정 근거와 섞지 않는다) |

### 근거 그래프 노드(`pipeline.json` → `evidence_graph.nodes[]`)

- `metric`(코드 또는 원문 라벨)·`value`·`unit`·`page`·`bbox`·`quote`·`source_file`이 있다.
- `boundary.provenance[]`의 출처별 의미:

| `source` | 뜻 |
|---|---|
| `zero_evidence` | 0 판정. `status`·`cause`·`source_period`·`source_site`·`evidence`·`scope_heading`·`scope_boundary`, 그리고 `scope_spans[]`(where·role·text·start·end, role=`period`·`site`·`standard_ref`) |
| `label_check` | 원문 칸 라벨로 정정. `model_label`·`row_label`·`column_header`·`label`·`rule` — UI 감사 보기에서 "모델 라벨 → 원문 라벨" |
| `value_recovery` | 모델 값 없음 → 원문 부정 서술로 0(`model_value: null`, `evidence`) |
| `row`·`document_header`·`text_span`·`table_cell` | 원문 위치·문맥 |

### 확인 목록(`pipeline.json` → `review_findings[]`)

- 공통 필드: `title`·`fact`·`reason`·`action`·`check_reason`·`evidence[]`(file·page·quote).
- 이번에 추가된 `check_reason`:
  - `label_from_table_header`: "원문 표 칸 라벨로 정정"
  - `zero_recovered_from_negation`: "원문 부정 서술로 0 보존"

### 보고서 본문(LLM)

- 영역 본문과 Executive Summary의 문장 뒤에 `[검토: …]` 표시가 붙을 수 있다. 종류는 셋이다.
  - 근거 확인 필요(인용 근거에 없는 숫자)
  - 범위 미확정(SOURCE_ONLY 값 단정)
  - 범위 주의(부분값을 전체·연간·합산으로 확대)
- 모델 원문은 `report_sections.json`(영역 검증 결과)에 따로 있다.
- UI가 본문을 보여 준다면 표시를 지우거나 숨기지 않는다.

## 5. UI에서 확인할 남은 연결 항목

1. `comparison_reason` 전문을 E-6-2처럼 긴 경우에도 자르지 않고 보이기(목록에는 요지, 상세에는 전문). 회사 답변 92%와 증빙 29.3%를 나란히 두고 `traced_node_id` 노드로 08 원문 보기 연결.
2. `scope_source_only`를 일반 '자가신고'와 구별되는 표시로(같은 행에 범위 확인 필요 + 사유). '대조 완료' 문구를 쓰지 않기.
3. `boundary_label`을 값 옆에 함께 표시. `display_value`의 `(2026년)`은 보고 연도라 범위로 오해하지 않게.
4. `label_check` 정정 노드(09 대상·13 고유 인원·08 합계)는 원문 라벨로 보이고, 감사 보기에서 모델 라벨을 함께.
5. `evidence_links[].page`는 0-기준이다(화면은 +1). bbox 강조는 기존 계약과 같다.
6. 보고서 본문을 노출할 경우 `[검토: …]` 표시 유지. 표시 없는 원문을 보일 때는 영역 검증 결과임을 밝히기.
7. 11 ISMS: 모델 응답에 따라 수치 0 또는 조항으로 온다. 둘 다 '미보유'로 보이고 '미확인'으로 바꾸지 않기.
8. 응답서 PDF의 '(이어서)' 행: 같은 문항 ID의 연속 칸이다(쪽보다 긴 근거). UI 다운로드는 이 PDF를 그대로 쓴다.
9. PR #65 `presenter`가 새 필드(`self_reports[].context`, `comparisons[].traced_node_id`, `review_findings` 새 `check_reason`)를 버리지 않는지 확인.
10. 최종 UI 적용 후 화면·Excel·PDF의 값·상태·출처가 위 §3 기대값과 같은지 대조(UI 마무리 완료 조건).
