# 역추적 — claim 오염의 진짜 원인은 "L2가 옛 값을 씀"이 아니라 **값 공급 경로가 2개**

2026-07-25 · 근거: `outputs/audit_trace_00164788_E_20260724_003402.json` + 코드 정적 추적
(후속: `docs/발견_D1잔존_claim오염_2026-07-24.md` §다음작업후보 1)

## 결론

**L2는 환각하지 않는다. 본문 숫자를 L1 원장(`extraction.mapped`)에서 그대로 전사한다.**
문제는 원장의 값과 D1이 비교하는 그래프 노드가 **서로 다른 파이프라인에서 온다**는 것이다.

```
[A] DART 사업보고서 XML 텍스트 ──정규식(무게이트)──┐
                                                  ├─→ report.kesg_data ─→ L1 extract() ─→ 원장 ─→ kesg_items_E 의사청크 ─→ L2 프롬프트 ─→ claim
[B] OCR(지속가능경영보고서 PDF) ─G1~G6 게이트─→ graph 노드 ─(승격)─┘
                                          └───────────────────────────────────────────────────────→ D1 비교 대상
```

PR #44의 G1~G6는 **[B]에만** 걸려 있다. claim은 [A] 또는 [B]의 **다른 선택 규칙**을 타고
들어오므로, 노드를 아무리 정화해도 claim은 그대로다. 7/24 관찰(노드 오염 3건 소멸 + D1=100 유지)이
정확히 이 그림이다.

## 근거 1 — L2는 원장을 전사한다 (환각 아님)

트레이스 `00164788_E_001`의 `retrieved_chunk_ids`가 **5개 전부 `kesg_items_E`, score 1.0**.
즉 L2가 인용한 것은 PDF 청크가 아니라 Phase 1에서 만든 원장 의사청크다.

- `layer2_rag.py:499 _kesg_pseudo_chunk` — `covered` 행을 `"{code} {name} {value} {unit}"`로 직렬화
- `covered`는 `extraction.mapped` → `layer1_extract.extract():77` → `report.kesg_data[code]["value"]`

**함의**: L2 프롬프트를 고쳐도 원장이 오염돼 있으면 소용없다. 수정 지점은 L1 원장 채우기다.

## 근거 2 — 원장 값의 출처가 코드마다 다르다 (두 갈래)

### [A] DART 원문 정규식 — 게이트 0개, 우선순위 최상

`dart_client._regex_extract_kesg:662`

```python
for code, unit, pattern, scale in _KESG_PATTERNS:
    m = re.search(pattern, text, re.IGNORECASE)   # 문서 전체에서 첫 매치가 이김
```

- `text` = 사업보고서 ZIP 내 모든 XML을 태그 제거 후 이어붙인 **수십만 자 단일 문자열**
- `re.search` = **첫 매치 승리**. 연도·전사/법인·표 구조 인식 전혀 없음
- 패턴 슬랙이 `[^\d]{0,40}` — 레이블 뒤 40자 안 아무 숫자나 집음. 라벨링 문서가 지목한
  "행 레이블만 보고 값 선택" 병리와 동일 구조
- G1(가드어휘)·G3(단위정합)·G4(미래기간)·G5(연도근접) **어느 것도 안 걸림**

이 경로가 값을 채우는 코드 13개:
`E-3-1 · E-4-1 · E-4-2 · E-5-1 · E-6-1 · S-3-1 · G-1-2 · G-1-4 · G-2-1 · G-2-3 · G-3-1 · G-3-4 · G-6-1`

단 `_extract_kesg_from_dart:303`이 구조화 API 5종(`G-3-4·G-1-2·G-1-4·S-2-2·S-3-1`)으로 덮어쓴다
(구조화가 더 신뢰 — 라벨링 §4-1의 대조군이 정확했던 이유). **덮개가 없는 무게이트 정규식 코드는
E 전량 + G-2-1·G-2-3·G-3-1·G-6-1 = 9개**이고, 이번 오염이 나온 E-3-1·E-5-1이 여기 있다.

**우선순위 역전**: `ssot_pipeline._merge_ssot_evidence`의 OCR 승격은
`if code in result.mapped: continue` — 즉 **무게이트 [A] 값이 게이트 통과한 [B] 노드를 이긴다.**
[B]에서 오염 노드를 걸러내도 [A]가 그 자리를 채운다.

### [B] OCR 노드 승격 — 게이트는 통과했으나 **D1과 선택 규칙이 다름**

`ssot_pipeline._merge_ssot_evidence:152`
```python
if current is None or (node.period, node.confidence) >= (current.period, current.confidence):
    ocr_repr[node.metric] = node          # ← max(period)
```
`layer3_detect._score_d1_numeric:425` (G5)
```python
node = min(compat, key=lambda n: (abs(n.period - ref_year), -n.period))   # ← report_year 최근접
```

**같은 코드, 같은 그래프인데 원장은 최신 연도 노드를, D1은 보고연도 노드를 고른다.**
다연도 노드가 있는 코드는 데이터가 완벽해도 claim ≠ node가 되어 D1이 발화한다.
G5는 D1 쪽에만 대칭 없이 들어갔다.

## 부수 발견

1. **단위 미환산**: E-4-1 항목 단위는 TJ인데 원장은 `2,841.0 MWh`를 그대로 출력한다.
   PR #44에서 MWh↔TJ를 환산군에 넣어 `units_compatible`은 통과하지만, 표시·비교 시
   **환산은 안 한다.** 항목 단위로 정규화하는 지점이 없다.
2. **D1 교차 비교 증폭**(`layer3_detect:411 cand_codes`): 한 문장의 모든 토픽 코드를 후보로 돌려
   claim 1개 오염이 E-5-1·E-6-1·E-6-2로 3중 계상된다. 트레이스 detail 13줄 중 E-5-1 비교만 4줄.
3. **원장 note에 이미 출처가 적혀 있다**: `"DART 원문 정규식 추출"` vs `"OCR 정량 증빙으로 자동 인식"`.
   지금은 어디에도 안 드러난다 — 감사추적·표에 노출하면 경로 판별이 무료가 된다.
