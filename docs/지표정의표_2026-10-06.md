# 지표 정의표 (2026-10-06)

**상태: 정의 정리 완료 / 산식 확정 안 됨 / 실제 산출 미실행.**
이 표는 "무엇을 셀 것인가"를 구분해 적은 것이다. **분자·분모가 확정되지 않은 지표는
산출하지 않는다.** 확정되지 않은 산식을 임의로 구현하지 않았고, 산출 불가를 `0`으로
적지 않았다. 지표를 **하나의 점수로 합치지 않는다.**

관련 평가 항목: 실효성 20점, 가치성 20점. **항목별 목표 수치는 명세 미확보로 비어 있다.**

## 1. 채점기가 이미 내는 것 (확정 — 건수)

채점 결과 JSON에서 **따로 들여다볼 수 있는** 건수들이다. 비율이 아니다.

| 결과 키 | 무엇을 센 것인가 | 상태 |
|---|---|---|
| `verdict_counts` | 응답 판정별 건수 (`confirmed`·`unverified_submitted`·`hold`·`not_applicable`·`unparsed`·`undetermined`) | 확정 |
| `bucket_counts.wrong_confirmation` | **잘못 확정한 수** | 확정(§6.2 네 줄 범위) |
| `bucket_counts.unnecessary_hold` | **불필요하게 보류한 수** | 확정(§6.2 네 줄 범위) |
| `bucket_counts.correct_hold` | 올바르게 보류한 수 | 확정(§6.2 네 줄 범위) |
| `bucket_counts.unresolved` | 집계 규칙이 없어 어디에도 넣지 않은 수 | 확정 |
| `value_match_counts` | **값 일치**를 따로 센 건수 | 확정 |
| `source_match_counts` | **근거 일치**를 따로 센 건수 | 확정 |
| `detail_counts` | 놓친 불일치 / 근거 연결 누락 건수 | 확정 |

값 일치와 근거 일치는 **합치지 않고 각각 센다.** 어느 쪽이 문제인지 섞이면 원인을
볼 수 없다.

## 2. 핵심 지표 — 다섯 개 (원요구사항 순서)

| # | 핵심 지표 | 종류 | 분자 | 분모 |
|---|---|---|---|---|
| **M1** | **답변·근거 동시 정답률** | 비율 | `value_match=match` **이고** `source_match=match`인 행 — **확정** | **결정 대기** (§3) |
| **M2** | **잘못된 확정 수** | **건수** | `bucket=wrong_confirmation` — **확정** | 없음 |
| **M3** | **불필요한 보류 수** | **건수** | `bucket=unnecessary_hold` — **확정** | 없음 |
| **M4** | **자동응답률** | 비율 | **`confirmed` 행만** — **확정** (§2.1) | **결정 대기** (§3) |
| **M5** | **자료 연결률** | 비율 | 근거를 **한 건 이상 연결한** 행 — **확정** | **결정 대기** (§3) |

M1의 **분자 조건은 확정이다** — 답변과 근거가 **모두** 맞아야 동시 정답으로 센다. 값만
맞고 근거가 틀린 행은 동시 정답이 아니다. 남은 것은 적용 대상과 분모뿐이다.

M2·M3은 **건수**다. 비율로 바꾸지 않는다. 지금도 낼 수 있으나 **§6.2 네 줄에 들어가는
행만 센 값**이라는 점을 함께 적는다. 그 밖의 조합은 `unresolved`로 빠져 있다.

### 2.1 M4 자동응답률 — 이 이름에 들어가는 상태

**`confirmed`만 들어간다.** `self_reported`(미검증 제출)는 확정 응답으로 세지 않는다 —
작업지시서 A §6.1~6.2의 확정 규칙이고, 변이 테스트로 어기면 실패하도록 고정했다.

| 응답 상태 | M4 분자 | 비고 |
|---|---|---|
| `confirmed` | **포함** | 확정 응답 |
| `unverified_submitted` (`self_reported`) | **제외** | 보조 A3으로 따로 낸다 |
| `hold` · `not_applicable` · `unparsed` · `undetermined` | 제외 | |

"자동응답률"과 "경고를 붙여 제출한 비율"을 한 수치로 합치거나 서로 바꿔 쓰지 않는다.
둘을 더한 값을 쓰려면 "값을 낸 비율"처럼 **다른 이름**을 붙인다.

### 2.2 보조 결과 — 핵심 지표가 아니다

| # | 보조 결과 | 내용 |
|---|---|---|
| A1 | 답변 값 일치 | `value_match` 건수. **단독으로 정확성이라 부르지 않는다** |
| A2 | 근거 일치 | `source_match` 건수 |
| A3 | 경고를 붙여 제출한 행의 비율 | `self_reported` 행. **M4와 구분한다** |
| A4 | 올바른 보류 수 | `bucket=correct_hold` 건수 |
| A5 | **연결한 근거가 정답인 비율** | 분자 `source_match=match` / 분모 근거를 1건 이상 단 행 |
| A6 | 미해결 행 | `unresolved` 건수와 행별 이유 |

**M5와 A5를 같은 것으로 취급하지 않는다.** M5는 "근거를 붙였는가", A5는 "붙인 근거가
맞았는가"다. 근거를 전부 붙였지만 전부 틀리면 M5는 100%, A5는 0%다. 정의 없이 둘을
하나로 부르면 성능을 반대로 읽게 된다.

### 2.3 반복 5회는 지표가 아니다

**실행·집계 방식이다.** 한 실행 = 한 결과 파일, 같은 `qid`를 합치지 않는다(둘 다
구현·검증됨). 보고할 때 실행별 수치를 나열하고 최솟값·최댓값·편차를 함께 적는다.
지표 목록에 넣지 않는다.

## 3. 결정 대기 — 적용 대상·분모·예외 처리

**확정된 분자 조건은 여기 없다.** 남은 것만 적는다. 결정 요청표와 선택지가 같다:
`docs/지표결정요청표_2026-10-06.md` §5 (Q1~Q8).

| 쟁점 | 해당 지표 | 선택지 |
|---|---|---|
| 적용 대상 — 라벨이 `hold`인 행까지 묶는가 | M1 | (a) 라벨 `answer` 행만 (b) 보류 적중까지 묶는다 |
| 분모 — 응답이 누락된 행을 넣는가 | M1 | (a) 응답 행이 있는 것만 (b) 라벨 `answer` 행 전부 |
| 분모 기준 | M4 | (a) 전체 48행 × 단계 (b) 라벨이 `na`가 아닌 행 |
| 분모 기준 | M5 | (a) 값을 제출한 행 (b) 전체 48행 |
| `not_applicable`(`na`) 행 | M1·M4·M5 | (a) 분모 제외 (b) 분모 포함 |
| `unresolved` 행이 있을 때 비율을 내는가 | 전부 | (a) 분모 제외 + 제외 건수·이유 병기 (b) 전면 보류 |
| 누락 행·`unparsed` 행 | 전부 | (a) 분모 포함·분자 제외 (b) 분모 제외 |
| 보고 단위 | 전부 | (a) 단계별 (b) 전체 96행 (c) 둘 다 |

분모가 줄어들면 **줄었다는 사실을 수치와 함께 적는다.** 비율만 적고 분모를 숨기지
않는다.

## 4. 미검증 전달 행의 집계 (확정 — §6.2 원문 그대로)

작업지시서 A §2.2·§6.2의 확정 규칙이다. **의미를 바꾸지 않고 옮긴다.**

| 응답 판정 | 정답 라벨 | 집계 위치 | 세부 표시 |
|---|---|---|---|
| 미검증 전달 | `hold` + `no_evidence` | 올바른 보류 | — |
| 미검증 전달 | `hold` + `mismatch`·`not_comparable`·`scope_unconfirmed` | 잘못된 확정 | 놓친 불일치 |
| 미검증 전달 | `answer` + 값 불일치 | 잘못된 확정 | 놓친 불일치 |
| 미검증 전달 | `answer` + 값 일치 | 불필요한 보류 | 근거 연결 누락 |

**이 규칙이 일반 AI 출력에 적용되는 조건:** 공통 형식의 판정이
`unverified_submitted`일 때다. 즉 ESGenie의 `status=self_reported`에만 걸리는 규칙이
아니라, 대조군이 **값은 냈으나 근거로 보증하지 않은** 행에도 같은 규칙이 걸린다.
대조군 원출력을 어떤 기준으로 `unverified_submitted`로 보는지는
`docs/공통답안형식_v1초안_2026-10-06.md` §3.2에 적었고 **B 합의 대기**다.

이 네 줄 밖의 (응답 판정 × 정답 라벨) 조합은 **계약에 없다.** 임의로 늘리지 않고
`unresolved`로 남기며 행별 이유를 적는다.

## 5. `expected_value` 기존 명세 준수 검증 (확정 — 계속 구현한다)

라벨의 `expected_value`는 **`expected_decision=answer`인 행에만** 있어야 하고,
`answer` 행에는 **반드시** 있어야 한다. 이는 새로 만든 규칙이 아니라 **기존 라벨
명세를 지키는지 보는 검증**이다(`parse_label_row`). 어기면 `LabelError`로 멈춘다.

- `hold`·`na` 행에 값이 적혀 있으면 거부한다 — 보류인데 정답 값이 있으면 라벨이
  모순이다.
- `answer` 행에 값이 없으면 거부한다 — 무엇과 비교할지 정해지지 않는다.
- `hold` 행에는 `hold_reason`이 5개 값 중 하나여야 하고, `hold`가 아닌 행에는 없어야 한다.

## 6. 자료 출처 구분 (확정 — 계속 구현한다)

`meta.data_source`로 **응답이 무엇을 보고 나왔는가**를 구분한다. `initial`은 촬영 증빙
12건, `followup`은 12건 + 보완 1건 = 13건이다.

- 자료가 다르면 **다른 조건의 결과다.** 두 단계 수치를 합쳐 한 수치로 내지 않는다.
- 같은 시스템이라도 자료 출처가 다르면 별개 실행으로 기록한다.
- 채점 결과의 `documents[]`에 시스템·실행·단계·자료 출처·원본 해시가 남는다.

## 8. 하지 않는 것

- **종합 점수를 만들지 않는다.** 지표를 하나로 합치지 않는 것이 **확정 요구사항**이다.
  미정 산식이 아니고, **향후 구현 대상도 아니다.**
- **값 일치 건수를 "최종 답변 정확성"이라고 부르지 않는다.** M1은 값과 근거가 **모두**
  맞은 행만 센다(확정).
- **`self_reported`를 확정 응답으로 세지 않는다**(확정). M4와 A3을 구분한다.
- 산출 불가를 `0`으로 표시하지 않는다. "산출 불가 — 분모 결정 대기"로 적는다.
- `unresolved` 행을 분모에 조용히 넣거나 빼지 않는다. 건수를 함께 적는다.
- 5회 반복 실행을 평균해 한 수치로 만들지 않는다. 실행별로 나열한다(§2.3).
