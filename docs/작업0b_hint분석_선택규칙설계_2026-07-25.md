# 작업0-b — hint 확보 후 분석: 선택 규칙 설계 근거

2026-07-25 · 현대모비스 E · `outputs/ledger_provenance_012330_v2.json`

## 결론 먼저

**필요한 정보는 전부 hint에 있다.** OCR이 뽑아준 레이블이 예상보다 훨씬 서술적이라
(`용수 사용량(취수량) 합계 2024년`, `Scope 1 배출량 합계`, `폐기물 처리량(매립, 소각 등) 국내(별도)`)
**hint만으로 총량/부분/파생을 가를 수 있다.** 지금은 그 hint를 대표값 선택에 전혀 안 쓴다.

## 1. 실측 — 선택된 노드의 hint가 명백히 틀렸다

| 코드 | 원장이 고른 값 | 그 노드의 hint | 판정 |
|---|---|---|---|
| E-3-1 | 1,161,214 | **온실가스 감축 효과** | 배출량이 아니라 감축효과 — 파생 지표 |
| E-4-1 | 4,654 MWh | **전력구매계약(On-site PPA)** | 조달 방식별 부분값 |
| E-5-1 | 623,648 | 용수 사용량(취수량) **국내(별도)** 2024년 | 부분(전사 아님) |
| E-6-1 | 1,693 | 폐기물 처리량(매립, 소각 등) **국내(별도)** | 부분 |
| E-6-2 | 92.9 | 2024년 국내 사업장 폐기물 재활용률 | 국내 한정이나 값은 타당 |
| E-4-2 | 12.9 | 사업장 재생에너지 사용·전환률 | **정상** |

같은 코드 안에 **정답 노드가 나란히 존재한다**:

```
E-5-1  → 용수 사용량(취수량) 합계 2024년           1,992,921 ton
E-6-1  → 폐기물 처리량(매립, 소각 등) 합계             17,694 ton
E-3-1  → 온실가스 배출량 (Scope 1 + 지역 기반 Scope 2) 합계   396,152 tCO2eq
E-4-1  → 전력 사용량                              7,497 TJ (2023) / 827,967 MWh (2024)
```

**앞선 보고 정정**: E-3-1의 정답을 3,560,074라고 썼는데 틀렸다. hint를 보니 3,560,074는
`총 온실가스 배출량 (Scope 1+2+3) 지역기반`이다. K-ESG E-3-1은 **Scope1+2**이므로 정답은
`396,152`(또는 Scope1 52,991 + Scope2 371,059 = 424,050)다. hint 없이 값만 보고 판단하면
이런 오독이 난다 — 선택 규칙을 값이 아니라 hint 위에 세워야 하는 이유이기도 하다.

## 2. hint에 이미 들어 있는 세 축

1. **집계 축** — `합계` / `국내(별도)` / `국내 자회사` / `해외 자회사` / 국가명 / 사업장명
   E-3-1 46개 노드 중 `합계` 포함 30개, E-6-1 82개 중 21개, E-5-1 17개 중 8개
2. **파생·비실적 축** — `감축`, `효과`, `예상`, `증감`, `원단위`, `1톤당`, `제로화`, `목표`
   E-3-1이 고른 `온실가스 감축 효과`가 여기 걸린다. **현행 G1 가드어휘에 `감축량`은 있으나
   `감축 효과`는 없다** — 어휘를 `감축`으로 넓히면 잡힌다
3. **지표 정합 축** — `Scope 1` / `Scope 2` / `Scope 3` / `1+2+3`.
   E-3-1(Scope1+2)에 `Scope 3`·`1+2+3` 노드가 섞여 있다

## 3. 별개로 확인된 버그 2건

### (가) 동일 hint가 연도마다 다른 코드로 간다
```
'Scope 3 온실가스 배출량 연결(일부)'  → E-3-2 (2022)  /  E-3-1 (2023·2024)
```
같은 문자열인데 코드 배정이 흔들린다. `_resolve_kesg_code`의 사전 매칭과 LLM 추정이
경합하는 지점으로 보인다(확신도 중간 — 코드 확인 필요). Scope3 값이 Scope1+2 후보 풀을
오염시키는 직접 원인이다.

### (나) 표의 연도 열이 한 period로 뭉개진다
```
2025  17,694  폐기물 처리량(매립, 소각 등) 합계
2025  17,129  폐기물 처리량(매립, 소각 등) 합계
2025  19,352  폐기물 처리량(매립, 소각 등) 합계
```
**hint가 완전히 같은데 값이 3개.** 원문 표의 3개 연도 열이 전부 period 2025로 붙었다.
라벨링 문서가 공통 뿌리로 지목한 "행 레이블만 보고 열 방향(연도) 미사용"이 노드 레벨에서
그대로 재현된 것. E-6-1 노드 82개 중 상당수가 이 중복이다.

**함의**: period는 신뢰할 수 없다. 선택 규칙을 연도에 의존시키면 안 된다 —
**hint 우선, 연도는 보조**로 가야 한다.

## 5. 제안하는 선택 규칙 (설계)

대표 노드를 `연도 최근접` 단일 규칙에서 **hint 기반 점수**로 교체한다.

```
1) 배제(hard)   hint에 파생·비실적 어휘(감축·효과·예상·증감·원단위·1톤당·목표·제로화)
                → 후보에서 제외.  G1 가드어휘를 '노드 선택' 단계로 확장하는 것
2) 지표 정합    항목 코드가 요구하는 구분과 충돌하면 제외
                (E-3-1에 'Scope 3'·'1+2+3', E-5-1에 '재활용·재사용')
3) 집계 우선    '합계/총계' 포함 > 구분어 없음 > '국내(별도)·자회사·해외·국가명·공장' 포함
4) 단위 정합    항목 단위와 같거나 환산 가능한 것 우선(E-4-1은 TJ 우선)
5) 연도         여기까지 동률일 때만 보고연도 근접 (period 신뢰도가 낮으므로 최후 기준)
6) 그래도 동률/후보 0 → 미공시 + confidence_flag
```

기대 효과(같은 데이터 기준):

| 코드 | 현재 | 규칙 적용 시 |
|---|---|---|
| E-3-1 | 1,161,214 (감축효과) | 396,152 (Scope1+2 합계) |
| E-5-1 | 623,648 (국내별도) | 1,992,921 (합계) |
| E-6-1 | 1,693 (국내별도) | 17,694 (합계) |
| E-4-1 | 4,654 MWh (PPA) | 7,497 TJ (전력 사용량) |
| E-4-2 | 12.9 | 12.9 (불변) |

**주의**: 이 표는 hint 문자열만 보고 손으로 돌린 예상이다. 구현 후 실제 실행으로 확인해야 한다.
그리고 E-6-1처럼 동일 hint 3중복이 남는 코드는 (나)를 먼저 안 고치면 셋 중 아무거나 고른다.

## 6. 작업 순서 제안

1. **(가) 코드 배정 일관성** — 동일 hint → 동일 코드. 싸고 명백한 버그, 후보 풀 오염 제거
2. **선택 규칙 §5** — 1순위 본체
3. **단위 정규화** — E-7-1/E-7-2 kg↔ton, E-4-1 MWh→TJ. 항목 단위로 환산해 저장
4. **(나) 연도 열 뭉개짐** — L0 표 파싱 소관. 범위가 크므로 분리
