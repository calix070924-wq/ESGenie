## 0. 왜 공통 형식이 필요한가

ESGenie와 일반 AI 대조군의 응답을 **같은 채점 로직**으로 보려면 입력 모양이 같아야
한다. 각자 형식을 쓰면 채점기가 두 벌이 되고, 두 벌이 되면 비교 결과가 로직 차이에서
오는지 응답 차이에서 오는지 알 수 없다.

- 채점 로직은 `esgenie/eval/response_scoring.py` **한 곳**이다.
- ESGenie 전용 의미(`status`·`comparison`·0-기준 페이지)를 공통 형식으로 옮기는 일은
  `esgenie/eval/esgenie_adapter.py` **한 곳**에서 한다.
- 제품 코드(`esgenie/supplychain/exporters/*`·`schema.py`·`mapping.py`)는 고치지 않는다.
  변환은 평가 도구 쪽에서만 한다.

## 1. 파일 형식과 단위 — JSON, 한 파일 = 한 시스템·한 실행·한 단계

**JSON 객체 한 개**로 한다. JSONL·CSV가 아니다.

| 후보 | 왜 안 썼는가 |
|---|---|
| CSV | 근거가 응답 하나에 여러 건이고(파일명·페이지·인용문), 측정 경계도 여러 칸이다. CSV로 담으면 한 칸에 구분자로 밀어넣어야 하고, 그 구분자가 인용문에 들어 있으면 깨진다 |
| JSONL | 파일 머리말(시스템·실행·단계·자료 출처)을 둘 곳이 없다. 첫 줄을 머리말로 쓰는 변칙은 행 단위 처리 이점을 없앤다 |
| JSON | 머리말 + 중첩 구조를 그대로 담는다. 한 실행의 행 수는 48로 고정이라 파일이 커지지 않는다 |

**한 파일에는 한 시스템의 한 실행의 한 단계만 담는다.** initial과 followup은 별도
파일이다. 5회 반복 실행은 5개 × 단계 수만큼의 파일이다. 한 파일에 여러 실행을 합치지
않는다 — 합치면 어느 실행의 응답인지 복원할 수 없다.

**정상 실행 한 건은 48행이다**(rba42 문항 수). 문항 수는 양식
(`get_framework("rba42").questions`)에서 읽는다. 48이라는 수를 코드에 박지 않는다.

파일 이름 권장: `<system>_<run_id>_<stage>.json` (예: `esgenie_LIVE-61b6167_initial.json`).
강제는 아니다. 식별은 파일 이름이 아니라 `meta`로 한다.

## 2. 최상위 구조

```json
{
  "format_version": "1.0-draft",
  "meta": { ... },
  "answers": [ { ... }, ... ]
}
```

### 2.1 `meta` — 머리말

| 필드 | 필수 | 자료형 | 뜻 |
|---|---|---|---|
| `system` | 필수 | 문자열 | 응답을 낸 시스템 식별자 (예: `esgenie`, `general_ai_a`) |
| `run_id` | 필수 | 문자열 | 실행 식별자. **실행마다 달라야 한다** |
| `stage` | 필수 | `initial` \| `followup` | 단계 |
| `framework` | 필수 | 문자열 | 양식 키 (이번 평가는 `rba42`) |
| `data_source` | 필수 | 문자열 | 응답이 **무엇을 보고** 나왔는가 (예: `촬영증빙_12건`, `촬영증빙_12건+보완_1건`). 같은 시스템이라도 자료가 다르면 다른 값이다 |
| `model` | 선택 | 문자열 \| 없음 | 해당되면 모델 식별자. ESGenie처럼 모델 하나로 환원되지 않으면 생략한다 |
| `produced_at` | 선택 | ISO 8601 | 이 파일을 만든 시각 |
| `adapter` | 선택 | `{name, version}` | 변환을 거쳤다면 무엇으로 했는가 |
| `source_ref` | 선택 | `{path, sha256}` | **원출력 파일의 경로와 해시.** 변환 결과를 원본과 대조하기 위해 남긴다 |
| `notice` | 선택 | 문자열 | 합성 예시 표시 등 읽는 사람에게 줄 경고 |

`format_version`은 최상위에 둔다(머리말보다 먼저 읽어야 하므로).

### 2.2 `answers[]` — 응답 한 행

| 필드 | 필수 | 자료형 | 뜻 |
|---|---|---|---|
| `qid` | 필수 | 문자열 | 양식의 문항 ID |
| `decision` | 필수 | 아래 §3의 6개 값 | **응답 판정** — 그 시스템이 무엇을 제출했는가 |
| `decision_basis` | 선택 | 문자열 | 그 판정을 어떻게 얻었는가(원출력의 어떤 점을 보고) |
| `value` | 필수(널 허용) | 수치 \| 참거짓 \| 문자열 \| `null` | 제출한 값. 없으면 `null` |
| `unit` | 필수 | 문자열 | 단위. 없으면 `""`. **환산하지 않는다** |
| `value_text` | 선택 | 문자열 | 사람이 읽는 표기(`"123.4 kg (2026년)"`). 채점에 쓰지 않는다 |
| `boundary` | 선택 | 객체(§4) | 측정 경계 — 기간·사업장·대상·분모 |
| `evidence` | 필수 | 배열(§5) | **값 산정에 쓴 근거.** 없으면 `[]` |
| `references` | 선택 | 배열(§5) | 값 산정에 쓰지 않은 참고 근거. `evidence`와 섞지 않는다 |
| `source` | 선택 | 객체 | **원본 보존.** 변환 전 값을 그대로 둔다(§3.2) |
| `notes` | 선택 | 문자열 \| `null` | 검토 메모 |

행 식별:

- **파일 안에서는 `(stage, qid)`**. 같은 파일에 같은 qid가 두 번 오면 형식 위반이다.
- **여러 실행을 함께 다룰 때는 `(system, run_id, stage, qid)`**
  (`answer_format.row_key`). 실행이 다른 같은 qid를 하나로 합치지 않는다.

## 3. 응답 판정(`decision`) — 6개 값

**정답 여부가 아니다.** 그 시스템이 무엇을 제출했는가다. 정답은 정답 라벨로만 판정한다.

| 값 | 뜻 |
|---|---|
| `confirmed` | 확정 — 근거로 검증했다고 제출 |
| `unverified_submitted` | **미검증 전달** — 값은 냈으나 근거로 보증하지 않음 |
| `hold` | 보류 — 값을 제출하지 않음 |
| `not_applicable` | 해당 없음 |
| `unparsed` | 원출력을 읽을 수 없었다(파싱 실패) |
| `undetermined` | 원출력은 읽었으나 공통 판정으로 옮기는 규칙이 계약에 없다 |

지켜야 할 것:

- **파싱 실패를 보류로 바꾸지 않는다.** `unparsed`로 남긴다. 채점에서는 `unresolved`로
  드러나며 올바른 보류로 세지 않는다.
- **누락 응답을 보류로 채우지 않는다.** 행을 만들지 않고, 검증이 `missing_qid`로 드러낸다.
- `undetermined`는 임의 배정을 피하기 위한 자리다. 쓸 때는 `decision_basis`에 무엇이
  정해지지 않았는지 적는다.

### 3.1 ESGenie 응답의 매핑 (작업지시서 A §6.1을 공통 판정 이름으로 옮긴 것)

의미는 바꾸지 않았다. 차단 비교 = `{scope_unconfirmed, not_comparable, mismatch}`.

| ESGenie | 공통 판정 |
|---|---|
| `status=verified` · 값 있음 · 차단 비교 없음 | `confirmed` |
| `status=self_reported` · 차단 비교 없음 | `unverified_submitted` |
| `status=not_applicable` · 차단 비교 없음 | `not_applicable` |
| 차단 비교가 있음 / `verified`이나 값이 비어 있음 / `insufficient`·`hitl_required`·`draft_ready`·`flagged` | `hold` |
| `status=not_applicable` + 차단 비교 | `undetermined` (우선순위가 계약에 없다) |

값 `0`과 `False`는 **채워진 값**이다. `self_reported`는 어떤 경우에도 `confirmed`로
올라가지 않는다.

### 3.2 대조군 응답의 판정 — ESGenie 전용 `status`가 없어도 된다

대조군에는 `verified`/`self_reported` 같은 상태가 없을 수 있다. 그래도

- **`status`가 없다는 이유만으로 전부 `unverified_submitted`로 분류하지 않는다.**
- **모든 응답을 `confirmed`로 바꾸지도 않는다.**

대조군은 **원출력의 서술 자체**로 판정한다. 제안하는 기준(B 검토 대상):

| 원출력이 이렇게 말하면 | 공통 판정 |
|---|---|
| 값을 내면서 **어느 자료의 어느 대목**을 근거로 들었다 | `confirmed` (근거는 `evidence`에 적는다) |
| 값은 냈으나 근거를 들지 않았거나 "확인이 필요하다"고 덧붙였다 | `unverified_submitted` |
| 자료에서 찾을 수 없다 / 답할 수 없다고 했다 | `hold` |
| 해당 사항이 없다고 했다 | `not_applicable` |
| 이 문항의 응답을 원출력에서 찾을 수 없거나 형식을 벗어났다 | `unparsed` |

판정의 근거를 `decision_basis`에 적고, 원출력 발췌를 `source.raw`에 남긴다. 이렇게 하면
사람이 나중에 판정을 다시 볼 수 있다.

**미검증 전달 행의 집계 규칙(작업지시서 A §6.2)은 공통 판정
`unverified_submitted`에 적용된다.** 즉 ESGenie의 `self_reported`에만 적용되는 규칙이
아니라, 대조군이 "근거 없이 값만 낸" 행에도 같은 규칙이 걸린다. 규칙 자체는 그대로다.

| 정답 라벨 | 집계 위치 | 세부 표시 |
|---|---|---|
| `hold` + `no_evidence` | 올바른 보류 | — |
| `hold` + `mismatch`·`not_comparable`·`scope_unconfirmed` | 잘못된 확정 | 놓친 불일치 |
| `answer` + 값 불일치 | 잘못된 확정 | 놓친 불일치 |
| `answer` + 값 일치 | 불필요한 보류 | 근거 연결 누락 |

이 네 줄 밖의 조합은 **아직 계약에 없다.** 임의로 늘리지 않고 `unresolved`로 남긴다
(§8).

## 4. 측정 경계(`boundary`) — 미상은 `null`로 보존한다

허용 필드는 여섯 개뿐이다. 그 밖의 키는 형식 위반이다.

| 필드 | 뜻 | 예 |
|---|---|---|
| `period` | 기간 | `"2026"`, `"2026-05"`, `"2025-04~2026-03"` |
| `site` | 사업장·범위 | `"본사"`, `"1공장"` |
| `target` | 측정 대상 | `"사용전력량"`, `"폐기물 배출량"` |
| `denominator` | 비율의 분모 | `"총 폐기물 배출량"` |
| `label` | 사람이 읽는 경계 한 줄 | `"2026-05 · 월간 · 부분"` |
| `completeness` | `total` \| `partial` \| `unknown` \| `null` | 총량인가 부분값인가 |

**모르는 값은 `null`이다.** 빈 문자열로 두지 않고, 그럴듯한 값을 만들어 넣지 않는다.
`completeness`의 `unknown`은 "모른다고 판단했다"는 뜻이고 `null`은 "기재하지 않았다"는
뜻이다.

기간·사업장·대상·분모의 차이는 **의미 차이**다. 표기 정규화로 지우지 않는다.

## 5. 근거(`evidence`, `references`)

```json
{ "file_name": "SYN_증빙.pdf", "page": 3, "quote": "<합성 자리값 — 실제 증빙 문구가 아니다>",
  "node_id": "n-123" }
```

**이 문서의 예시 값은 전부 합성 자리값이다.** 실제 증빙 문구나 실제 기대값을 예시로
쓰지 않는다 — 독립 라벨링 전에 이 문서를 읽는 사람에게 정답을 흘리면 안 된다.

| 필드 | 필수 | 뜻 |
|---|---|---|
| `file_name` | 필수 | 증빙 파일 이름. 비어 있으면 형식 위반 |
| `page` | 필수(널 허용) | **1-기준 정수** 또는 `null`(미상). 0 이하는 형식 위반 |
| `quote` | 필수(널 허용) | 근거 문구. 모르면 `null` |
| `node_id` | 선택 | 시스템 내부 근거 식별자 |

**페이지는 1-기준이다.** 사람이 PDF 뷰어에서 보는 번호와 같다.

- ESGenie의 `evidence_links[].page`는 **0-기준**이다(`esgenie/ssot/audit_trace.py`,
  UI 출력계약 §2 "0-기준, 화면은 +1"). 어댑터(`to_common_page`)에서 **한 번만 +1** 한다.
- **이미 1-기준인 대조군 근거는 다시 변환하지 않는다.** 대조군은 어댑터를 거치지 않는다.
- **페이지·인용문을 모르면 `null`로 보존한다.** 첫 페이지로 간주하거나 만들어 넣지 않는다.
  페이지가 없는 근거는 근거 일치 판정에서 불일치로 처리되고 그 이유가 기록된다.

`evidence`는 값 산정에 쓴 근거, `references`는 참고용이다. 섞으면 "근거를 연결했는가"를
잘못 세게 된다.

## 6. 어기면 안 되는 처리 규칙

| 상황 | 처리 |
|---|---|
| 응답 누락 | 행을 만들지 않는다. 검증이 `missing_qid`·`row_count`로 드러낸다 |
| 같은 qid 중복 | 형식 위반(`duplicate_qid`). 둘 중 하나를 골라 조용히 버리지 않는다 |
| 양식에 없는 qid | 형식 위반(`unknown_qid`) |
| 파싱 실패 | `decision="unparsed"`. 보류로 바꾸지 않는다 |
| 자료형 위반 | 형식 위반(`bad_type`). 강제 변환하지 않는다 |
| 파일 자체를 읽을 수 없음 | 예외(`FormatError`)로 멈춘다. 빈 문서로 대체하지 않는다 |

검증은 `esgenie/eval/answer_format.py::validate_document(doc, expected_qids)`가 한다.
문제를 **목록으로** 내며(코드·위치·설명), 고쳐 주지 않는다. 채점 CLI는 문제가 있으면
결과를 쓰되 **종료 코드 3**으로 알린다. 문제를 안고 나온 수치를 그대로 쓰지 않는다.

## 7. 버전과 호환성

`format_version`은 `주.부` 형식이다. 현재 `1.0-draft`.

| 변경 | 버전 | 읽는 쪽 |
|---|---|---|
| 선택 필드 추가 | 부 버전 올림 (1.0 → 1.1) | 모르는 선택 필드는 무시하고 읽는다 |
| 필수 필드 추가·삭제, 값 집합(`decision`·`completeness`) 변경, 기존 필드의 **의미** 변경, 페이지 기준 변경 | **주 버전 올림** (1.x → 2.0) | 주 버전이 다르면 **읽기를 거부한다**(`unsupported_version`) |

- `boundary`의 키는 **고정 목록**이다. 필드를 늘리려면 양쪽이 합의하고 부 버전을 올린다.
- 합의 전까지는 `-draft` 접미사를 붙인다. 합의 시 `1.0`으로 바꾸고 이 문서에 커밋 SHA를
  적는다.

## 8. 이 형식이 정하지 **않는** 것

형식은 "무엇을 제출했는가"만 담는다. 아래는 형식의 범위가 아니며 아직 확정되지 않았다.

- 정답 라벨의 내용 — 사람이 원본 증빙을 보고 작성한다. 형식 문서에 정답을 적지 않는다.
- §3.1·§3.2 네 줄 밖의 (응답 판정 × 정답 라벨) 조합의 **집계 위치** — 형식의 범위가
  아니지만 2026-10-06에 **확정됐다**(`docs/지표결정요청표_2026-10-06.md` §6.2 판정표).
  남은 것은 판정표 이전 단계의 미정이며 같은 문서 §6.3에 적는다.

**형식에서 발견한 빈칸(A 보고):** 이 형식에는 **시스템의 보류 사유를 담는 구조화
필드가 없다.** `decision_basis`는 자유 서술이고 `source.comparison`
(`compared`/`mismatch`/`not_comparable`/`scope_unconfirmed`)에는 라벨의
`no_evidence`·`needs_human_text`에 대응하는 값이 없다. 그래서 `hold × hold` 행의 보류
**사유** 비교는 대부분 "사유 미확인"이 되며, **미확인을 사유 일치로 간주하지 않는다.**
**이 빈칸은 선택적 후속 개선안이며, 지금 필수 산출물의 완성을 막는 조건이 아니다.**
기존 형식에서 사유를 확인할 수 없으면 `hold_reason_unknown`으로 남기는 것이 정상
동작이다. **자유 서술에서 사유를 추정해 일치로 처리하지 않는다.** 구조화 필드를
추가하려면 B와 합의하고 부 버전을 올린다(§7) — **B 합의 없이 넣지 않는다.**

지표의 **적용 대상·분모**와 `not_applicable`·누락·파싱 실패·`unresolved` 행의 분모
처리는 2026-10-06에 **확정됐다**(같은 문서 §6 Q1~Q8). 형식이 정하는 것은 아니지만
미정도 아니다.

아래는 형식의 범위가 아니지만 **이미 확정됐다.** 형식이 정하는 것이 아니라는 뜻이고,
미정이라는 뜻이 아니다.

- 답변과 근거가 **모두** 맞아야 동시 정답으로 센다. 단순 값 일치 건수를 최종 답변
  정확성이라고 부르지 않는다.
- `unverified_submitted`(미검증 제출)는 **확정 응답으로 세지 않는다.** 자동응답률에
  들어가지 않고 별도 보조 수치로 낸다.
- **지표를 하나의 종합 점수로 합치지 않는다.** 향후 구현 대상도 아니다.

## 9. 누가 무엇을 변환하는가

| 입력 | 공통 형식으로 바꾸는 주체 | 도구 |
|---|---|---|
| ESGenie `result.json` | **A** | `esgenie/eval/esgenie_adapter.py` (CLI 있음) |
| 대조군 원출력 | **B에게 제안** — 아직 합의되지 않았다 | 공통 형식 검증기는 A가 제공한다 |

A가 제공하는 것: 공통 형식 정의, 검증기(`validate_document`), ESGenie 어댑터,
채점 CLI(`scripts/eval_response_quality.py`), 합성 예시(`data/eval/examples/`).

인터페이스 항목 I-1~I-5의 상태는 **2026-10-07 기준 세 칸으로 나뉘어 있다.** 다섯 개를
한 묶음으로 "미회신"이라고 적지 않는다. 상세는 `docs/B회신_2026-10-06.md` §9.

| # | 항목 | 2026-10-07 상태 |
|---|---|---|
| **I-1** | 대조군 원출력을 누가 공통 형식으로 변환하는가 | **합의 완료 — B가 변환한다.** B가 수용했다 |
| **I-5** | 대조군 원출력의 `source.raw`·`source_ref` 보존 | **합의 완료.** B가 수용했다 |
| **I-4** | `boundary` 6개 필드로 대조군 경계를 담을 수 있는가 | **조건부 수용 — A가 답할 차례.** 조건은 "모르는 칸은 `null` 보존". §4가 이미 그렇게 규정하고 있고 A가 조건을 그대로 지킨다고 답했다. **B가 조건 충족을 확인하면 합의로 적는다** — 아직 합의가 아니다 |
| **I-2** | 데이터 출처 표현 | **수정안 재확인 필요.** B가 구조화 enum을 요청 → §4 명세의 `dataset_tag`(`virtual`/`public_report`/`real_pilot`)로 받고, **입력 자료 구성은 별도 축**이라 필드가 더 필요하다(§0.1) |
| **I-3** | 대조군 판정 구조 | **수정안 재확인 필요 + 지민 결정 선행.** §4 명세는 `decision` 3값 + `decision_detail`, 이 초안은 6값이다(§0.1). 구조가 정해져야 §3.2의 다섯 줄을 다시 올릴 수 있다 |

**합의 완료 (2026-10-06):** `05_자가진단응답초안`을 대조군에도 주되 **증빙과 분리된
구획**에 "회사 자가 답변 초안 — 검증된 증빙이 아님"으로 표시하고 **프롬프트·실행
메타데이터에 기록**한다. 이 항목은 더 묻지 않는다.

**공통 형식 전체가 확정된 것은 아니다.** I-2·I-3·I-4가 남아 있고 `format_version`은
`1.0-draft`다. 합의된 I-1·I-5도 **형식 전체의 확정을 뜻하지 않는다.**
