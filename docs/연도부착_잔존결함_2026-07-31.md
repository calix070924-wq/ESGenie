# 연도 부착 후 드러난 잔존 결함 4건

- 작업 브랜치: `feature/l0-period-attach-only`
- 검증일: 2026-08-02
- 범위: 코드 배정 2건, 대표 노드 선택 2건
- 제외: 연도 부착 로직, VLM 프롬프트, 라이브 API, 두 코드 사전 통합

## 기준선

`pymupdf` 설치 상태를 먼저 확인한 뒤 Python 3.13.13에서 전체 스위트를 직접 측정했다.

```text
901 passed, 3 warnings in 8.68s
```

작업 시작 시 `prompts.py`는 확장 프롬프트를 되돌린 staged 상태였다. 이 상태와 기존 문서,
`out/` 덤프는 사용자 변경으로 보존했고 이번 수정에서 건드리지 않았다.

## 결함과 수정

### (가) `_backfill_kesg_codes`의 선착순 점유

원인은 코드 점유를 정규화된 **라벨 전체**로 비교한 것이다. 연도 부착 후
`대기오염물질 배출량 국내(별도) 2022`, `해외 자회사 2022`, `합계 2024`가 서로 다른
라벨이 되면서 첫 metric만 E-7-1을 받고 나머지는 차단됐다.

집계 범위(`국내(별도)`, 국내·해외 자회사/사업장, `합계`, `총계`, `전사`, `연결(일부)`)와
연도만 제거한 **지표 본체**를 별도 점유 키로 추가했다. 본체가 같은 값은 모두 같은 코드를
받고, 본체가 다른 보조수치는 계속 차단한다. 단독 `총`은 `총탄화수소` 같은 실제 지표명을
훼손하므로 제거 대상에서 제외했다.

음성 검증으로 `폐기물 배출량 본문확정`이 E-6-1을 점유했을 때 `지정폐기물`은 여전히
코드를 받지 못하는 것을 고정했다.

### (나) Scope 3의 E-3-1 오배정

`evidence_graph._HINT_TO_KESG`에는 일반 `온실가스 → E-3-1`만 있고 `Scope 3` 키가
없었다. 따라서 `kesg_items` alias는 E-3-2를 반환하지만 evidence graph 폴백은 E-3-1을
반환했다.

`scope3 → E-3-2` 키를 추가하고, 배정 단계에도 코드별 negative keyword
`E-3-1 ← scope3 / 1+2+3 / 가치사슬`을 적용했다. 잘못된 E-3-1 LLM guess도 버리고
최장 일치 사전으로 E-3-2를 다시 찾는다.

현재 모비스 캐시 한 청크는 Scope 3 실측의 guess에 코드 대신 표 머리글 문자열 `"2"`를
담고 있었다. 이 확인된 오응답만 사전 재해소해 2022~2024 실측 노드를 살렸다. 전 코드의
비표준 guess로 넓히면 기존 4개사의 후보 풀이 달라지므로 일반화하지 않았다.

실측 시계열과 연도 없는 각주 예상치가 E-3-2 풀에서 경쟁하므로, 코드별 지표 계열 축에
`연결(일부)` 실측 계열을 추가했다. 그 결과 2024 실측 3,136,024가 각주 예상치
14,160,000을 이긴다. NAVER의 Scope 3 카테고리별 보조수치는 backfill의 기존 점유 가드가
merge 사전에서 다시 살아나지 않도록 E-3-2 차단 상태를 내부적으로 전달해 기존값을 보존했다.

### (다) 총량 어휘가 부분 어휘를 가림

`_aggregation_rank`가 총량 어휘를 먼저 검사해 다음 두 라벨을 모두 총량(0)으로 판정했다.

```text
온실가스 배출량 합계 (...) 해외 자회사  → 종전 0, 수정 2
온실가스 배출량 합계 (...) 합계          → 종전 0, 수정 0
```

부분 어휘는 더 구체적인 범위 한정이므로 총량 어휘보다 먼저 판정하도록 순서를 바꿨다.
음성 검증에서 `용수 사용량(취수량) 합계 2024`는 계속 총량이다.

5개사 재생에서 신한의 `국내(지역 기반)`·`국내(시장 기반)`은 조직 범위가 아니라 Scope 2
산정 방법임을 확인했다. 이를 단독 지역어 예외로 추가해 E-3-1 89,861을 보존했다.

### (라) 파생 어휘의 `증가` 누락

파생·비실적 어휘에 `증가`, `감소`, `증감률`, `전년 대비`, `전년대비`를 추가했다.
v5 5개사 전체 후보 hint를 조사한 결과 이 계열에 걸린 것은 모비스의
`에너지 사용량 증가` 1건뿐이며 정상 지표 충돌은 0건이었다.

음성 검증에서 `에너지 사용량`, `전력 사용량`, `재생에너지 사용 비율`,
`재생에너지 사용·전환율`, `용수 사용량(취수량) 합계 2024`가 파생으로 판정되지 않는 것을
고정했다.

## 오프라인 전후 결과

5개 PDF를 `OCR_CACHE_MODE=on`으로 재생했고 `LLMClient.complete`는 호출 시 즉시 실패하도록
patch했다. 따라서 아래 결과에는 라이브 호출과 과금이 없다.

**`out/*_v5.json` 덤프로 하는 리플레이는 선택 축((다)(라))만 검증한다.** 배정 축
((가)(나))은 그래프를 다시 빌드해야 확인된다. v5 덤프의 노드 풀은 (가) 수정 이전에
만들어져 `대기오염물질 배출량 합계 210.68` 노드가 아예 없다. 그 상태로 리플레이하면
`E-7-1: 7,240 → 7.24`처럼 개선이 악화로 보이는 착시가 난다. 같은 이유로 삼성전기
`E-4-1: 8,979 → 2,494,209 MWh`도 재빌드 전 수치다. 배정 축은 위처럼 원본 캐시에서
`_backfill_kesg_codes`와 `merge_ocr_extraction`을 다시 실행해 검증해야 한다.

`out/`은 라이브 산출물이라 커밋하지 않는다. 재현에 보존할 필요가 있는 산출물은 기존

## 남은 구조적 부채

`evidence_graph._HINT_TO_KESG`는 손으로 관리하는 부분문자열 사전이고,
`kesg_items.resolve_kesg_code`는 항목 alias 기반 해소기다. 이번 Scope 3 결함처럼 두 사전은
서로 다른 답을 낼 수 있다. 이번 작업은 요구 범위대로 Scope 3 최소 키와 배정 negative만
추가했으며 두 사전 통합은 하지 않았다.
