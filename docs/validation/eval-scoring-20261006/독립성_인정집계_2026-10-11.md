## 2. 반영한 열람 기록

### 2.1 B 회신 2026-10-09 (유지)

초안 AI(Claude Code 세션)가 라벨링 가이드의 RBA-C-4-E-6-2 "29.3%/92%" 언급을 읽었고, 사람 B가 그 초안을 원본과 대조해 검토했다. 그래서 RBA-C-4-E-6-2는 `expected_value` 노출 행으로 센다(기존 행 유지).

### 2.2 B 회신 2026-10-11 열람확인 보완

B는 라벨 작성 시작(10/9 14:13) 전까지의 작업 대화 기록(검사 담당 대화, Claude Code 세션 1·2 화면 출력)을 15개 문항 ID로 검색해 확인했다. 원문은 이 저장소에 없다(지민이 전달한 회신).

| 문항 | B 회신(응답 / 기대값 / A 초안) | 현재 기록 | 이유 |
|---|---|---|---|
| RBA-C-4-E-6-2 | 예 / 아니오 / 아니오 | **노출 제외** (`system_answer` 추가, 기존 `expected_value` 유지) | 10/6 B-1 출력 검사기 보고에 ESGenie 응답서 셀 값이 나왔다 |
| RBA-C-4-E-6-1, RBA-C-8-E-4-1 | 아니오 / 아니오 / 아니오 | **노출 제외** (`expected_value`) | 작업지시서_B §4.1 "부분 범위" 함정 설명(에너지: 전력만·가스 미포함 / 폐기물: 4월·제1공장)을 읽었다. 이 표는 문항 ID와 결함을 함께 지정하므로 문항별 기대 판정 힌트로 보고 보수적으로 제외한다(정민 재검토 §3-1 권고 반영). 힌트가 실제 라벨과 일치했는지와 무관하다 |
| RBA-C-8-E-3-1, E-11, E-12, C-5-E-7-1, C-8-E-4-2 | 아니오 / 아니오 / 아니오 | **확인 대기** (`unconfirmed`) | 라벨 작성 전 대화에서 B-3 사례 분류를 봤다(C-8-E-3-1 함정 후보 추가 / E-11 normal / E-12 partial_scope / C-5-E-7-1·C-8-E-4-2 증빙 부재 확인). **그 분류를 누가 썼는지, 원문과 전달 경로가 확인되지 않았다.** 타인의 기대 판정 힌트면 제외, B 자신의 원본 판단이면 경위를 기록해 인정한다. 구별할 수 없으므로 대기로 둔다(정민 재검토 R1). 직전 판(`2d353bf`)에서는 이 5문항을 독립으로 인정했으나 이를 되돌린다 |
| RBA-A-6, B-7, C-1, C-5, E-2, E-3, E-8 | 아니오 / 아니오 / 아니오 | **독립** (`none`) | 기록 검색에서 결과·분류 언급이 없었다. A-6·E-8은 사용법 안내의 입력 예시로만 문항 ID가 나왔다 |

초안 AI에 대해 B가 확인한 것:
- 10/9 13:04에 새로 연 Claude Code 세션으로 **B-1 세션과 다른 세션**이며 작업 폴더도 다르다. 도구 기록상 ESGenie 결과나 정답 포함 폴더를 연 기록이 없다. 읽은 것은 라벨링 폴더 파일과 작업 메모뿐이다.
- "29.3%/92%"의 출처는 작업지시서_B(2026-10-05) §4.1 함정 표이며, B 검사 담당이 B 쪽 `라벨링_가이드.md` §7-1과 `체크리스트_사용법.md` §6에 열람확인 예시로 옮겨 적었다. 이 두 문서는 이 저장소에 없어 대조하지 못했다.
- **초안 AI가 본 "일부 문항 ID 목록"이 어느 문항·문구인지는 아직 모른다.** 목록에 문항별 판정 힌트가 있었다면 해당 문항의 상태를 다시 판단해야 한다.

### 2.3 이번 회신을 읽는 방식
- "기록을 검색해 보지 못했다"는 기억에 기댄 "본 기억 없음"보다 강한 확인이지만, 기록에 남지 않은 열람까지 증명하지는 못한다. 그래서 `none`의 사유에 "작업 대화 기록 검색 기준, 기억 아님"으로 적었다.
- 독립으로 인정한 행은 모두 판정 힌트 출처를 설명할 수 있어야 한다. 설명할 수 없는 행은 대기로 둔다.

## 4. 협의 전 A·B 원값 대조

`AB_원값대조_요약_2026-10-11.json`의 값이다. **"전체"는 독립 일치율이 아니다.** 인정 행이 바뀔 때마다 다시 산출한다.

| 집합 | 부분집합 | 행 | 판정 일치 | hold 사유 일치(둘 다 hold) | 값 일치(둘 다 answer, B 10/10 수정본) |
|---|---|---|---|---|---|
| 공식 20행 | 전체(노출 제외 전) | 20 | 20/20 | 6/16 | 4/4 |
| 공식 20행 | B 독립 인정 행 | 14 | **14/14** | **4/12** | **2/2** |
| 공식 20행 | B 독립 + A 신고 노출 행 제외 | 14 | 14/14 | 4/12 | 2/2 |
| 수치 전수 12행 | 전체(노출 제외 전) | 12 | 12/12 | 8/8 | 2/4 |
| 수치 전수 12행 | B 독립 인정 행 | 0 | 산출 불가(분모 0) | 산출 불가 | 산출 불가 |

- 공식 집합의 A 신고 노출 문항(C-8-E-3-1)은 B 쪽이 대기라 이미 빠져 있어, 두 부분집합의 값이 같다.
- B 10/9 원본은 answer 행의 값 칸을 비워 둬서 값 일치가 0이다(전체 0/4, B 독립 0/2). 10/10 수정본은 그 칸에 "예"만 채웠다. 값 일치는 문자열 비교이며 단위 환산을 하지 않는다.
- hold 사유 불일치: 공식 집합의 RBA-A-6, C-1, E-12, E-3, E-8 × 두 단계(10행). A `no_evidence` / B `not_comparable`. **협의 결과: A 라벨 유지**(정민 결정 2026-10-10, 지민 전달). B 독립 행만 보면 A-6, C-1, E-3, E-8의 8행이 불일치이고 일치는 B-7, C-5의 4행이다(4/12). 사유 일치율이 낮다는 점을 숨기지 않는다.
- 수치 전수 값 불일치 2행(전체 기준): RBA-C-4-E-6-1 두 단계. A `18.4 톤` / B `18,400 kg`.
- 공식 20행과 수치 전수 12행을 합친 일치율은 만들지 않는다.

## 5. A 쪽 한계

A는 RBA-C-4-E-6-2(기대값·시스템 응답), RBA-C-4-E-6-1·C-8-E-4-1·C-8-E-3-1(시스템 응답)에 과거 노출이 있다(PR #71 작업 중, 본인 신고). 이 4문항(두 단계 8행)의 A 최종 라벨은 원본으로 다시 확인했지만 독립 라벨이 아니다. **새 실행 결과를 라벨 커밋 뒤에 열었다는 순서만으로 이 과거 노출이 없어지지 않는다.**
