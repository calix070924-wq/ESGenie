# 배치 B — 실데이터 미공시 평가셋 결과 (멀티티커, 주입 없음)

> bench: `data/benchmark_v2/batch_b_omission.json` (n=21, 회사=['005930', 'SME001', 'SME002']) · 모드: AUTO · 임계값 BASELINE 고정
> 각 케이스는 해당 회사가 **실제로 공시하지 않은** 지표에 대한 주장 → 주입 없이 실 그래프에서 no_evidence 자연 발동.

## 0. 데이터 무결성 감사 (expect 대비 실제)

- ✅ 전부 의도대로 동작 (no_evidence 자연 발동 15건, 문제 0건)

## 1. 전역 지표 (OFF vs ON)

| 해석 | Coverage | Accuracy(assessed) | Overall | 기권수 |
|---|---|---|---|---|
| OFF (기권 무시) | 1.000 | 0.571 | 0.571 | 0 |
| ON  (기권 반영) | 0.286 | 1.000 | 0.286 | 15 |

- 사유별 기권: {'no_evidence': 15, 'unit_mismatch': 0, 'low_confidence': 0}
- ΔAccuracy(assessed) = +0.429 · ΔCoverage = -0.714 · ΔOverall = -0.286

## 2. 기권 분해 — 가치(save) vs 비용(waste)

- 총 기권 15건 = save 9건 + waste 6건
- **save**(OFF면 틀렸을 미탐 → 검토 구제): ['B-GW-01', 'B-GW-02', 'B-GW-03', 'B-GW-04', 'B-GW-05', 'B-GW-06', 'B-GW-07', 'B-GW-08', 'B-GW-09']
- **waste**(OFF면 맞았을 것 → 불필요 검토): ['B-CL-01', 'B-CL-02', 'B-CL-03', 'B-CL-04', 'B-CL-05', 'B-CL-06']
- **기권 정밀도 p = 0.600** · 손익분기 **B/R > 0.6667**

> 주의: p는 이 파일럿의 미공시 영역 라벨 구성(greenwash:clean = 9:6)을 반영한 값이다. 실제 운영에서의 p는 '미검증 주장 중 실제 그린워싱 비율'에 좌우되므로, 회사·지표 수를 늘려 신뢰구간과 함께 재추정해야 한다(§4 다음 단계).

## 3. probe(주입) 대비 — 실데이터가 말해주는 것

probe(005930 단일 그래프에 omit_codes 주입, p=0.60)와 달리 이 배치는 서로 다른 회사의 **실제 공시 공백**에서 no_evidence가 자연 발동했다 — 주입 없이도 기권 메커니즘이 실 데이터에서 동일하게 작동함을 확인. 이로써 '현행 벤치는 미공시를 관측 못 한다'는 감사 결론의 해법(배치 B)이 실제로 성립함을 실측으로 입증했다(자연 no_evidence 15건).

## 4. 판정 · 다음 단계

실데이터에서 no_evidence 기권이 15건/21 자연 발동했고(현행 dev/test는 0건이었음), 그중 미탐 9건을 사람 검토로 전환하며 자동판정 정확도를 +0.429 끌어올렸다(정밀도 p=0.600). Overall(-0.286)은 이 설계에서 구조상 오를 수 없으므로 채택 판정은 p와 B/R로 한다. 다음 단계: (1) 이 셋을 실키 회귀에 편입해 실측 고정, (2) HITL 라우팅을 붙여 '기권→검토'를 실제 동작으로 연결, (3) 회사 수·지표 수를 늘려 정밀도 p의 안정성(신뢰구간) 확인.
