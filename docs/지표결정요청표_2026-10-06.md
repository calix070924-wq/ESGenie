# 지표 산식 결정 요청표 (2026-10-06, 2차 정정)

**확정된 것과 결정이 필요한 것을 분리했다.** §1은 승인 대상이 아니다. 승인이 필요한
것은 §5뿐이고, **승인 전까지 코드에 적용하지 않는다.**

1차 요청표에서 잘못 올린 것을 정정했다(2026-10-06 정민 지시).

| 1차에서 잘못한 것 | 정정 |
|---|---|
| D1의 "근거 일치를 분자에 넣을지"를 승인 질문으로 올렸다 | **이미 확정이다.** 답변과 근거가 **모두** 맞아야 동시 정답으로 센다. §1로 옮겼다 |
| 핵심 지표에서 **잘못된 확정 수·불필요한 보류 수가 빠져** 있었다 | §2 핵심 5개에 넣었다 |
| "연결한 근거가 정답인 비율"을 핵심 지표(D4)로 올렸다 | **보조 결과**로 내렸다. 자료 연결률과는 계속 구분한다 |
| "반복 5회 처리"를 지표(D5)로 올렸다 | 지표가 아니다. **실행·집계 방식**으로 §4에 분리했다 |
| 종합 점수를 "미정 산식"으로 적었다 | **합치지 않는 것이 확정 요구사항이다.** 향후 구현 목록에서 뺐다 |

## 1. 이미 확정 — 승인 대상이 아니다

다시 결정할 필요가 없다. 참고용으로만 적는다.

| 확정 내용 | 근거 |
|---|---|
| **답변과 근거가 모두 맞아야 동시 정답으로 센다.** 값만 맞고 근거가 틀린 행은 동시 정답이 아니다 | 원요구사항. 2026-10-06 재확인 |
| 값 일치 건수를 곧 "최종 답변 정확성"이라고 부르지 않는다 | 같음 |
| **잘못된 확정·불필요한 보류는 건수(수)로 낸다** | 작업지시서 A §6.2. 구현·검증됨 |
| **지표를 하나의 종합 점수로 합치지 않는다.** 향후 구현 대상도 아니다 | 확정 요구사항 |
| **`self_reported`(미검증 제출)를 확정 응답으로 세지 않는다** | 작업지시서 A §6.1~6.2. 구현·검증됨(변이 테스트로 확인) |
| "자료 연결률"과 "연결한 근거가 정답인 비율"을 정의 없이 같은 것으로 취급하지 않는다 | 기존 지시 |
| 단위·기간·대상 차이를 정규화로 숨기지 않는다 | 작업지시서 A §7 |
| 모든 비율에 분자·분모 **건수를 함께 적는다**(`12/20`). 산출 불가는 "산출 불가"로 적고 **0으로 적지 않는다** | 기존 지시 |
| 공식 표본과 수치형 전수는 **분리 보고**한다. 합산하지 않는다 | 2026-10-06 지시 |
| 노출 확인 행은 독립 일치율 분자·분모에서 제외한다 | 2026-10-06 지시. 구현·검증됨 |
| 실행별 결과를 덮어쓰거나 여러 실행의 같은 `qid`를 합치지 않는다 | 기존 지시. 구현·검증됨 |
| 라벨을 채점보다 먼저 커밋하고 해시를 기록한다 | 기존 지시 |

## 2. 핵심 지표 — 다섯 개

원요구사항의 순서와 이름을 그대로 쓴다.

| # | 핵심 지표 | 종류 | 확정된 분자 조건 |
|---|---|---|---|
| **M1** | **답변·근거 동시 정답률** | 비율 | `value_match=match` **그리고** `source_match=match`인 행 (§1 확정) |
| **M2** | **잘못된 확정 수** | **건수** | `bucket=wrong_confirmation` (확정·구현됨) |
| **M3** | **불필요한 보류 수** | **건수** | `bucket=unnecessary_hold` (확정·구현됨) |
| **M4** | **자동응답률** | 비율 | **`confirmed` 행만.** `self_reported`는 분자에 넣지 않는다 (§1 확정) |
| **M5** | **자료 연결률** | 비율 | 근거(`evidence`)가 1건 이상인 행 |

M2·M3은 **건수**다. 비율로 바꾸지 않는다 — 분모를 정해 비율로 만들면 원요구사항과
다른 지표가 된다.

### 2.1 M4 자동응답률 — 이 이름에 어떤 상태가 들어가는가

**`confirmed`(검증까지 끝난 확정 응답)만 들어간다.** `self_reported`(값은 냈으나
경고를 붙여 제출한 상태)는 들어가지 않는다.

| 응답 상태 | M4 분자 | 비고 |
|---|---|---|
| `confirmed` | **포함** | 확정 응답 |
| `unverified_submitted` (`self_reported`) | **제외** | 보조 결과 A3으로 **따로** 낸다 |
| `hold` / `not_applicable` / `unparsed` / `undetermined` | 제외 | |

보고 문장에서도 분리한다. "자동응답률"과 "경고를 붙여 제출한 비율"을 한 수치로 합치거나
서로 바꿔 쓰지 않는다. 두 수치를 더해 "값을 낸 비율"이라고 부르려면 그 이름을 따로 쓴다.

## 3. 보조 결과 — 핵심 지표가 아니다

핵심 지표를 해석하려면 필요하지만, 핵심 5개와 같은 줄에 놓지 않는다.

| # | 보조 결과 | 내용 |
|---|---|---|
| A1 | 답변 값 일치 | `value_match` 건수. **단독으로 정확성이라 부르지 않는다** |
| A2 | 근거 일치 | `source_match` 건수 |
| A3 | 경고를 붙여 제출한 행의 비율 | `self_reported` 행. **M4와 구분한다** |
| A4 | 올바른 보류 수 | `bucket=correct_hold` 건수 |
| A5 | **연결한 근거가 정답인 비율** | 분모 = 근거를 1건 이상 단 행. **M5와 다르다** — 근거를 전부 달았으나 전부 틀리면 M5 = 100%, A5 = 0%다 |
| A6 | 미해결 행 | `unresolved` 건수와 행별 이유. 어느 지표에도 들어가지 않는다 |

## 4. 반복 5회 — 지표가 아니라 실행·집계 방식

지표 목록에서 뺐다. 결정할 산식이 아니라 **실행 방법**이다.

- 한 실행 = 한 결과 파일. `--out`을 실행마다 다르게 준다(이미 구현·검증됨).
- 여러 실행의 같은 `qid`를 하나로 합치지 않는다(이미 구현·검증됨).
- 보고할 때는 실행별 수치를 **나열**하고 최솟값·최댓값·편차를 함께 적는다. 평균 하나로
  줄이면 편차가 숨는다.
- 먼저 1회 실행을 해석할 수 있어야 반복 실행의 편차가 뜻을 가진다.

여기서 승인이 필요한 것은 없다. 다만 §5의 Q6(보고 단위)과 함께 보면 된다.

## 5. 결정이 필요한 것 — 이것만 승인해 주시면 된다

확정된 조건은 뺐다. 아래는 **적용 대상·분모·예외 처리**만 남긴 것이다.

| # | 지표 | 결정할 것 | A의 제안 | 선택에 따른 영향 |
|---|---|---|---|---|
| **Q1** | M1 | **적용 대상.** 라벨이 `answer`인 행만 보는가, 라벨이 `hold`인 행까지 "보류가 맞았는가"로 묶어 보는가 | 라벨 `answer` 행만. 보류 적중은 M3·A4로 따로 본다 | 묶으면 보류가 많은 시스템이 유리해진다. 분리하면 M1이 "답을 낸 것의 품질"로 좁아진다 |
| **Q2** | M1 | **분모.** ① 라벨 `answer` 행 중 응답 행이 있는 것 ② 라벨 `answer` 행 전부(응답 누락 포함) | **②.** 답을 내지 못한 것도 결과다 | ①은 응답을 적게 낼수록 높아진다. ②는 누락이 벌점이 된다 |
| **Q3** | M4 | **분모.** ① 전체 48행 × 단계 ② 라벨이 `na`가 아닌 행 | **①.** 양식 전체를 분모로 둔다 | ②로 하면 `na` 문항이 많을 때 높아진다. ①은 양식 전체 커버리지를 뜻한다 |
| **Q4** | M5 | **분모.** ① 값을 제출한 행(`confirmed` + `self_reported`) ② 전체 48행 | **①.** "낸 답에 근거를 달았는가"가 된다 | ②로 하면 보류가 많을 때 낮아지고, 지표 이름이 "응답률 × 연결률"에 가까워진다 |
| **Q5** | M1·M4·M5 공통 | **`na`(해당 없음) 행 처리.** 분모에서 빼는가 | M1·M5 **분모 제외**, M4는 Q3 선택에 따른다 | 빼면 분모가 줄어든다. 줄어든 사실을 함께 적는다 |
| **Q6** | 전부 | **보고 단위.** 단계별(48행) / 전체(96행) / 둘 다 | **둘 다.** 단계별이 기본, 전체는 참고 | 단계별만 내면 전체 수치를 묻게 되고, 전체만 내면 initial·followup 차이가 숨는다 |
| **Q7** | 전부 | **`unresolved`가 1건 이상일 때 비율을 내는가** | **낸다. 단 분모에서 제외하고 제외 건수·이유를 같은 표에 적는다.** 또는 전면 보류 | 내지 않으면 미정 조합이 남은 동안 수치가 없다. 내면 분모가 줄어든 수치를 해석해야 한다 |
| **Q8** | 전부 | **누락 행(응답 문서에 행이 없음)과 `unparsed`(파싱 실패) 처리** | 둘 다 **분모 포함·분자 제외.** 시스템이 답을 못 낸 결과로 센다 | 분모에서 빼면 파싱이 깨질수록 수치가 좋아진다. 포함하면 입력 품질 문제가 수치에 섞인다 |

M2·M3은 건수라서 분모 결정이 없다. Q6(보고 단위)만 적용된다.

## 6. 결정 전까지 코드가 하는 일

- 행별 분류와 **건수**만 낸다. `bucket_counts`·`value_match_counts`·`source_match_counts`·
  `detail_counts`·`unresolved_reasons`.
- M2·M3에 해당하는 건수는 이미 나온다(`wrong_confirmation`·`unnecessary_hold`).
- M1·M4·M5의 **비율은 내지 않는다.** `metrics_blocked_reason`에 이유를 적는다.
- 종합 점수는 내지 않는다. **앞으로도 만들지 않는다**(§1 확정).
- 미정 조합은 `unresolved`로 남기고 행별 이유를 적는다. 어느 지표에도 넣지 않는다.

Q1~Q8이 정해지면 **그때 산식을 구현하고 테스트를 추가한다.** 승인되지 않은 산식을
미리 넣어 두지 않았다.
