## 1. 결함 (a) — 총량 후보가 없으면 부분값을 고른다

### 원인

`_PARTIAL_TERMS`는 우선순위 **5단계의 후순위 축이지 배제가 아니다.** 후보가 전부 부분값이면
그중 하나가 이긴다. 실측에 그런 풀이 두 개 있었다.

```
LG화학  E-4-1 : 36노드에 '합계/총계' hint가 0개  → '비재생 전력 소비량 해외 2025' 5,104 TJ
NAVER   E-3-2 : 노드 1개                        → 'Scope 3 - Upstream 구매 제품 및 서비스' 71,385
```

NAVER 71,385는 `docs/라벨링_발견_수정목록_2026-07-19.md` §1이 Scope3 Category 1로 지목한 값이다.
총합 자리에 카테고리 하나가 실린 것으로, §3-6(배출량 89% 축소)과 같은 성격의 리스크다.

### 결정 — 값은 싣고 부분값임을 표기 (선택지 ㄴ)

미공시로 버리지 않는다. 커버리지가 이미 5~7항목/17이고, 값 자체는 실제 공시값이다.
`unit_suspect` → `공시(증빙연결)·단위확인`과 같은 Phase 2 표기 관행을 그대로 쓴다.

**D1은 이 오류를 못 잡는다** — 원장과 노드가 같은 값이라 Δ=0이다. 표기가 유일한 방어선이므로

## 2. 결함 (b) — 단위 표기 변종 미처리 (신한 2건)

```python
# 전
normalize_to_item_unit("E-3-1", 100.0, "ton CO2 eq")  → (100.0, 'ton CO2 eq', 'unit_suspect')  ✗
normalize_to_item_unit("E-3-1", 100.0, "tCO2 eq")     → (100.0, 'tCO2eq', None)                ✓
# 후 — 4종 변종 전부
'ton CO2 eq' / 'ton CO2eq' / 'tCO2 eq' / '톤 CO2eq'   → (100.0, 'tCO2eq', None)
```

원인: 문자열 폴백이 `_norm`(소문자·공백제거)만 써서 `toncO2eq ≠ tco2eq`였다.
`tCO2 eq`는 공백 제거 후 `_UNIT_ALIASES`에 등재된 `tco2eq`가 되어 우연히 통과했을 뿐이다.

**중복 구현하지 않았다** — `layer1_extract._relaxed_unit`이 이미 `^tons?(?=co2|$) → t` 축약을
갖고 있어 그것을 import해 폴백 비교에 쓴다. 두 지점을 함께 고쳤다:

- `normalize_to_item_unit`의 문자열 폴백 (저장 축)
- `_unit_rank`의 문자열 폴백 (선택 축) — 두 축이 같은 단위를 다르게 보면 "랭킹은 2인데
  저장은 동일 단위로 통일"이라는 모순이 생긴다

재사용 사실은 `test_relaxed_unit_is_reused_not_reimplemented`가 patch로 고정한다
(`_relaxed_unit`을 항등 함수로 바꾸면 판정이 뒤집혀야 한다).

음성 테스트 — 진짜 다른 단위(`명`·`건` vs `TJ`/`tCO2eq`)는 여전히 `unit_suspect`.

## 4. 결함 (d) — 시간 단위 오류

```
LG화학 E-5-1  540,000 ton  '일평균 산업용수 공급량'   ← 연간이 아니다 (365배)
```

`_DERIVED_TERMS`에 `일평균`·`일 평균`·`월평균`·`월 평균`·`1일당`·`1일 당`·`1개월당` 추가.
**`평균` 단독은 넣지 않았다** — `평균 근속연수`·`1인 평균 교육시간` 같은 정상 지표가 걸린다
(음성 테스트 `test_plain_average_metrics_are_not_excluded`).

### 후보 1개 우회를 없앴다 (계약 변경)

노드가 1개뿐이라 `if len(pool) == 1: return pool[0]`이 hard 배제 **앞**에 있어 규칙이 개입하지
못했다. 그 줄을 배제 **뒤**로 옮겼다:

```python
survivors = [n for n in pool if not is_derived_hint(...) and not _conflicts_metric(...)]
if not survivors:
    return None
if len(survivors) == 1:
    return survivors[0]     # 순위 축(3~7)만 우회 — 결과가 같으므로 판정 불변
```

의미: **hard 배제(1·2단계)는 후보 1개에도 적용되고, 순위 축은 여전히 우회된다.** 부분값·분해값
하나뿐이면 종전대로 채택된다((a)의 결정과 일관 — 배제는 (d)뿐이다).

기존 테스트 `test_single_candidate_wins_regardless_of_rules`는 계약이 바뀌었으므로 이름과
케이스를 갱신했다(파생 hint 유일 후보 → 부분값 유일 후보). 배제 방향은 새 테스트가 고정한다.

결과: LG E-5-1은 **미공시 + `no_representative_node`**. 365배 틀린 값보다 낫다(라벨링 §3-1).

## 7. 소계-합 검산 누락 경위 (확인만 — 이번 범위 밖)

### 결론 — 의도적 제외가 아니라 **누락이다.** 지시서 요구를 구현하지 않고 결과 문서에도 적지 않았다.

근거 4가지:

1. **요구는 명시적이었다.** `작업문서/프롬프트_L1대표노드선택_2026-07-26.md` §2-2가 우선순위
   6번으로 `소계-합 검산`을 넣고 §2-6이 사양(같은 집계등급 후보 중 하나가 나머지의 합과
   ±0.1% 내로 일치하면 총량 확정, 독립 함수로 분리)까지 적었다.
   같은 문서 §2-6은 **"6번을 반드시 구현해라"**, §4-1은 **"E-6-1은 §2-4와 §2-6을 각각
   태우는 케이스다 — 둘 다 없으면 실패해야 한다"**고 못박았다.

2. **코드에 없다.** `node_select.py`에 합·항등식·오차 허용 로직이 없고, docstring 우선순위도
   6번이 `단위 정합`, 7번이 `연도`, 8번이 `None`인 **8단계**다(지시서는 소계-합을 6번에
   끼운 8단계).

3. **결과 문서가 누락을 신고하지 않았다.** `docs/대표노드선택_결과_2026-07-26.md`의 우선순위
   표(§105-113)는 소계-합 없는 8단계를 그대로 적었고, §9 "범위 밖으로 남긴 것" 표에도
   이 항목이 없다. 다른 미구현 항목(연도 열 뭉개짐, D1 축 재정의, `best_nodes` 등)은
   전부 그 표에 적혀 있다. **의도적 제외라면 그 표에 있어야 한다.**

4. **후속 지시서가 있다고 오인했다.** `작업문서/프롬프트_연도복원_2026-07-27.md` §작업 2는
   *"`select_representative_node`의 소계-합 검산이 **이미 있다**(§2-6, 커밋 699d9d7).
   그 로직을 독립 함수로 빼서 …"*라고 전제하고 있다. 구현 없이 후속 작업의 전제가 되어
   누락이 한 단계 더 가려졌다.

### 왜 통과했는가 (추정)

E-6-1이 `발생량` 72,463을 정답으로 뽑는 데 **§2-4(지표 계열 축)만으로 충분**했기 때문이다.
지시서 §4-1은 §2-4와 §2-6이 각각 다른 케이스를 태운다고 했지만, 실제로는 `_METRIC_FAMILY`의
`발생량 > 배출량 > 처리량` 하나로 실측 4사례가 전부 통과했다. 검산 없이도 회귀가 초록이라
누락이 드러나지 않았다.

### 필요한 자리는 남아 있다 — 신한 E-3-1

```
선택: 89,861  '온실가스 배출량 - 총 배출량 국내(지역 기반)'   ← '총 '로 집계 축 0

계열사 '총 배출량' 노드 15개 전량 합 = 89,861   (오차 0)
  신한은행 57,475 · 신한카드 11,705 · 신한투자증권 6,640 · 신한라이프 8,518
  · 제주은행 1,479 · 신한자산운용 853 · 신한캐피탈 699 · 신한DS 463
  · 지주 403 · 신한저축은행 398 · 펀드파트너스 340 · 신한이지손보 291
  · 신한벤처투자 263 · 신한자산신탁 215 · 신한리츠운용 119
```

**지시서의 "일부 계열사 누락 추정"은 실측으로 반증된다** — 지시서가 든 85,440은 6개사만
더한 값이고, 덤프의 계열사 노드 15개를 전부 더하면 89,861과 **오차 0으로 일치**한다.

즉 이 풀에서는 검산이 선택을 바꾸지 않고 **확증한다**. 반대로 지주 상위 총계 행이 없는
회사에서는 검산이 유일한 총량 식별 수단이 된다 — 그것이 이 과제를 별도로 잡는 이유다.

**별도 과제로 잡는다.** 이번 작업에 넣지 않았다(지시서 지정 — 범위가 다르다).
같이 처리할 항목: (나) 연도 복원(같은 검산 함수를 재사용), E-6-2 부분값 백로그.
