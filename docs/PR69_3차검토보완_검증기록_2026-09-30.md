## 2. 공통 판정 결과

0 근거 판정은 `_ZeroVerdict` 하나로 돌려준다. 파싱·사실성·범위 일치를 bool 하나로 섞지 않는다.

| `status` | 의미 | 처리 |
|---|---|---|
| `CONFIRMED` | 같은 지표의 실제 사실이고 요청 범위까지 확인 | 채택 |
| `SOURCE_ONLY` | 원문 사실은 확인, 요청 범위의 실적인지는 미확정 | 값·출처·**원문 범위**를 보존하고 범위 미확정 표시 |
| `REJECTED` | 다른 지표·목표·조건·가정·명시적 범위 충돌 | 싣지 않고 `zero_not_in_evidence` + `cause` |
| `UNRESOLVED` | 해석·근거 연결을 판정하지 못함 | 싣지 않고 원문·모델 원값을 감사 기록에 보존 |

- 결과 필드: `cause`, `candidate`(numeric | negation), `evidence_text`·`evidence_offset`,
  `evidence_period`·`evidence_site`, `requested_scope`, `source_scope`(원문 `_DateSpan`).
- 호환용 `accepted`는 **"원문 사실로 보존한다"**(CONFIRMED 또는 SOURCE_ONLY)는 뜻이다. 요청 범위까지
  확인됐다는 뜻은 `scope_confirmed`(CONFIRMED만)이다. `_zero_is_grounded`는 `accepted`를 돌려준다.
- 기록에서 쪽 0과 쪽 미상(None)을 구분한다(`page`). 채택하지 않은 0에도 `status`·모델 원값·
  `requested_scope`·`evidence_text`를 남긴다.

## 3. 네 경로의 변경과 기본 반환 규칙

### F1 [P1] 복합 단위 — 분모 표지가 있으면 단순 단위로 복귀 금지

- `_read_unit`이 `_UnitRead`(`raw_text`·범위·`status`·`canonical_unit`·`has_denominator_marker`·
  `reason`)를 돌려준다. `status`: `SIMPLE_COMPLETE` / `COMPOUND_COMPLETE` / `INCOMPLETE` /
  `UNKNOWN` / `ABSENT`.
- 순서: 분자 → 제한된 공백·줄바꿈 건너뛰기 → **슬래시를 독립적으로 검출** → 있으면 그 뒤로는
  `SIMPLE_COMPLETE`를 반환하지 않는다. 분모가 비었거나(`MJ/`) 괄호·숫자·줄바꿈 분모를 끝까지
  확인하지 못하면 `INCOMPLETE`. 분자 뒤에 소비하지 못한 이어짐이 있으면 `UNKNOWN`.
- `_trailing_unit`·`_kr_scale_chains`·`_evidence_amounts_in_unit`·`_reconcile_scale_chain`이 같은
  판독 결과를 쓰고, `SIMPLE_COMPLETE`일 때만 단위군·환산에 들어간다. 분자를 재사용하던 우회 경로를
  없앴다. 보정 기록에 `source_unit_status`를 남긴다.
- 결과: `2 GJ + 500 MJ, 1만 2천 MJ/(톤)`·`MJ/\n톤`·`MJ/100개`에서 2.5 GJ 유지, 보정 기록 없음.

### F2 [P2] 숫자 0 — 숫자·서술 후보 모두 같은 최종 검사

- `_zero_candidates`가 숫자 0(`_ZERO_NUMERIC_RE`)과 부정 서술(`_ZERO_NEGATION_RE`)을 **위치를 가진
  후보**로 찾는다. 후보마다 자기 서술·같은 절의 앞부분 문맥·표 열 머리(`_column_header`)만 쓴다.
- 채택 조건은 한 곳에서 결정한다: 대상(`_zero_subject`: same/target/different/unclear) →
  사실성(`_numeric_zero_mood`/`_negation_mood`) → 범위(`_zero_scope_verdict`).
  `if 인용에 0이 있음: 채택` 분기는 없다.
- 여러 후보는 상태 순위로 고르되 대상이 맞은 후보를 우선한다. 다른 후보의 0·날짜·사업장을
  빌리지 않는다.
- 다른 행의 0(`지하수 | 0.0 | 12.4`를 `장기차입금`의 근거로)은 `other_subject`로 거부한다. 행 라벨이
  지표명의 부분 집합이고 구체 낱말·지표 종류가 같으며 표 행(`|`)이거나 열 머리가 있을 때만 같은
  지표로 본다.

### F3 [P2] 미분류 문장은 사실이 아니다

- `_negation_mood`·`_numeric_zero_mood`의 **마지막 반환은 `interpretation_unknown`**이다. 사실(None)은
  명시적 사실 분기(완료·현재 부정, 확인된 사실의 인용, 명시적 수치 행)에서만 반환한다.
- 판정 순서: 미확인 → 증거 부족 → 조건(`conditional`) → 가정(`assumption`) → 목표·미래 → 안긴 절 →
  이중 부정 → 관형형 → 사실 분기 → 미분류.
- 연결 어미 분리(`_ZERO_STATEMENT_SPLIT_RE`)는 `-며`(인용 `-다며`/`-라며` 제외)와 **용언 어미의
  `-고`**(`않고`·`했고` 등)만 경계로 본다. `사고`의 `고`에서 잘려 주어를 잃던 문제를 함께 고쳤다.
  `ISMS 인증은 미보유이며 향후 취득을 계획하고 있다`의 현재 미보유 0은 유지한다.

### F4 [P2] 보고 연도 ≠ 연간

- `_DateSpan`에 `kind`(REPORT_YEAR / ANNUAL / YEAR / MONTH / AS_OF / DAY / RANGE)와 `year_known`을
  더했다. 연도 미상의 부분 기간(`3월`, `04-01~04-07`)은 월·일만 보존한다.
- `_requested_period`: 모델의 `period="2026"`은 `REPORT_YEAR`(시작·종료일 없음). 지표명에 연간
  표지(`연간`·`연합계` 등)가 있거나 `2026년 연간`처럼 명시되면 `ANNUAL`.
- `_period_relation` 관계와 처리:

| 관계 | 처리 |
|---|---|
| match(같은 범위, 연간 표기 `2026년 연간` = `2026-01-01~2026-12-31`) | CONFIRMED |
| mismatch(겹치지 않음, 부분 기간의 충돌 `3월` ↔ 4월 포함) | REJECTED `period_mismatch` |
| unproven(겹치지만 다른 범위: 월 ↔ 기준일, 연간 ↔ 월) | REJECTED `period_unproven` |
| report_year(보고 연도 ↔ 그해 월간 사실) | SOURCE_ONLY `report_year_only` |
| unscoped / requested_unknown / year_unknown | SOURCE_ONLY(`period_not_stated` 등) |
| ambiguous(여러 범위 중 연결을 특정하지 못함) | UNRESOLVED `period_ambiguous` |

- 사업장 불일치는 기간보다 먼저 막는다. 사업장 미기재·원문에만 사업장이 있는 경우는 SOURCE_ONLY.
- 남긴 0의 경계(`_zero_scope_boundary`): `basis=actual`, 원문 `period_text`, 집계(MONTH→monthly,
  AS_OF/DAY→point, ANNUAL→annual, RANGE→period_total), 연도를 알면 시작·종료일. 모델 period는
  `provenance`의 `zero_evidence` 기록(`requested_period`·`source_period`·`status`·`cause`·`evidence`)으로
  따로 보존한다. SOURCE_ONLY면 `review_notes`에 사유를 남긴다.

### 후속 원장

- `derive_boundary`: 모델 경계의 `provenance`·`review_notes`를 규칙 추론 결과에 **항상 이어 붙인다**
  (추론 전 경계가 비어 있어도).
- `selection`: `scope_source_only` 플래그(`_from_nodes`·`finalize_ledger`), 범위 메모를 `scope_notes`에.
- `audit_trace`: `scope_source_only`를 추정값으로 센다(검증 완료로 보이지 않음).
- `source_review`: `scope_source_only` 문구 "원문 사실은 확인했지만 요청 기간·사업장의 실적임은
  확인하지 못했습니다(원문 범위로만 보존)". `conditional`·`assumption`·`period_ambiguous` 문구 추가.
  SOURCE_ONLY 0에는 '수치를 읽지 못함' 안내를 붙이지 않는다.
