# ESG 입문자를 위한 실사 작업 화면

## 결정

2026-09-12 시안 검토에서 B안(업무 안내)을 첫 화면으로, A안(답변·근거 대조)을 상세 검토로 연결하기로 했다.
서비스의 대상은 ESG 전문지식이 부족한 담당자다. 점수나 내부 검증 체계보다 다음 행동을 먼저 안내한다.

- 시작: 회사명, 자료 연도, 업종, 준비 목적. 업종을 몰라도 기본값으로 진행한다.
- 자료 올리기: 전기·가스 고지서, 사내 규정, 기존 질문서 등 구체적인 예를 보여준다.
- 내용 확인하기: 각 질문에 확인 이유, 다음 행동, 찾아볼 서류를 안내한다. 부족한 질문도 그대로 남긴다.
- 상세 검토: 찾은 답변과 연결된 원문·페이지를 나란히 보여준다. 직접 작성한 회사 답변은 별도로 비교한다.
- 작성·저장: 직접 쓴 답변과 검토 메모를 보관한다. 저장은 신뢰 상태를 승격시키지 않는다.
- 응답서 받기: 미확정 항목을 표시한 Excel, PDF·원문·근거·작성 내용을 포함하는 ZIP을 제공한다.

"자가신고"는 "직접 작성한 답변", "증빙"은 "답변을 확인할 서류", "HITL"은 "답변 작성 필요" 등으로 표현한다.
코드, 원래 판정 이유와 경고는 상세 펼치기에 남긴다. 없는 값은 0으로 나타내지 않는다.
질문 옆에는 "이 질문은 어떤 뜻인가요?"를 제공한다. 재활용 비율의 전체 양·기간, 전력 사용 기간,
온실가스 환산 단위, Scope 1·2·3의 범위, 윤리·인권·안전·회사 운영 등 질문에 맞는 설명을 펼쳐 볼 수 있다.
이 설명은 질문의 의미이며 회사가 기준을 충족했다는 판정으로 사용하지 않는다.

## 구현

`frontend/`는 React·TypeScript·Vite로 만든 화면이다. `esgenie/web/`의 FastAPI가 빌드된 화면과 같은 주소에서
프로젝트 API를 제공한다. 기존 `pipeline.run`과 `respond_from_pipeline`, 응답서 출력기를 재사용한다.
기존 Streamlit 및 엔진 구현은 이 변경에서 수정하지 않았다.

분석은 프로젝트별 스냅샷을 단일 작업 큐에서 실행한다. 입력 서류와 직접 작성한 설문 답변을 분리하여,
설문 답변이 독립 증빙으로 파이프라인에 들어가지 않게 한다. DART 대체 데이터와 의도적 과장 시연은 새 화면에서
사용하지 않는다. 실제 분석 동안 strict LLM 모드를 적용해 호출 실패를 가짜 성공으로 바꾸지 않는다.

연도 추정·계산값·부분 기간·표 읽기 미확정은 질문 화면과 출력에 남긴다. 검증된 것으로 표시된 원 응답도
화면에서 확인할 자료가 없으면 "자료 확인 전"으로 보수적으로 표현한다.

프로젝트·입력 개정 번호·결과 개정 번호·직접 작성한 답변·메모는 로컬 JSON에 원자적으로 저장한다.
분석 중 입력 변경을 막고, 입력이 바뀌면 기존 결과를 과거 결과로 표시하여 내려받기와 메모 작성을 막는다.
재분석 후 이전 메모는 삭제하지 않고 "이전 분석 기록"으로 구분한다. 분석 실패 시 이전 결과는 보관한다.

PDF·PNG·JPG를 지원한다. 파일당 20MB, 프로젝트당 20개·합계 100MB, 파일당 200쪽까지 받는다.
파일 이름·내용·암호·중복을 확인한다. 원본 조회는 프로젝트에 등록된 파일 ID로만 가능하다.
Excel에는 담당자가 작성한 내용이 별도 시트에 들어가며 수식으로 실행되지 않도록 텍스트로 내보낸다.

## 실행 및 보관

```bash
python -m esgenie.web --port 8765
```

기본 주소는 `http://127.0.0.1:8765`이며 로컬 사용을 대상으로 한다. 외부 다중 사용자 배포는 포함하지 않는다.
저장 위치는 `ESGENIE_WEB_DATA_DIR`로 지정할 수 있다. 기본값은 저장소의 `outputs/web_workspace`다.
기존 `.env`를 읽지만 화면과 API에는 키를 전달하지 않는다.

사용법 예시는 원본 파일을 포함하지 않는 세 개의 대표 항목이다. 9월 11일 확인된 수치(92%와 29.3%,
월 단위 전력량 142,560kWh, 추정 연도, 부족한 거버넌스 자료)를 설명하기 위한 예시이며,
파이프라인 오프라인 리플레이나 전체 실사 결과를 의미하지 않는다.

## 검증

- Python 전체: 1,224 통과, 12 건너뜀. 건너뛴 항목은 기존 비공개 실보고서 PDF를 요구하는 검사다.
- 새 서버 검사 12개: 업로드·역할 분리·원본 페이지·프로젝트 격리·중복/잘못된 파일·실행 중 입력 잠금·오류 노출 제한·
  이전 결과 유지·입력 변경 시 출력 차단·메모 버전·재시작 후 복원·출력 근거 보존·Excel 수식 방지·로컬 요청 가드·엔진 연결.
- 화면 빌드와 TypeScript 검사 통과.
- 실제 브라우저 검사 3개: 예시 진입→근거 대조→직접 작성→저장→새로고침 복원→Excel 받기,
  새 회사 생성→파일 업로드→역할 변경→손상 파일 안내, 375px/320px 화면 및 키보드 이동.
- 질문 설명 검사 1개: Scope 3를 구매 에너지 배출과 혼동하지 않고 Scope 1+2를 함께 설명하는지 확인.
- 1,280px 첫 화면·작업 목록·상세 검토와 작은 화면을 캡처하여 문구와 배치를 확인했다.

검증 중 외부 AI 호출은 실행하지 않았다. 실제 분석 연결은 역할을 분리해 기존 엔진을 호출하는 경계 검사와
기존 엔진 회귀 검사로 확인했다. 실제 파일로 유료 AI/OCR를 다시 돌리는 검증, 실제 사용자 사용성 평가,
완전한 오프라인 리플레이, 외부 배포용 로그인·권한 관리는 이번 변경 범위에 포함하지 않는다.
