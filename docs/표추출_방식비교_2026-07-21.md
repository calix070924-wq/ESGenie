# 표 추출 방식 비교 실험 결과 — L0 오염 근본 원인 검증

2026-07-21 · 스크립트: `scripts/table_extract_bakeoff.py` · 원문 덤프: `outputs/table_bakeoff/`

## 결론

**가설 확정**: 현행 `pymupdf page.get_text()`는 표의 레이블-값 연결을 **100% 소실**한다.
gpt-4.1-mini가 오매핑한 것이 아니라, **연결이 이미 사라진 텍스트를 받았다.**

| 방식 | LINKED | 판정 |
|---|---|---|
| **pymupdf_plain (현행)** | **0/9 (0%)** | 값은 모두 존재하나 어느 행의 값인지 알 수 없음 |
| **pymupdf_dict** | **8/9 (89%)** | ✅ 채택 권장 — 무료, 의존성 추가 없음 |
| pdfplumber | 4/9 (44%) | 표 인식 성공 시 정확하나 실패율 높음 |
| upstage_dp | 미측정 | 키 필요(사용자 실행) — dict가 89%면 불필요할 수 있음 |

채점 기준: `LINKED` = 레이블과 값이 **같은 줄**에 복원됨(어느 지표의 값인지 식별 가능),
`PRESENT` = 값은 있으나 레이블과 분리, `MISSING` = 값 자체 없음.

## 방식별 실제 출력 (LG화학 용수 표, p.41)

**현행 pymupdf_plain** — 레이블과 숫자가 완전히 분리:
```
용수 취수량
합계
ML
73,423
72,391
65,237
...
용수 재이용률
%
2.72
3.48
7.90
```
→ mini 입장에서 "2.72"가 재이용률인지 취수량인지 구분 불가. **오매핑은 필연.**

**pymupdf_dict** — y좌표로 행 재구성:
```
용수 취수량 | 합계 | ML | 73,423 | 72,391 | 65,237
원단위 취수량 | 5) | ML/백만 원 | 0.0036 | 0.0032 | 0.0030
Water Stress 지역 취수량 | 6) | ML | 50,603 | 48,778 | 47,436
용수 재이용률 | 7) | % | 2.72 | 3.48 | 7.90
```
→ 행 구조가 살아나며, 각주 마커 `5)`·`7)`도 **별도 셀로 분리**되어 값과 구분된다
(§삼성전기 각주 4.0 오염도 자동 해소).

## 남은 한계 1건 — 레이블이 별도 헤더 행인 표 (모비스 p.52)

```
TJ | 1,918 | 2,234 | 4,218 | 8,371 | ... | 9,075
```
행 선두가 단위(`TJ`)이고 지표명 `에너지 사용량`은 위쪽 헤더 행에 있다. dict 방식도
같은 줄에는 못 넣는다(PRESENT). → **헤더 행 상속** 후처리가 별도로 필요.

## 다중 컬럼 문제는 별개로 남는다

`재생에너지 사용·전환율 | 1) | % | 0.2 | 0.1 | 11.3 | ... | 22.7 | 12.9`
행은 복원됐지만 **12개 값 중 어느 것이 전사(합계)인지는 헤더 컬럼 라벨을 읽어야** 안다.
현재 실측 사례(35.0 오염)는 이 지점 — 행 복원만으로는 부족하고 **컬럼 헤더 매핑**이 필요.

## 권고 (수정 순서 재배치)

1. **[1위 수정] `_extract_text_pymupdf`를 dict 기반 행 복원으로 교체** — 0% → 89%.
   변경 범위가 함수 1개로 작고 무료. 각주 오염도 부수 해소.
2. **[1위 보강] 헤더 행 상속 + 컬럼 헤더 매핑** — 다중 컬럼·별도 헤더 표 대응.
   전사/합계 컬럼 우선 선택 규칙 포함.
3. **[3위] 매칭 게이트(단위·기간·가드 어휘)** — 위 둘을 통과한 뒤에도 남는 오배정의
   안전망. `작업문서/L0매칭_정합성_개편안_2026-07-21.md` 그대로 유효하되 **후순위**.
4. Upstage DP는 1·2로 부족한 경우에만 검토(비용 발생). dict 89%면 우선순위 낮음.
