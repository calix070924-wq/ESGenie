# 표 추출 구조 복원 결과 — L0 근본 수정

2026-07-23 · 브랜치: `feature/l0-table-structure` · 대상: `esgenie/ssot/ocr_router.py::_extract_text_pymupdf`

## 배경

정답셋 라벨링(`docs/라벨링_발견_수정목록_2026-07-19.md`) 결과 D1 오염 30건이 전부
`__ocr_unstructured__` 노드에서 나왔고, 그 경로는 `pymupdf page.get_text()` → 평탄화
텍스트 → gpt-4.1-mini다. bake-off 실험(`docs/표추출_방식비교_2026-07-21.md`)에서
현행 방식이 표의 레이블-값 연결을 **0/9 복원**함을 실측했다. 오매핑은 모델 잘못이
아니라 **입력에서 연결이 소실**됐기 때문이다.

## 수정 내용

`_extract_text_pymupdf`를 좌표 기반 행 복원으로 교체(시그니처·호출부 유지):

1. **작업1 — dict 행 복원**: `page.get_text("dict")`의 span을 y좌표 근접(±3pt, 상수
   `_ROW_Y_TOLERANCE_PT`)으로 같은 행에 묶고 x중심 순 정렬 후 ` | `로 조인.
   - **블록 단위**로 묶어 2단 편집 레이아웃(회사 소개 등)의 좌/우 단 혼선을 방지
     (전역 묶기 시 산문이 뒤섞이는 회귀 발견 → 블록 내부 묶기로 해소).
   - x중심 사용: 값이 우측정렬이라 x0(좌변) 기준은 컬럼 매칭이 한 칸씩 밀림(실측).
   - 폰트 큰 문서 대응 동적 임계값 `min(3.0, height*0.5)`.
   - 예외 시 `page.get_text()` 폴백(페이지 단위·전체 2단).
2. **작업2 — 헤더 행 상속** (`_inherit_label_rows`): 지표명이 값 행들 *사이*에 단독
   셀로 놓이는 rowspan 구조(모비스 p.52) 대응. 레이블 행을 인접 ±2행의 '단위 선두
   값 행'에 `[에너지 사용량]` 접두로 **양방향 상속**. 과잉 상속 방지: 대상은 단위 선두
   값 행으로 한정, 이미 지표명 있는 행 제외.
   - **주의**: 작업지시서는 "레이블이 위 헤더 행"으로 가정했으나 실제 PDF는 레이블이
     값 행 아래(중앙배치)라, 전방 상속만으론 실패 → 양방향으로 구현.
3. **작업3 — 컬럼 헤더 매핑** (`_attach_column_headers`): 법인별 다중 컬럼 표(모비스
   p.53) 대응. 헤더 행(합계·국내·해외·연도)의 x중심과 값의 x중심을 최근접 매칭해
   `12.9(합계)`처럼 컬럼 라벨 부착. 헤더 미인식·값>컬럼수·경계 밖이면 부착 생략
   (틀린 라벨보다 무라벨이 낫다는 원칙).

## 텍스트 길이 영향 (청크 크기 관계)

` | ` 구분자로 표 페이지 글자 수가 늘어난다(실측 모비스 60p):
- 페이지당 중앙값: 현행 1,749자 → 신규 1,764자 (+1%, 산문은 사실상 무변)
- 표 밀집 페이지 최대: 4,247자 → 4,889자 (+15%)

`_UNSTRUCTURED_CHUNK_CHARS = 4000`은 **유지**. `_split_text_chunks`가 줄 경계로 분할하고
표의 한 행은 한 줄이라 행이 중간에 잘리지 않는다. 상수를 올리면 300p 전체에서 호출당
토큰이 늘어 비용만 커지므로, 드문 초과 페이지를 위해 올릴 이유가 없다.

## 라이브 검증 (실행 필요 — 과금으로 미실행)

개선된 텍스트가 실제 노드 오염을 줄이는지는 파이프라인 실행이 필요하다. **미실행**
(라이브 LLM 호출·과금). 아래 커맨드와 기대 결과를 남긴다:

```bash
python3 scripts/verify_d1_fix.py --ticker 012330 --areas E
```

기대 결과 (모비스 E):
- **382,946**(누적 목표 감축량 → 실적 배출량 오매핑) 소멸 또는 감소
  — 이제 `[누적 온실가스 목표 감축량]` 레이블이 값과 같은 줄에 있어 mini가 '목표'로 식별.
- **1,005 TJ**(재생에너지 전환량 → 총 에너지 사용량 오매핑) 소멸 또는 감소
  — 9,075(합계) vs 1,005가 각각 다른 지표 행으로 분리됨.
- **3,910명**(임직원 수 → 용수 사용량 오매핑) 소멸 또는 감소
  — 행 복원으로 '명' 단위 값이 용수 행과 섞이지 않음.

주의: 이 스크립트는 전체 파이프라인(LLM)을 돌린다. `ESGENIE_FORCE_MOCK=1`이 아닌
실 키 환경에서만 의미가 있다.
