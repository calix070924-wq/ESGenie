# 독립 라벨링 표본 패키지 안내 (B용, 2026-10-06)

**상태: 표본 목록·서식·가이드 제공 완료 / 실제 라벨링 미착수.**
이 패키지에는 **정답이 들어 있지 않다.** A의 정답 라벨도, ESGenie의 응답도 없다.

표본 패키지: `data/eval/sample/bm_rba42_v1/`

| 파일 | 내용 |
|---|---|
| `sample.json` | 표본 목록과 추출 방법·씨값·대상 목록 지문 |
| `questions.csv` | 표본 문항의 정의 (문항 ID·구역·유형·단위 힌트·증빙 필요 여부·문항 본문) |
| `labels_blank.csv` | **빈 라벨 서식.** 20행의 `stage`·`qid`만 채워져 있고 나머지는 비어 있다 |

## 1. 왜 독립 라벨링인가

ESGenie와 일반 AI의 응답을 채점하려면 "맞는 답이 무엇인가"가 먼저 있어야 한다.
그 정답을 **A와 B가 서로 보지 않고 각자 매긴 뒤 비교**해야, 정답 자체가 한쪽 시스템의
출력에 맞춰 흔들리지 않는다.

그래서 다음을 지켜 주셨으면 한다.

- **B의 독립 라벨을 제출하기 전에 A의 정답 라벨과 ESGenie 응답을 열지 말아 주세요.**
  A도 B 제출 전에는 전달하지 않는다.
- 이 패키지(및 이 커밋)에는 정답이 포함되지 않도록 확인해 두었다. 다만
  **PR #72의 다른 문서에는 ESGenie 기대값이 일부 적혀 있다.** 라벨 제출 전에는
  `docs/validation/eval-scoring-20261006/README.md`와
  `docs/UI연결용_수치범위_출력계약_2026-10-05.md`를 열지 말아 주세요.
  (표본에 해당 문항이 들어가면 A가 따로 알린다. 현재 표본에는 포함되지 않았다.)
- 협의 전 A·B 라벨은 **각각 원본으로 보존**한다. 협의로 합친 라벨은 별도 파일로 둔다.
- 실제 결과를 보고 정답을 맞추는 일은 하지 않는다.

## 2. 표본 — 20행 (단계별 10문항)

- 양식: `rba42` (실사 응답서 48문항). **현대차 HMC 47문항은 섞지 않았다.**
- 단계: `initial`(초기 증빙), `followup`(보완 증빙 반영) 두 단계.
- **단계별 10문항 × 2단계 = 20행.** 전체 96행(48문항 × 2단계)의 **20.8%**다.
  (20% 이상이 되도록 올려 잡은 수다.)
- 단계마다 **같은 10문항**을 쓴다. 같은 문항의 보완 전후를 비교할 수 있게 한 것이다.

추출 방법(`sample.json`에 그대로 기록되어 있다):

1. 문항을 **유형(`qtype`)으로 층화**한다. 수치형 6문항, 예/아니오+증빙형 42문항.
2. 유형별 자리를 비율로 배분한다(내림 후 큰 나머지 순). → 수치형 1, 예/아니오형 9.
3. 유형 안에서 **문항 ID를 정렬한 뒤** `random.Random(씨값).sample`로 뽑는다.

- 씨값: **20261006**. 대상 목록 지문(`qid_list_sha256`)과 함께 기록해 두었다.
  같은 씨값·같은 양식이면 같은 표본이 재현된다.
- **시스템의 정오답·보류 여부를 보고 고르지 않았다.** 추출 스크립트는 응답 파일도
  정답 라벨도 입력으로 받지 않는다(`scripts/eval_label_sample.py`).

재현:

```bash
python scripts/eval_label_sample.py --seed 20261006 --out <다른_경로>
# data/eval/sample/bm_rba42_v1/ 과 같은 내용이 나온다
```

**정민 확인이 필요한 점:** 비율 배분이라 **수치형이 단계별 1문항**만 들어간다.
수치형은 값·단위·측정 경계 비교가 걸리는 가장 중요한 부분인데 6문항밖에 없어, 비율대로
뽑으면 거의 안 들어온다. 선택지는 (a) 현재대로 비율 배분, (b) 수치형 6문항 전수 +
예/아니오형 표본, (c) `--per-stage`를 올려 표본을 키우는 것이다. **A가 임의로 정하지
않았다.** 결정되면 씨값과 함께 다시 뽑는다.

## 3. 라벨 채우는 방법

`labels_blank.csv`의 각 행을 채운다. 열 11개의 뜻은 다음과 같다.

| 열 | 채우는 값 |
|---|---|
| `stage` | 이미 채워져 있다. 바꾸지 않는다 |
| `qid` | 이미 채워져 있다. 바꾸지 않는다 |
| `expected_decision` | **`answer`** (증빙으로 답할 수 있다) / **`hold`** (답할 수 없다) / **`na`** (해당 없음) |
| `hold_reason` | `hold`일 때만, 아래 5개 중 하나. `hold`가 아니면 **비워 둔다** |
| `expected_value` | `answer`일 때만. `hold`·`na`면 **비워 둔다** |
| `expected_unit` | 값의 단위 (`톤`, `kg`, `%`, `tCO2eq`, `TJ`). 단위가 없으면 비운다 |
| `tolerance` | 수치 허용 오차(절대값). 비우면 0 — 정확히 같아야 한다 |
| `expected_sources` | `파일명#페이지`를 `;`로 구분. **페이지는 1부터 시작**(PDF 뷰어에 보이는 번호) |
| `boundary_note` | 기간·사업장·측정 대상·분모 등 경계에 대한 메모 |
| `labeler` | 본인 식별자 |
| `note` | 판단 근거, 애매했던 점 |

`hold_reason`에 쓸 수 있는 값 5개:

| 값 | 뜻 |
|---|---|
| `no_evidence` | 증빙에 해당 내용이 없다 |
| `scope_unconfirmed` | 범위(기간·사업장 등)를 확인할 수 없다 |
| `not_comparable` | 증빙이 있으나 문항과 비교할 수 없다 |
| `mismatch` | 증빙끼리 또는 증빙과 문항이 어긋난다 |
| `needs_human_text` | 사람의 서술 판단이 필요하다 |

주의할 점:

- **값이 `0`인 것과 값이 없는 것은 다르다.** 증빙에 0으로 적혀 있으면
  `answer` + `expected_value=0`이다. `hold`가 아니다.
- **단위를 환산하지 말아 주세요.** 증빙에 적힌 단위를 그대로 쓴다(`톤`을 `t`로 바꾸지
  않는다). 채점기는 단위가 다르면 의미가 다르다고 보고 불일치로 남긴다.
- **페이지를 모르면 비워 둔다.** 추정해서 1페이지라고 적지 않는다.
- 애매하면 `note`에 애매한 이유를 적는다. 비워 두거나 추측으로 채우지 않는다.
- 빈 서식을 그대로 채점기에 넣으면 거부된다(`expected_decision`이 비어 있어 `LabelError`).
  빈 서식이 정답으로 오해되어 쓰이지 않도록 기본값을 넣지 않았다.

## 4. 라벨링에 필요한 원본 증빙 — 아직 전달되지 않았다

**표본 목록·문항 정의·서식은 원본 없이도 만들 수 있지만, 실제 라벨링에는 해당 단계의
원본 증빙이 필요하다.** 현재 A도 이 자료를 받지 못했다.

| 단계 | 필요한 자료 | 현재 |
|---|---|---|
| `initial` | 촬영 증빙 12건 | **미확보** |
| `followup` | 촬영 증빙 12건 + 보완 증빙 1건 = **13건** | **미확보** |

- `followup`은 초기 12건에 보완 1건을 더한 13건을 보고 매긴다. 보완 자료를 뺀 채
  `followup`을 매기면 단계 구분이 무의미해진다.
- `00_` 안내·요청서 PDF는 원본 검토에 참고할 수 있으나 **제품에 업로드할 증빙에는
  포함하지 않는다.**
- 자료가 오는 즉시 라벨링을 시작할 수 있도록 표본과 서식을 먼저 보내는 것이다.

**B에게 먼저 드릴 수 있는 것:** 자료가 확보되면 `followup` 10행부터 드린다.
다만 이 시점에 **두 단계 독립 검토가 끝난 것으로 보지 않는다.** `initial` 10행은
그다음이다. B의 `followup` 결과는 `followup` 라벨과만 비교한다(단계를 섞어 비교하지
않는다). A가 맡은 `initial` 범위는 그대로다.

## 5. 제출과 그다음

1. B가 `labels_blank.csv`를 채워 `labels_B_<단계>_<날짜>.csv`로 제출.
2. A가 `labels_A_<단계>_<날짜>.csv`를 같은 시점에 공개(그 전까지는 비공개).
3. 두 라벨을 행별로 비교 → 불일치 행만 사람이 함께 검토.
4. 합의 라벨을 `data/eval/labels/`에 **채점보다 먼저** 커밋. 커밋 SHA를 기록.
5. 그다음에 실제 채점을 돌린다.

3번 이전에 채점 결과를 보지 않는다. 결과를 보고 라벨을 고치면 비교가 성립하지 않는다.
