## 문제와 변경 후 동작

공시 자료에서 읽은 수치와 조항이 원장, 검색, 생성, 검증을 거치는 동안 출처·연도·범위가 충분히 전달되지 않거나, 이미 계산한 검증 사유가 최종 화면과 보고서에 설명되지 않았다. 예를 들어 전체 에너지 후보와 전력 후보가 함께 있으면 전력 내부의 합계가 전체 에너지 대표값으로 선택될 수 있었다. OCR이 일부 실패하거나 시연 결과를 반환해도 업로드가 결과에 반영됐다는 문구만 표시되는 경로도 있었다.

이번 변경은 원문 근거와 처리 상태를 보존하고, 기존 검사에서 무엇을 확인해야 하는지 사용자에게 설명한다. 추가 검색은 항목별 근거를 보강하며 기존 원장 수치를 바꾸지 않는다. 최종 결과에는 확인할 사실 또는 문장, 확인 이유, 다음 행동, 연결된 출처가 함께 나타난다. 자료에 실제로 기록된 위반·추세와 작성 문장의 검증 문제, 입력 자료의 불확실성은 서로 다른 사유로 기록한다.

성공 기준은 다음과 같다.

- 실제 PDF 페이지와 원문 인용을 확보한 경우 OCR부터 결과물까지 보존한다. 확보하지 못한 정보는 미확인으로 표시한다.
- 실적·목표, 전체·부분 범위, 확정·추정 연도 차이를 대표값 선택에 반영한다.
- 기존 검색 게이트를 통과한 추가 근거만 사용하고, 검색 성공을 문제 발견이나 수치 확정으로 해석하지 않는다.
- 기존 D1/D2/D3/D5의 검사 사유와 판단 보류를 결과에서 확인할 수 있게 한다.
- OCR·보고서 생성 실패, 일부 처리, 시연 결과를 성공과 구분한다.
- 기존 점수 산식·임계값·가중치와 원장 중심의 검증 계약을 유지한다.

## OCR: 문맥·출처·실패 상태 보존

### 페이지와 표 문맥

`esgenie/ssot/ocr_router.py`는 디지털 PDF를 실제 페이지별로 읽으며 빈 페이지도 위치 정보에 남긴다. 큰 페이지는 기존 4,000자 한도 안에서 나눈다. 긴 표의 다음 청크에는 머리글 문맥만 반복하고 데이터 행은 반복 복제하지 않는다. `page`, `line_start`, `line_end`, `context_repeated`, 원문 `body`로 분할 근거를 남긴다. 긴 산문도 안전한 경계에서 나누고 숫자 토큰 중간을 자르지 않는다. 한도를 넘는 단일 숫자 토큰은 조용히 훼손하지 않고 실패로 기록한다.

라벨 상속은 값 셀보다 왼쪽에 있는 가장 가까운 라벨을 사용한다. 서로 다른 라벨이 같은 거리이면 추측하지 않는다. 연도 머리글은 `2030 목표`, `2024 실적`, 계획·전망 등의 성격을 보존한다. 연도 그룹이 불균등하거나 대응이 모호하면 기존의 보수적인 미부착 동작을 유지한다.

`prompts.py`의 추출 프롬프트는 실제 입력에 맞게 원문 텍스트 추출로 정정했다. 수치와 조항에 페이지·인용을 요청하고, 실적과 목표를 분리하며, 계산·보정과 반복 머리글의 재추출을 금지한다. 위반·벌금·재해·교육 이수율 저하·산정기준 변경 및 비교 한계도 생략하지 않도록 명시한다. 이 프롬프트 지시 자체를 추출 성공률의 측정 결과로 해석하지 않는다.

### 페이지·인용의 신뢰 기준

- `ExtractedMetric`, `ExtractedClause`, `EvidenceNode`, `TextNode`에 선택적 `quote`, `page_source`를 추가했다. 기존 데이터는 빈 기본값으로 읽을 수 있다.
- 모델이 주장한 페이지 번호를 신뢰해서 붙이지 않는다. 실제 호출 청크에서 확인한 페이지를 사용한다.
- 인용은 공백 정규화 후 해당 청크 본문에서 실제로 일치할 때만 저장한다. 반복 문맥 머리글을 원문 데이터 인용으로 승격하지 않는다.
- 실제 페이지 청크에서 나온 요약은 페이지를 유지할 수 있지만, 인용이 없는 요약을 원문 인용으로 표시하지 않는다.
- 스캔 문서의 DP 토큰은 실제 페이지 메타데이터가 모두 유효할 때 페이지별로 사용한다. 그렇지 않으면 출처 페이지를 미확인으로 남긴다.
- 부가 조항 보강도 페이지별로 수행하며 일치한 원문 인용을 저장한다.
- 완전 중복 제거는 같은 실제 페이지와 같은 원문 인용이 확인된 동일 레코드에 한정한다. 페이지·인용이 미확인인 근거를 임의로 합쳐 반복 관측을 없애지 않는다.

### 실패와 캐시

엄격 모드에서는 키 부재, 텍스트 추출 실패, API/mock 폴백, 잘못된 JSON·스키마·레코드를 예외로 전달한다. 일반 모드는 유효한 부분 결과를 보존하면서 `complete`, `partial`, `failed`, `mock` 및 `chunk_failures`를 남긴다. 수치 누락·비유한 수·불리언을 임의의 0으로 만들지 않으며 실제 0은 보존한다.

### 수치를 보고하지 못한 표 행 (2026-09-20 수정, 라이브 실측으로 발견)

TPM 한도를 올린 뒤 처음으로 실제 전체 PDF의 엄격 모드 OCR을 돌리자 **176청크 중 16번째에서
전체 처리가 중단**됐다. 원인은 모델이 그래픽 안에 있는 값을 읽지 못해 `value: null`로
정직하게 답한 표 행 3개였다(p.16 “젠더 다양성(여성 비율)”, “국적 다양성(한국 외 국적 비율)”,
“이사회 구성원 연령 분포”). 기존 코드는 이를 스키마 위반과 같은 `invalid_records`로 묶어
엄격 모드에서 예외로 올렸기 때문에, **라벨만 있는 표 행 한 줄이 문서 전체를 실패시켜
엄격 모드로는 이 보고서를 끝까지 처리할 수 없었다.** 사용자가 보고한 “잘 구동이 안 되고
버그가 나는” 문제의 실체다.

수정은 레코드 문제를 두 갈래로 나눈다. 스키마 위반·비유한 수·불리언·본문 없음은 여전히
`fatal`이며 엄격 모드 중단 계약을 그대로 유지한다. 라벨은 읽혔으나 값이 보고되지 않은 행은
`fatal: False`로 표시해 `router_meta["unvalued_records"]`와 `unvalued_record_count`에 남기고
해당 행만 버린다. **0으로 채우지 않고 추정값을 만들지 않으며 실제 0과 구분한다.** 추출
상태를 `partial`이나 `failed`로 바꾸지도 않는다. 대신 확인 목록에 “값을 읽지 못한 항목”으로
드러내므로 문서를 전부 읽었다는 인상을 주지 않는다.

청크별 성공·실패·캐시 적중·모델·공급자·mock 여부는 `chunk_runs`에 기록한다. 잘못된 응답과 시연 응답은 실제 OCR 캐시를 채우지 않는다. 캐시 적중에도 현행 결정적 후처리와 스키마 검사를 수행하며 입력·프롬프트 변경은 새 캐시 키를 사용한다. 페이지·인용 누락 수, 전체 페이지 수, 텍스트가 없는 페이지도 상태 메타데이터로 남긴다.

## 원장: 지표 범위와 연도에 맞는 대표값 선택

`esgenie/ssot/node_select.py`에서 E-4-1 전력·전기 사용량/소비량은 전체 에너지의 구성요소로 분류한다. 전력 내부의 합계라는 문구만으로 전체 에너지 `total`이 되지 않는다. 일반적인 `에너지 사용량`처럼 전체 범위가 명시되지 않은 라벨은 `unknown`을 유지한다.

기본 선택 순서는 기존 파생·충돌 배제 → 단위 호환 → 역할 → 세부 분해 범위 → 확정 연도 → 연도 근접 → 지표 계열 → 집계 → 단위 표기 → 같은 연도 값 최빈 → 최신·신뢰도·ID다. 단, E-6-1의 폐기물 발생량·처리량과 E-6-2의 전체 폐기물·자재 재활용률은 의미가 다른 지표이므로, 두 코드의 기존 지표 계열 우선순위는 범위 판정 뒤이면서 연도보다 먼저 적용한다. 전체·부분 범위와 세부 분해는 연도보다 먼저 보므로 최신 국내 부분값이나 PPA 내역이 전사 총량을 대신하지 않는다. 같은 범위에서는 최신 환산 가능 MWh가 과거 TJ보다 우선한다. 같은 범위·연도에서는 기존 지역 기반 산정법 선호를 유지한다. Scope 1+2 결합 라벨도 국내·별도 제한이 있으면 부분 범위를 보존한다.

전력만 있어도 값을 버리지 않고 `partial_value`로 전달한다. 원본의 단순 `에너지 사용량` 라벨로 올바른 숫자를 선택해도 전체 범위가 불명확하면 경고를 임의 해소하지 않는다. 호환 가능한 물리량이 있는 경우 `%`처럼 비교 불가 단위의 후보가 총량 문구만으로 대표가 되지 않는다. 환산식·검증 게이트는 완화하지 않았다.

실제 PDF에서 확인한 두 후보를 최소 입력으로 구성해 `extract_with_ssot → finalize_ledger → D1`을 비교했다. 원본은 현대모비스 2025 보고서이며 SHA-256은 `b7845ec3e1f9cf0087b3c9140c7f531cb9fc4ce6bfab80188f6f6c93fe75e8e0`이다.

## RAG: 추가 검색 범위와 생성·검증 근거 일치

`embeddings.py`의 `split_documents()`는 **추가 검색용 별도 인덱스에만** 사용한다. 현재 로컬 모델의 tokenizer와 `max_seq_length`를 읽고 특수 토큰을 포함한 입력 한도를 직접 측정한다. 모든 문자 구간을 덮으며 문장·줄·단어 경계를 선호하고 최대 48자 중첩을 둔다. `parent_chunk_id`, `char_start`, `char_end`와 원본 메타데이터를 보존한다. 이 위치는 부모 검색 문서 안의 문자 위치이며 PDF 좌표가 아니다. tokenizer가 없는 backend는 원래 문서를 유지하므로 모든 backend의 잘림을 해결한다고 주장하지 않는다.

`layer2_rag.py`의 `retrieve_for_items()`는 기존 회사 검색 자료를 복사해 별도 vector/BM25 인덱스를 만든다. 프로파일의 항목명·설명·기존 동의어 첫 두 개로 자동 질의를 만들고 요청한 영역의 항목만 검색한다. 회사명이나 정답을 본 뒤 만든 문구는 질의에 넣지 않는다.

검색은 기본 k=3과 기존 cascade·gate를 유지한다. 그룹의 top 1이 ACCEPT여도 뒤따르는 무관한 hit를 함께 허용하지 않도록 각 hit를 기존 `evaluate_retrieval`로 다시 검사한다. `ItemRetrievalResult`에 질의, 단계별 판단, hit별 판단과 채택한 청크 ID를 기록한다. 지원하지 않는 영역은 `HUMAN/R0_unsupported_area`로 남긴다. 원래 corpus의 문서·벡터·메타데이터·검색 결과는 바꾸지 않는다.

`RAGContext.as_context_text()`의 기본값을 선정된 근거 전체 전달로 바꾸어, 생성기에는 top 2만 보이고 검증기에는 전체가 보이던 차이를 줄였다. 생성 프롬프트는 공시 지표 수치를 원장에서만 쓰고, 검색 근거는 활동·정책 설명에 사용하도록 문구를 일치시켰다. 추가 검색에서 숫자가 보인다는 이유로 원장 밖의 지표 수치를 허용하지 않는다. SSOT 검색 문서에도 `page`, `quote`, `page_source`를 전달하며 페이지 미확인은 `p.None` 대신 미확인으로 표시한다.

현재 저장된 과거 OCR 코퍼스에 자동 질의를 재생한 측정은 원문 1,080문서 → 1,486조각, 최대 128토큰, 원본 문자 전부 보존, 원래 인덱스 불변이었다. 전체 카탈로그 61항목 중 32항목에서 49개 hit가 채택됐다. 실제 E/S/G 항목은 56개이며 실행에서는 요청 프로파일·영역으로 제한한다. 이 수치는 근거 게이트의 채택 결과이지 문제 발견률이 아니다.

### ⚠️ 게이트 판정 의미 변경 (2026-09-20, 리뷰어가 반드시 확인할 부분)

위 재생에서 환경 위반 설명 조항이 계속 회수되지 않던 원인을 두 단계로 진단했다.

1. **tier 판정이 top 1 문서만 본다.** 실제 위반 경위를 적은 조항이 후보 목록에 들어와도, 무관한
   top 1(예: “안건: 산업안전보건법 …”) 때문에 그 tier 전체가 escalate되고 **그 tier의 유효 근거가
   함께 버려졌다.** 다음 tier의 다중 질의 RRF는 여러 변형에 두루 걸리는 일반 정책 문구를 앞세웠다.
   → `CascadeResult.tier_hits`에 각 tier가 이미 계산해 둔 답안 묶음을 중복 제거해 기록만 해 둔다.
   `decision`과 최종 `hits`는 바꾸지 않는다. **k를 키우지 않았다.**
2. **R1은 묶음 1위 전용 점수 검사다.** 후보에 들어온 뒤에도 `R1_low_top1_score`로 탈락했다
   (tier 1 하이브리드 3위 점수 0.4707 < `RAG_R1_MIN` 0.54). 점수는 tier마다 정규화 방식이 다르므로
   (tier 0 min-max, tier 1 가중합, tier 2 RRF/최댓값) **2위 이하 후보는 내용이 정확해도 구조적으로
   이 임계값을 넘을 수 없다.** 척도 범주 오류다.
   → `layer2_rag._SCALE_ONLY_HARD_FAILS = {"R1_low_top1_score"}`를 두고, **2위 이하 후보에만**
   이 사유를 제외한다. 1위 후보는 기존 규칙 전부를 그대로 적용한다.

**바꾸지 않은 것:** `RAG_R1_MIN`·`RAG_R2_MIN`·`RAG_R4_MIN`·`RAG_MAX_TIER` 값, 영역 검색 판정,
게이트 파일 자체, 채택 수 상한(기존 k), 묶음 단위 점수 요건(`decision`이 계속 강제한다).
영역 키워드·질의 키워드·수치 근거 등 **내용 게이트는 2위 이하 후보에도 전부 적용된다.**

**실측 결과:** 항목 61 / 채택 항목 32는 그대로이고 채택 hit는 49 → 69로 늘었다. E-8-1은
`012330_txt_0148`(“2024년 기준 국내(별도)에서 1건의 규제 위반”)을 회수했다. 원본 코퍼스의
텍스트·메타데이터·벡터·기존 검색 결과는 불변임을 실행 중 단정으로 확인했다.
`tests/test_top1_acceptance_does_not_accept_an_unrelated_tail`은 그대로 통과한다 — 그 꼬리는
점수가 아니라 내용(R3)으로 탈락하므로 원래 의도가 살아 있다.

교육 감소 조항 `txt_0558`(컴플라이언스·부패방지 교육 이수율)은 **항목별 추가 검색으로는
회수할 수 없다.** K-ESG 카탈로그의 G 항목 17개를 전부 확인했으나 해당 항목이 없고, 항목을
새로 추가하면 점수 프로파일에 영향이 가기 때문이다. 이 조항은 “보류”로 이름을 바꾸지 않고
**미해결(카탈로그 항목 부재로 이 경로로는 불가)** 로 분류한다. 위 수치를 문제 발견률이나
최신 전체 OCR 코퍼스·새 생성 결과의 평가로 확대하지 않는다.

## 확인 목록: 무엇을 확인해야 하는지 설명

신규 `esgenie/source_review.py`는 원장·증거 그래프·기존 검증 결과를 읽어 확인 목록을 만든다. `ReviewFinding`에는 범주, 제목, 관측 사실 또는 대상 문장, 이유, 다음 행동, 영역·항목 코드, 근거를 저장한다. `check_reason`에는 기존 기계 사유 코드를, `check_result`에는 기존 축의 점수·사유·판단 보류·근거 ID를 보존한다. 새 LLM 판정을 호출하거나 위험 점수를 다시 계산하지 않는다.

### 원문 관측과 자료 품질

- 양수의 위반 건수, 비교 가능한 교육 이수·참여율 하락, 재해 발생 건수 상승을 관측 사실로 설명한다. 실제 0건, 교육 상승, 미이수율 하락, 무재해·예방·교육·조치·점검·훈련 활동 증가를 같은 부정 추세로 분류하지 않는다.
- 같은 자료 파일·지표명·단위·역할 범위와 확정 연도가 있는 경우에만 시계열을 비교한다. 서로 다른 범위·파일, 목표, 연도 미상, 같은 연도의 충돌값을 합치지 않는다. 단순 변화로 기업 성과 악화나 위반의 인과관계를 확정하지 않는다.
- 항목명·힌트 끝의 연도가 각 노드의 `period`와 정확히 일치하는 단독 꼬리일 때만 비교용 이름에서 제거한다. 같은 교육 지표가 연도 꼬리 때문에 서로 다른 시계열로 갈라지는 문제를 고치며 지역·집계 범위와 원본 값·문자열은 유지한다.
- 원장 경고와 `ResolvedFact.flags`를 복사해 합친다. 연도 추정, 부분값·부분 집계, 대표값 없음, 단위 불일치·의심을 원래 불확실성 그대로 설명한다. 명시적 `ResolvedFact=None`과 구버전 결과도 보수적으로 처리한다.
- 대표값 품질 경고는 실제 K-ESG 원장·선택 프로필과 추가 공시 항목에만 표시한다. 자유 형식 목표값의 정당한 대표값 제외를 사용자 보완 과제로 잘못 표시하지 않는다. 과거 재생의 과도한 경고 157개를 화면 목록에서 제외해 전체 191→34건으로 정리했으며 원본 그래프·원장 내부 flags는 보존했다. 원문 사실 2건과 검색 근거 미확보 29건은 그대로다.
- OCR 청크 생성 전후의 실패 사유를 보존한다. `mock`으로 표시된 파일은 실제 위반·추세·추가 검색 근거에서 제외하고 시연 경고를 남긴다. `partial`인 파일에서 실제로 읽은 유효 관측은 유지한다.
- **값을 읽지 못한 항목**(2026-09-20 추가): 위의 `unvalued_records`를 자료마다 한 건으로 묶어 개수와 라벨 앞 5개만 보여 준다. 화면이 길어지지 않도록 묶고, 그림·빈 칸에 값이 있을 수 있다는 사유와 원본 대조 행동을 함께 적는다. **미공시 확정으로 표시하지 않으며 0으로 채우지 않는다.**

### 직접 근거와 주변 설명의 구분 (2026-09-20 추가)

이전에는 항목별 추가 검색이 붙인 자료가 원장 근거와 똑같이 “출처”로 표시됐다. 과거 재생에서
E-8-1 “공시된 위반·침해 현황 확인”의 설명 근거가 **일반 환경 법규 준수 방침 문구(`TXT_0144`)
하나뿐이었는데도 위반 사건의 직접 증거처럼 읽혔다.**

`ReviewEvidence.role`을 추가해 `direct`(직접 근거)와 `context`(주변 설명)를 구분한다. 판정은
새 LLM 호출이나 새 의미 판단 없이 결정적으로 한다 — **이미 확정된 확인 사항의 수치·연도가
그 원문에 모두 그대로 적혀 있을 때만** `direct`이고, 나머지는 `context`다. 수치가 없는 확인
사항(작성 문장·검색 누락 등)의 추가 근거는 보수적으로 `context`로 둔다. `review_markdown()`은
`direct`를 `**출처:**`, `context`를 `**참고(주변 설명):**`으로 렌더링한다. 근거 자체를 버리지
않으며 `_finding()`의 ID 계산에는 역할을 넣지 않으므로 기존 확인 사항 ID는 바뀌지 않는다.

실측(과거 재생): E-8-1의 근거가 `원장 노드(direct) + TXT_0144(context) + TXT_0148(direct)`가 됐다.
정책 문구는 참고로 내려가고, 실제 경위를 적은 조항이 직접 근거로 올라온다. 전체 목록은 34건
그대로이고 근거 행만 11 → 15로 늘었다(direct 10 / context 5).

### 작성 문장의 기존 검사

- D1은 대표 문장만 읽지 않고 기존 `RiskVector.numeric_evaluation`의 전체 문장 기록을 사용한다. 수치 불일치는 작성값·단위와 근거값·단위를 함께 표시한다. 근거 없음, 단위 비교 불가, 지표 연결 모호, 부적합 숫자도 각각의 이유와 행동으로 설명한다.
- `layer4_verify.py`는 이미 수행한 모든 문장의 D2/D3/D5 결과를 `sentence_axis_reviews`에 남긴다. 기존 최악 문장 선택과 점수 집계에는 참여하지 않는 설명용 기록이다.
- D2의 모호·과장 표현, D3의 근거와 의미 대조, D5의 증감 방향 확인 중 기존 기준에 해당하거나 판단을 보류한 결과를 설명한다. D3의 낮은 유사도만으로 사실 오류를 확정하지 않는다. 문장별 기록이 없는 구버전은 저장된 대표 결과만 설명하며 대상 문장 위치를 특정하지 않는다.
- 검색 청크의 실제 ID를 검증에 전달해 근거 연결을 보존한다. 과거 `kesg_i` 방식의 결과는 구버전일 때만 해당 순서로 대응한다. 근거 ID가 해석되지 않으면 출처를 만들어내지 않고 원래 검사 결과에 남긴다.

인용이 없으면 “추출 내용(원문 인용 미확인)”, 페이지가 없으면 “페이지 미확인”으로 표시한다. Markdown·HTML 문자는 표시 시 escape하고 저장 원문은 바꾸지 않는다. 서로 다른 영역·사유·파일·페이지의 경고가 중복 제거로 사라지지 않도록 ID에 구분 정보를 넣는다. 추가 검색은 이미 있는 확인 사항에 채택된 실제 근거를 붙이며 검색 성공만으로 새로운 문제를 만들지 않는다. 검색 실패도 미공시 확정으로 설명하지 않는다.

## 화면·감사 기록·보고서·실패 표시

`PipelineOutput`에 `item_retrievals`, `review_findings`, `report_export`를 추가한다. 확인 목록을 만든 뒤 영역별 감사 기록에 목록과 검색 결과를 붙이고 저장한다. 구버전·시험 대역의 `trace=None`은 안전하게 건너뛴다. 저장 또는 출력 요청 시 `source_review.json`에 확인 목록, 항목별 검색 판단, OCR 상태, 보고서 생성 상태를 함께 남긴다.

`layer6_report.py`는 동일한 `review_markdown()`으로 결정적 “확인 필요 사항” 블록을 만들고 `ReportDoc.meta`에도 구조화된 목록을 남긴다. 화면의 진단 결과는 현재 영역과 공통 확인 사항을 같은 렌더러로 표시한다.

업로드 요약은 접수 건수를 성공 건수처럼 표현하지 않고 읽기 완료·일부 처리·실패·시연·미확인을 구분한다. 자가진단 응답 파일은 실제 OCR 증빙과 구분한다. 파일별로 실패 사유, 확인할 페이지, 대체 방식 사용, 텍스트가 없는 페이지를 안내하고 `app.py`의 문서 상태 경고도 같은 경로에 연결한다. 텍스트가 없는 페이지를 빈 페이지나 이미지 페이지 중 하나로 단정하지 않는다.

보고서 생성은 조립·Markdown 저장·PDF 생성 단계를 구분한다. `report_export`는 `not_requested`, `unavailable`, `complete`, `partial`, `failed`와 실패 단계·예외 종류·상세 사유를 남긴다. PDF만 실패한 경우 Markdown 결과는 보존하고 화면에 사유를 안내한다. 엄격 모드는 실패를 다시 전달한다. 화면의 조립 결과 캐시에는 분석 결과 객체를 포함하여 같은 회사·영역의 새 결과가 이전 보고서를 재사용하지 않게 한다.

미리보기 생성 결과는 `report_export.preview`에 별도로 남겨 이미 발생한 저장 실패를 덮지 않는다. 보고서 저장 실패 뒤 같은 디렉터리의 확인 목록 저장도 실패하면 원래 보고서 오류와 추가 저장 오류를 함께 보존한다. 정형 문서의 `pymupdf+regex` 대체 경로는 실제 추출 메타데이터로 감지해 경고하며, 정상적인 비정형 PDF 텍스트 읽기를 같은 실패로 표시하지 않는다.

`exporters/report_pdf.py`는 확인 목록에서 escape한 원문 기호를 PDF 인라인 변환 전에 보호했다가 복원한다. 원문 별표·밑줄·소수점·HTML 문자·파일명에 불필요한 역슬래시가 남거나 원문 기호가 강조 구문으로 해석되는 문제를 고친다. 기존 의도된 강조·코드 표기와 실제 경로의 역슬래시는 유지한다.

## Azure 접속·재시도와 실제 실행 한계

로컬 Azure 접속 대상을 복구했고 동일한 `gpt-4.1-mini`를 사용한다. endpoint·key·`.env` 내용은 이 문서와 PR에 포함하지 않는다. 접속 설정 복구와 모델 배포·용량 변경은 구분하며, 클라우드 리소스 변경은 수행하지 않았다.

뒤 2건은 **검색·연결 재현율의 남은 한계**이며, 문장에 지표명이 없는 상태에서 코드를
억지로 붙이면 잘못된 대조가 생기므로 게이트를 느슨하게 바꾸지 않았다.

버그 수정의 전·후 효과는 재현 가능하게 증명했다. 인계 기록의 패치에서 `ocr_router.py`의
인계 버전을 복원해(해시 대조) 새 회귀 테스트를 실행하면 라이브와 **동일한 오류로 2건 실패**하고,
최종 버전을 복원하면(해시 대조) 통과한다. 이전 429 기록은 아래 문장으로 보존한다.

라이브 전체 OCR 시도에서는 첫 2청크 성공 후 429가 발생했고, 핵심 7쪽 별도 시도도 첫 청크에서 429가 발생했다. 확인 당시 배포 한도는 1 RPM/1,000 TPM이었다. 큰 입력 요청은 대기 시간을 늘리는 것만으로 처리 가능해진다고 보장할 수 없다. **이 문단은 TPM 조정 이전의 기록이다.** 30,000 TPM 조정 이후 전체 PDF OCR과 그 결과의 생성·검증·출력은 위 표대로 완주했고, 429는 0회였다. 다만 완주는 **처리 성공**이며 추출·작성 내용의 정확도 전수 검증이 아니다. 이 부분을 코드 회귀 테스트의 통과로 대체하지 않는다.

사용자는 사람이 잠시 처리하면 비용상 유리한 설정을 직접 처리할 수 있다고 허용했다. 이 배포의 수동 작업은 Azure AI Foundry의 모델 배포 목록에서 **현재 사용하는 `gpt-4.1-mini` → 편집 → 분당 토큰 제한(TPM)을 1,000에서 30,000으로 조정**하는 것이다. UI가 천 토큰 단위 용량을 표시하면 제안값은 30이다. 모델·버전·리전은 그대로 둔다. 이는 검증용 초기 제안값이며 전 문서 처리를 보장하는 값은 아니다. 분당 한도는 총사용액 상한이 아니며 실제 호출의 입력·출력 토큰에 따른 비용은 계속 발생한다. 읽기 전용 조회에서 사용 가능한 할당량을 확인했지만 실제 한도 변경과 추가 라이브 호출은 하지 않았다.

조각 자체를 인덱스 문서로 넣자 **E 영역이 ACCEPT → HUMAN으로 뒤집혔다**(tier 0 → 2).

1. tier 0은 BM25 단독이고 BM25에는 토큰 한도가 없다 — 멀쩡했던 tier 0 순위가 흔들렸다.
2. 게이트의 수치 근거 확인(`R3_numeric_evidence_missing`)은 상위 1건 본문을 본다. 조각은
   조항 앞 128토큰뿐이라 뒤에 있던 수치가 사라졌다. 근거가 없어진 게 아니라 게이트가
   보는 단위가 줄어든 것이다.

"더 보수적이 됐다"로 넘기지 않고 설계를 바꿨다.

### ⚠️ 이 측정에서 **우리 수정의 결함**을 찾았다 — 법·정관 조항 번호를 조(兆)로 읽었다

1·2차 측정은 "수정본이 매칭하는 청크"만 근거로 골랐다. 그 편향을 없애고(두 버전 중 어느
쪽이든 매칭하는 청크 사용) 다시 돌리니 판정이 뒤집히는 사례가 나왔고, 원인은 우리 수정이었다.
`제25조`·`상법 제388조`·`정관 제29조`·`제6조(…)`의 `조`를 자릿수 兆로 읽어 **25조 원**
(2.5×10¹³)으로 해석했다. 실데이터 빈도: 조항문 647건 중 **9건**, 최종 보고서 문장 484건 중
**12건**. 조항 번호는 근거 청크에 같은 번호가 그대로 없으면 절대 매칭되지 않는다. G2는
hard_fail이므로 보고서 경로에서는 오탐 확인 항목, **드래프터 경로에서는 정상 초안 폐기**다.
응답서 문항·조항 텍스트는 조항 번호를 많이 쓰므로 여기서 더 자주 터질 수 있었다.

수정: 숫자와 자릿수 글자가 **붙어 있어야** 한 금액으로 보고(`3 조`·`114\n조` 제외, 조각
사이 개행 불허), `조`는 뒤에 통화 단위가 붙거나(`1조 원`) 더 작은 자릿수가 이어질 때
(`1조5000억`)만 자릿수로 읽는다. `제`가 앞에 붙으면 조항 번호로 본다. 둘 다 아니면
**종전 동작으로 되돌린다** — 조항 번호를 25조 원으로 읽는 쪽이 금액을 놓치는 쪽보다 나쁘다.
`억`·`만`은 손대지 않았다. **게이트 판정 기준·임계값·점수식은 바꾸지 않았다.**
테스트 4건 추가. 전체 회귀 **1,525 passed / 12 skipped / 0 failed**.
수정 후 토큰화가 갈리는 건수: 보고서 문장 13 → **1**, 조항문 37 → **20**, 지표 인용 65 → **54**.

`교육훈련비는 211억 1,600만 원으로…` 문장의 실제 근거 청크는 `[S-2-4] 21116.0백만 원`
하나뿐이고 **단위가 축약되어 있다.** 생성 단계가 인덱싱하는 청크 4,317건 전체에 이 금액을

- 페이지를 보존하는 분할은 실제 예시에서 92→176청크로 늘었다. 캐시가 없는 OCR의 호출 수와 반복 머리글 입력 토큰이 증가할 수 있다. 청크 수를 실제 청구 호출 수로 그대로 등치하지 않으며, 측정 전 비용 금액이나 절감률을 제시하지 않는다.
- 항목별 추가 검색은 별도 vector/BM25 인덱스 1회를 만들고 요청 프로파일·영역의 항목 수만큼 로컬 검색한다. 기존 cascade는 최대 tier 2까지 세 단계, 질의 변형은 최대 8개다. CPU·메모리·지연이 증가할 수 있지만 새 LLM 검색·판정 API 호출은 추가하지 않았다.
- 선정 근거 전체를 생성에 전달하므로 생성 입력 토큰은 증가할 수 있다. 추가 검색 결과는 원장을 덮어쓰지 않는다.
- 서버 지시 대기는 불필요한 조기 재시도를 줄이지만 작은 TPM/RPM 한도를 확대하지 않는다. 이번 실제 실행 제한 때문에 전체 PDF 수준의 최종 개선률은 아직 측정하지 못했다.
- 전역 임베딩의 잘림 가능성은 이번 별도 검색 인덱스 수정으로 모두 해소되지 않는다. 모든 backend 또는 D3에 동일한 분할이 적용됐다고 설명하지 않는다.
- OCR이 이미 잘못된 연도를 확정값처럼 추출한 경우 선택기만으로 원본을 복원하지 않는다. 텍스트 페이지 분할만으로 스캔 이미지의 읽기 품질을 보장하지 않는다.
- 원문 위반·추세 목록은 제한된 결정적 조건과 기존 검사 결과를 설명한다. 산업별 법률 판단, 기업 성과 악화의 인과관계, 모든 문제의 탐지는 범위 밖이다.
- 추가 검색에서 일부 관련 조항이 계속 회수되지 않았다. 채택 hit 수와 테스트 통과 수를 문제 발견률이나 실제 보고서 정확도로 바꾸어 보고하지 않는다.
- 2위 이하 후보에서 R1 점수 사유를 제외한 변경은 **채택 근거 수를 늘린다**(49 → 69). 내용 게이트는 그대로지만 화면에 붙는 참고 근거가 많아지는 방향의 변화이므로, 리뷰에서 근거 품질을 직접 확인할 것을 권한다.
- 직접 근거/주변 설명 판정은 **수치·연도 일치라는 결정적 규칙**이다. 수치 없이 사건 경위만 서술한 원문은 `context`로 남으므로, 이 표시가 근거의 중요도 순위는 아니다.
- 교육 이수율 감소 조항은 K-ESG 카탈로그에 대응 항목이 없어 항목별 추가 검색으로 회수할 수 없다. 항목을 새로 만들면 점수 프로파일에 영향이 가므로 **미해결로 남겼고 보류로 이름을 바꾸지 않았다.**
- 장문 입력 절단은 이번에 **측정만** 했다. 문서 28.9%·문자 22.1%가 임베딩에서 잘리고 영역 질의 3개도 잘린다는 사실을 확인했으나 코드는 바꾸지 않았다. 해소했다고 설명하지 않는다.
- 전체 문서 기준의 전후 비교는 아래 표로 정리했다. **기준 버전의 같은 지표를 재측정하지 않은 칸은 "미측정"으로 남겼고, 추정값으로 채우지 않았다.**

## 승인이 필요한 남은 결정

아래 둘은 **측정만 끝났고 코드를 바꾸지 않았다.** 승인 없이 적용하지 않는다.

1. **임베딩 128토큰 절단(항목 B)** — 문서 28.9%·문자 22.1%가 임베딩 단계에서 잘린다.
   제안은 영향이 작은 순서로 분리해 두었다([제안 문서](proposal_long_input_truncation.md)).
   기존 검색·D3 전체로 분할을 확대하는 안은 별도 승인 사항이며, 이 문서를 그 승인으로
   해석하지 않는다.
2. **동시 실행(2~3)과 429 백오프** — 전량 실행에서 30,000 TPM 중 약 12,700만 썼다.
   전체 OCR 시간(4,119초)을 줄이는 실제 수단은 청킹이 아니라 이쪽이라는 것이 A/B 측정의
   결론이다. 호출 패턴을 바꾸는 변경이므로 승인 대기로 남긴다.

클라우드 리소스 생성·배포 용량 변경·모델 변경은 하지 않았다. 이 문서 작성으로 푸시·PR
게시·병합을 하지 않았다.
