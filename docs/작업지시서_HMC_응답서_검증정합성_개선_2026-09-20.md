### 2-2. 합산 가능한 값과 참고 부분값을 분리하라

E-4-1은 대표 노드 하나를 고르거나 같은 코드의 모든 값을 무조건 합산하는 방식으로 총량을 만들면 안 된다.

- 동일 기간·호환되는 사업장 경계·서로 중복되지 않는 실제 에너지원임이 확인된 경우에만 공용 단위로 변환해 합산한다.
- 전기/가스 고지서와 이미 합산된 에너지 총계의 중복, 동일 고지서 중복 업로드, m³와 같은 가스의 MJ 이중 계상을 막는다.
- 도시가스는 문서에 표시된 사용열량을 우선한다. 체적만 있는 경우 열량계수의 근거 없이 임의 환산하지 않는다.
- 부분합을 계산할 수 있어도 그 값이 전사·연간·전체 에너지원 총량을 충족한다는 의미는 아니다. 부분합과 총량의 완결성 판정을 분리한다.
- 완결성이 입증되지 않으면 전체 에너지 답변의 verified를 허용하지 않는다. 참고값을 보존할 경우 답변에서 기간·사업장·부분값과 검토 사유가 분명히 보여야 한다. 단순 자가신고 배지만 붙여 해결했다고 하지 않는다.
- 답변에 연결하는 근거는 실제 채택값/계산에 참여한 근거여야 한다. 사용하지 않은 가스 문서를 전력 단독값의 산정 근거처럼 붙이지 않는다. 보완 대상 근거는 용도를 구분한다.

## 작업 3. 재생에너지 부분 비율의 검증 자격 수정

`node_select.classify_common_value_role`의 비율 표현을 무조건 total로 처리하는 경로를 점검하라. 다른 지표의 정상 비율까지 일괄 부분값으로 내리지 않으면서 분자·분모·범위에 따라 판정해야 한다.

- 태양광 5.6%, 기타 재생에너지 1.2%는 에너지원별 구성 비율이다. 전체 재생에너지 비율의 대체값으로 verified 처리하지 않는다. 태양광이 재생에너지의 유일한 공급원이라는 별도 근거 등이 있을 때만 동등성 판단이 가능하다.
- 명시된 전체 비율을 우선하되, 이름만 ‘합계/현재 비율’이면 자동 검증되는 구조는 피한다. 해당 양식이 요구하는 분모가 총에너지인지 전력인지 확인하고 실제 증빙의 분모와 맞춰라.
- 개별 비율을 더하려면 공통 분모·동일 기간·동일 범위·중복 없는 구성임을 먼저 확인한다. 가능한 경우 사용량 합계/전체 사용량으로 계산하고 산식을 보존한다.
- 그린프리미엄·PPA·REC의 포함 여부는 해당 기준과 확인된 조달 증빙에 따라 처리한다. 무조건 포함하거나 제외하지 않는다. 조달수단 이름과 계약 설명이 충돌하면 확인 사유를 남긴다.
- 기존 원본은 ‘상반기 태양광 사용량’과 ‘하반기 착공’이 함께 있다. 확인되지 않은 기존 설비를 가정해 해소하지 말고 실적/계획 충돌로 처리한다. 현재 비율 10.6%가 선택됐다는 이유만으로 검증 완료로 올리지 않는다.
- 원본이 아니라 단일 행/축약 OCR만 주어진 경우에도 그 입력만으로 전체성을 입증할 수 없으면 검증을 보류해야 한다.

단순히 전체 비율 10.6을 하드코딩하거나 D1 임계값을 낮춰 이 사례만 잡는 방식은 금지한다. 완결성이 확인된 정상 재생에너지 총비율은 계속 검증 가능해야 한다.

### 4-1. 같은 대상을 비교하라

비교 전 지표의 의미·단위 차원·기간·사업장·에너지원/총량 범위를 확인하고, 비교 가능할 때만 공용 단위로 수치 오차를 계산한다.

- 142,560 kWh와 142.56 MWh는 동일 조건이면 일치해야 한다.
- 가스 MJ와 전력 kWh는 물리적 환산이 가능하더라도 서로 다른 에너지원이다. 서로 같은 사용량이어야 한다는 비교를 만들지 않는다.
- 같은 값의 다른 단위, 전체와 구성요소, 특정월과 반기 월평균, 제1공장과 범위 미상을 각각 구분한다.
- 이 자료의 720/805 MWh와 전기고지서는 바로 비교할 수 없다. 명확히 다른 범위는 비교 대상에서 제외하고, 요구된 총량을 확인하는 데 필요한 범위가 불명확하면 ‘범위 확인 필요’를 답변과 체크리스트에 남긴다.
- 같은 OCR origin의 서로 다른 독립 문서도 비교가 필요할 수 있다. origin 차이만으로 비교 자격을 정하지 않는다. 동일 문서의 중복 추출값은 독립 검증 근거로 세지 않는다.

### 4-2. 판정 사유를 끝까지 전달하라

비교 완료/실제 불일치/비교 불가/범위 확인 필요를 구분할 수 있는 결과를 기존 평가 모델에 보강하고 `DataPoint → Answer → UI/Excel/PDF/체크리스트`까지 전달하라.

- 실제 불일치는 위험 점수가 0.4라는 이유만으로 단순 자가신고에 머물러서는 안 된다. 구조화된 판정과 사유를 근거로 검토 상태와 설명을 전달한다.
- 모든 estimated를 flagged로 바꾸지 않는다. 정상 파생 추정과 미해결 불일치·경계 미상을 구분한다.
- 관련 없는 범위의 문서를 많이 넣었다고 경고가 쏟아지는 구조를 만들지 않는다. 수치 불일치와 요구 범위의 미확인을 구분한다.
- 재생에너지 전체/부분 비율의 의미 차이를 숫자 허용오차 내 ‘자가신고 일치’로 덮지 않는다.
- 기존 D1 수치 가중치·양방향 비교·공급망 비율 10%p 및 각 경로의 기존 오차 임계값은 유지한다. 수정 대상은 비교 자격·단위·평가 상태 전달이다.
- 평가하지 못한 항목을 위험 0 또는 verified로 되살리지 않는 9월 14일 수정과 확정 원장 계약을 보존한다.

## 작업 5. 제출 출력과 문항 안내 수정

### 5-1. 정렬·요약·숫자 표시

- HMC 영역 순서는 유지하면서 영역 내 코드를 자연 정렬한다. E-1~E-12 순서와 조항 아래 수치 하위 문항의 묶음을 보존한다.
- Excel/PDF 헤더에 `자동응답 / AI초안(승인 대기) / 작성필요 / 증빙대기`를 모두 표시한다. 검토필요 건수는 자동응답 그룹과 중복되는 별도 지표임을 유지한다.
- 회귀용 기존 47문항 사례에서는 68.1% + 10.6% + 0.0% + 21.3%가 보여야 한다. 일반 입력은 각 비율의 표시 반올림을 고려하고 0분모·해당없음을 처리한다. 수치/배지 수정 이후 새 출력 비율을 이 옛 비율에 맞춰 조작하지 않는다.
- 숫자는 공용 표시 경로에서 천 단위 구분, 불필요한 `.0` 제거, 단위와 기간을 일관되게 표시한다. 원장 값을 표시용으로 반올림해 저장하지 않는다. 0.513216 TJ를 0.5나 0으로 뭉개지 않으며 기존 파생값의 의미 있는 정밀도를 보존한다.
- UI와 Excel/PDF의 배지·값·범위·검토 사유를 맞춘다. 없는 답을 검토필요로 분류했다고 ‘채워진 자동응답’으로 잘못 집계하지 않는지도 확인한다.

### 5-2. 증빙 요구를 실제 문항에 맞춰라

- D-5 공정거래와 C-1 환경 인허가는 실제 qtype과 문항 목적에 맞는 방침·절차·인허가/등록 자료를 안내한다. K-ESG 위반 건수 코드의 정량 폴백을 그대로 쓰지 않는다.
- 문항별 명시 요구 → 해당 문항 유형/의미에 맞는 폴백 순으로 일관된 규칙을 둔다. exporter에서만 문구를 바꾸지 말고 UI·체크리스트가 공유하는 응답 정보에서 해결한다.
- C-5는 현재 numeric/kg이므로 유지할 수치 문항의 문구를 명확히 하라. 관리체계 존재 여부는 기존 C-4/C-8의 패턴을 따라 별도 문항으로 분리하는 방식을 우선 검토·적용한다. 분리로 문항 수나 qid 의미가 바뀌면 저장 답변·초안 캐시·집계 호환성을 처리하고 변경을 문서화한다. 기존 숫자 답을 예/아니오로 조용히 재해석하지 않는다.
- K-ESG 원래 수치 문항에 필요한 정량 안내까지 정책 안내로 바꾸지 않는다.

### 5-3. 내부 인용 ID를 제출 표시로 변환하라

- 내부 `draft_text`와 감사 JSON의 node_id·추적 관계는 보존한다.
- 사용자에게 보여주는 응답 본문과 출처 목록은 `[1]` 등의 인용번호와 문서명·실제 페이지로 표시한다. Excel/PDF와 사용자용 초안 표시가 같은 규칙을 쓰게 한다.
- `[LOCAL_TXT_0043]` 같은 내부 ID를 그대로 노출하지 않는다. 모든 대괄호를 지우는 방식은 사용하지 않는다.
- 본문에서 실제 인용한 근거와 출처 목록을 맞추고 번호를 안정적으로 부여한다. 근거 ID가 해소되지 않으면 출처를 지어내지 말고 검토 사유를 남긴다.
- 페이지가 미상이면 임의로 p.1을 붙이지 않는다. 0/1 기반 페이지를 확인해 실제 1쪽 문서를 p.2로 표시하지 않는다.

## 작업 6. E-7의 질문 적합성과 초안 승인 조건 개선

우선 볼 위치: `supplychain/drafter.py`, 기존 검색·근거게이트, `tests/test_supplychain_drafter.py` 및 초안 UI 테스트.

- 코드 일치 경로와 BM25 폴백 모두에서 문항 목적에 맞게 근거를 좁힌다. 관련 청크 하나 때문에 관련 없는 청크 전체가 통과하지 않게 한다.
- 근거에 있는 말인지 확인하는 grounding과, 질문에 실제로 답하는지 확인하는 문항 적합성을 구분한다. E-7만의 파일명/노드 ID 화이트리스트나 무관 단어 블랙리스트로 해결하지 않는다.
- E-7은 방침·관행·기대·성과를 누구에게 어떤 경로로 전달하는지를 근거가 허용하는 만큼 답해야 한다. 근거가 부족하면 부족 상태를 유지하거나 확인된 범위만 명확히 한 제한적 초안으로 제시한다. 공급사·고객 소통, 담당자, 주기 등을 지어내지 않는다.
- 노사협의·단결권·핫라인·ISMS 문장을 이어 붙이는 것만으로 의사소통 프로세스 답변이 완성됐다고 보지 않는다.
- E-8은 근로자·이해관계자 참여·구제접근 문항이다. 같은 근거의 정당한 재사용은 허용하되, 문항 차이를 무시한 동일 답변을 승인 가능한 초안으로 만들지 않는다.
- 근거 없는 ISMS 취득·운영 사실을 생성하지 않는 등 기존 미증빙 진술 방어와 인용 게이트를 유지한다.

긍정 대조군은 실제 의사소통 절차가 있는 문서로 구성한다. 부정 대조군은 단결권/정보보호 등 인접 주제만 있는 경우로 구성하라. 결정적 테스트와 저장 자료 재생을 우선하고, 새 LLM 호출을 하지 않았다면 생성 품질의 라이브 검증을 수행했다고 표현하지 않는다.

## 작업 7. 양식 라벨·설계문서·시연 원본의 정합성

- HMC 제목은 **`현대차 협력사 ESG 사전점검 (RBA v8.0 매핑 참고양식)`**처럼 실제 성격을 드러내도록 변경한다. 공식 현대차 설문 양식으로 오해할 표현을 UI/Excel/PDF에서 정리한다. 내부 framework key `hmc`는 유지한다.
- 설계문서의 `hyundai.py`를 실제 `hmc.py`로 고치고, 존재하지 않는 `kap.py`는 구현 완료 항목에서 제외해 계획으로 표시한다.
- KAP 88지표와 K-ESG 공급망 60항목을 구분한다. 최신 공식 지표 수를 확인하지 않았다면 최신 기준으로 검증했다고 쓰지 말고 참고자료의 시점·확인 범위를 명시한다.
- 모순이 있는 12번 원본은 실패 회귀 자료로 보존한다. 엔진을 통과시키려고 원본·기존 캐시를 바꾸지 않는다. 정상 비교용 자료가 필요하면 별도 합성 fixture를 만들고 가상자료임을 표시한다. 시연 문서의 실제 정정이 필요한 부분은 결과 보고에 남긴다.
