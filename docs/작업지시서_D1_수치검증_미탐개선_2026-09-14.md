**작업 2. 쉼표 없는 숫자도 전체 값으로 인식하도록 수정하라.**

우선 확인할 위치는 `esgenie/layer3_detect.py`의 `_NUMBER_PATTERN`, `_normalize_number`, `extract_numeric_claims`와 D1/D5의 해당 패턴 소비 경로다. 현재 숫자 패턴은 처음 1~3자리 뒤에 쉼표 묶음만 허용하여 `9999`를 놓친다.

필수 동작:

- 지원 단위가 붙은 정상 정수·소수는 천 단위 쉼표 유무와 무관하게 같은 값으로 읽는다. 예: `9999`/`9,999`, `12345.67`/`12,345.67`, `1000000`/`1,000,000`.
- 숫자의 앞이나 뒤 일부만 잘라 인식하지 않는다. 잘못된 쉼표 묶음도 일부 숫자를 정상 주장으로 오인하지 않게 한다.
- 부호가 있는 입력의 부호를 버리지 않는다. 지원하지 않거나 해당 지표에서 부적합한 입력은 이유를 남기고 검토 대상으로 처리한다. 음수를 임의로 양수로 바꾸지 않는다.
- 기존 `Scope3`, `RE100`, `IFRS S2`, 연도·식별자를 수치 실적으로 오인하지 않는 보호 규칙을 유지한다.
- `%`와 `%p`는 전체 단위 토큰을 보존하고 같은 의미로 취급하지 않는다. 지원 중인 `만 tCO2eq` 등 배수 표기도 기존 동작을 유지한다.
- 지원 단위를 무작정 늘리거나 새로운 숫자 파서를 여러 곳에 복제하지 않는다. 이번 변경이 공용 패턴을 사용하는 다른 경로에 미치는 영향을 확인한다.

완료 기준: 정상 표기 변형들은 추출값·단위·주장 수·D1 결과가 같고, 잘못된 입력은 부분 인식으로 정상 통과하지 않아야 한다. 0, 소수, 네 자리 경계, 큰 수, 단위 앞 공백 유무와 기존 식별자 보호를 함께 검사한다.

**작업 3. 주장마다 해당 지표의 확정 증빙만 비교하라.**

핵심 위치는 `esgenie/layer3_detect.py`의 `_score_d1_numeric`, `_match_topic_near`, `_sentence_topic_codes`다. 현재는 가까운 지표 외에 같은 문장의 모든 지표를 후보로 넣고, 주장 숫자와 오차가 가장 작은 값을 채택한다. 이 때문에 서로 뒤바뀐 두 숫자가 각각 다른 지표에서 정답을 찾는다.

필수 동작:

1. 숫자와 지표의 연결을 문장 내 위치·절·지표 표현으로 먼저 결정하고, 그 지표의 증빙과 비교한다. 숫자값이 잘 맞는다는 이유로 다른 지표로 연결을 바꾸지 않는다.
2. 연결이 모호하면 해당 주장을 미확정으로 남기고 이유를 표시한다. 첫 지표에 일괄 배정하거나 문장 전체를 통째로 건너뛰지 않는다.
3. 지표가 결정되면 기존 `ResolvedFact`와 확정 원장 선택을 따른다. 같은 지표라도 부분값·오염 후보·다른 연도의 값으로 재선택해 오류를 숨기지 않는다. 명시적인 확정값 없음과 구버전 메타데이터 누락도 기존 계약대로 구분한다.
4. 정상 다지표 문장, 지표 나열 순서를 바꾼 문장, 쉼표·접속사로 구분된 절, 숫자 뒤에 지표가 등장하는 지원 문형을 확인한다. 기존 다지표 오탐 방지를 제거한 뒤 오탐이 재발하지 않는지 검사한다.
5. 목표·계획·전망과 실적을 구분하는 기존 규칙을 유지한다. 목표가 있는 절 때문에 이웃한 실제 실적까지 검증 대상에서 빠지지 않아야 한다.
6. 비교 기록에는 주장 원문과 위치, 연결된 코드, 비교한 값·단위·근거 ID, 판정 이유를 추적할 수 있는 정보를 남긴다. 기존 자료구조를 활용하고 필요한 정보만 보강한다.

완료 기준: 31%/92%를 맞바꾼 사례가 탐지되고, 정상 다지표 문장은 계속 정상으로 판단되어야 한다. 문장을 둘로 나누거나 순서를 바꿔도 동일한 주장–증빙 관계의 판정은 같아야 한다. 기존 대표값 248.5/부분값 61.2/오염값 999.0 회귀와 정상 단위 환산·Scope 1+2 합산도 유지한다.

**작업 4. 미검증 상태를 보존하고, 이미 발견한 불일치는 유지하라.**

이 항목에는 제품 기본 동작 변경이 포함된다. 현재 `ABSTAIN_ENABLED` 기본값은 False이고, 기존 테스트 일부는 ‘근거 없어도 0점·기권 아님’을 의도적으로 고정한다. 이번 요구사항은 **일반 실행에서 근거 없는 수치 주장을 정상 검증 완료로 집계·표시하지 않는 것**이다.

점검 대상은 `config.py`, `schemas.py`, `layer3_detect.py`, `ssot/detector_5axis.py`, `layer3_judge.py`, `layer4_verify.py`, `layer5_audit_trace.py`와 평가·표시 소비 경로다.

필수 동작:

- 비교 대상 실적 수치에 근거가 없으면 `no_evidence`로 평가를 보류한다. 내부 저장값이 0이더라도 이 값을 ‘수치가 일치함’이나 ‘검증 결과 위험 없음’으로 취급하지 않는다. 환경변수를 따로 설정하지 않은 기본 실행을 검사한다.
- 수치 주장이 없는 문장과 목표만 있는 문장은 ‘해당 비교 대상 없음’으로 구분한다. 이런 문장까지 일괄 평가불가로 만들지 않는다.
- 근거 없음, 단위 비교 불가, 지표 연결 모호, 부적합 숫자를 구분한다. 기존 `ABSTAIN_UNIT_MISMATCH` 토글만 켜서 해결했다고 하지 말고 실제 미검증 사유와 평가 범위를 전달한다. 단위 비교 불가를 수치 불일치라고 확정하거나 정상 일치로 표현하지 않는다.
- 한 문장에 **정상 일치 + 미검증 주장**이 섞이면 전체를 평가 완료로 처리하지 않는다. **확인된 불일치 + 미검증 주장**이 섞이면 불일치 점수를 보존하면서 미검증 범위를 함께 표시한다. 하나의 `abstain` 값으로 문장 전체 점수를 지워 이미 발견한 위험을 숨기지 않는다.
- 비교 가능한 주장 수, 미검증 주장 수와 사유를 알 수 있게 하라. 기존 축별 기권과 별도로 부분 검증 정보가 필요하면 스키마를 최소한으로 확장하고 구버전 읽기 호환성을 확인한다.
- 모든 비교 대상 주장이 미검증이면 D1은 기권한다. 일부 비교 결과가 있으면 그 결과와 부분 평가 상태를 함께 보존한다. 종합 결과의 `evaluation_complete`는 일부 주장만 검증됐다는 이유로 True가 되면 안 된다.
- 기존의 기권 축 제외·유효 가중치 재정규화·전 축 기권 시 null 계약을 유지한다. D1의 부분 평가와 전부 기권을 구분하며, 불일치 임계값과 D1/D2/D3/D5 가중치는 변경하지 않는다.
- LLM 보정 경로에서도 미검증 상태가 사라지지 않도록 한다. 설명만으로 없는 독립 증빙이 생기거나, 낮은 점수 때문에 미검증 답변이 자동 수렴하지 않아야 한다. 사람 검토 필요 상태를 최종 출력에 전달한다.

기존 플래그를 유지하거나 정리한다면 기본값·우선순위·이전 설정의 처리 방식을 문서화하라. 과거 비교 실험용 비활성화가 필요해도 실제 검증이 없었다는 정보까지 지우면 안 된다. 정책 변경으로 기대값을 갱신한 테스트는 변경 이유와 새 요구사항을 연결해 기록한다.

**작업 5. 실제 소비 경로에서 값과 평가 상태를 확인하라.**

함수 단위 검사 후 다음 경로를 연결하여 확인하라.

- 감사 추적: `layer5_audit_trace.py`의 문장별 원문·근거 ID·평가 범위와 요약.
- 화면: `app.py`와 `esgenie/ui/tabs.py`의 요약 카드·수치 검증 표시·부분 평가/평가불가 표시. 실제 앱을 실행하는 Streamlit AppTest도 포함한다.
- 출력: 변경된 D1 결과를 실제로 사용하는 JSON·보고서·Excel/PDF 경로. 해당 결과를 소비하지 않는 경로까지 일괄 수정하지 말고, 적용 여부를 결과 보고서에 구분한다.

대표 사례는 정상, 숫자 뒤바뀜, 쉼표 없는 오기, 근거 없음, 정상+미검증, 불일치+미검증으로 잡는다. 정상값은 유지하고, 오류값은 검토 대상으로, 근거 부재는 평가불가/부분 평가로 전달되는지 확인한다. 낮은 숫자 점수만으로 초록색 ‘검증 완료’가 표시되지 않아야 한다.

확보 가능한 대표 문서의 원문 또는 저장된 실제 추출 결과를 이용해 원장·화면·출력의 값, 단위, 연도, 월간/연간 범위와 근거 페이지가 일치하는지도 확인하라. 자료가 새 worktree에 없으면 원본을 읽기 전용으로 참조한다. 합성 입력 검증과 실제 문서 대조는 결과를 분리해서 기록한다. 이번 D1 수정과 무관한 OCR·기간 추출 결함을 발견하면 별도 후속 항목으로 남긴다.

**작업 6. 회귀와 평가를 수행하고 검토 가능한 결과를 제출하라.**

외부 네트워크를 차단한 상태에서 새 재현 → 관련 회귀 → 전체 테스트 순으로 수행하라. 새 worktree의 코드를 실제로 import하는지 경로를 확인하고, OCR/LLM 캐시와 테스트 산출물은 이번 실행 전용 위치에 둔다. 원본 사용자 캐시를 지우거나 평가 데이터와 섞지 않는다.

주요 기존 회귀는 `test_d1_target_guard.py`, `test_d1_topic_match.py`, `test_d1_units.py`, `test_d1_abstain.py`, `test_abstain_unit_mismatch_toggle.py`, `test_layer3_risk_vector.py`, `test_layer3_judge.py`, `test_pipeline_e2e.py`, `test_ui_apptest_smoke.py`와 `tests/audit_integrity/`다. 새 테스트는 각 요구사항을 검증하는 적절한 위치에 정식으로 추가한다.

평가 원칙:

- 기존 테스트를 무조건 그대로 유지하지도, 실패를 전부 새 동작으로 정당화하지도 않는다. 제품 정책 변경, 정상 동작 회귀, 환경·fixture 문제를 구분한다.
- 새 테스트는 오동작에 맞춰 기대값을 낮추거나 skip/xfail로 숨기지 않는다. 개인 PDF 부재 등 기존 조건부 skip이 있으면 이유와 수를 명시한다.
- 기존 독립 D1 평가와 합성/실보고서 회귀 자료 중 실행 가능한 범위를 같은 설정으로 전후 비교한다. 다지표 매칭을 좁힌 결과 기존 오탐이 늘었는지 반드시 확인한다.
- 기존 held-out에서 이미 확인한 사례는 회귀 비교 자료로 사용한다. 그 사례를 고친 뒤 같은 자료의 개선값을 새로운 일반화 성능이라고 주장하지 않는다. 점수를 높이기 위한 임계값 사후 조정은 하지 않는다.
- 기본 설정, 기존 실험 토글, 룰 단독, LLM 보정 후의 상태 보존을 확인한다. 외부 API가 필요한 평가는 실행한 경우에만 제공자·모델·mock 여부·캐시 여부와 함께 별도로 보고한다.
- 전체 테스트 통과는 새 재현 해결과 함께 보고한다. 테스트 통과 개수만으로 실제 기업 문서 전반의 정확도를 보증하지 않는다.

커밋은 숫자 추출, 지표 매칭, 미검증 상태 및 소비 경로, 검증 기록처럼 검토 가능한 단위로 나눈다. 관련 파일만 선별하여 커밋하고 결과는 작업 브랜치에 남긴다. 원격 게시·PR 생성은 별도 요청 범위에 따르며 **main 병합은 하지 않는다.**

최종 산출물:

1. 작업 브랜치명, 기준 main 커밋, worktree 경로, 실제 사용한 실행 환경.
2. 세 재현 문제의 원인·수정 내용·수정 전후 판정과 정상 대조군 결과.
3. 미검증 상태의 기본 정책, 혼합 문장 처리, 스키마·플래그 호환성 설명.
4. 관련·전체 테스트 결과, 실패/skip과 정책 변경으로 갱신한 기대값의 근거.
5. UI·감사 JSON·관련 내보내기에서 값과 상태가 일치하는 확인 자료.
6. 기존 D1 평가의 전후 변화, 새 오탐 여부, 실제 문서 대조 범위와 남은 한계.
7. 선별 커밋 목록, main 대비 검토용 diff, 원본 미커밋 작업·키·캐시 보존 확인.

**완료 기준은 숫자 표기와 지표 순서가 판정을 왜곡하지 않고, 근거 없는 수치를 검증 완료로 표시하지 않으며, 확인된 불일치와 기존 정상 동작을 모두 유지하는 것이다.** 시연의 네트워크 차단 재현과 완전한 오프라인 실행 패키지는 이번 결과를 바탕으로 별도 작업 지시서에서 다룬다.
