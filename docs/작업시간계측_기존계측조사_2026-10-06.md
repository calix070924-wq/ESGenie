# A-2 작업시간 계측 — 기존 계측 조사 기록 (2026-10-06)

**상태: 조사만 완료 / 구현 미착수.**
작업지시서 A §3의 상세 명세를 확보하지 못해 **파이프라인을 수정하지 않았고 UI 타이머도
구현하지 않았다.** 이 문서는 "이미 있는 계측이 무엇이고, 무엇이 없는가"의 기록이다.

## 2. 없는 것 (명세 없이 만들지 않았다)

| 필요한 것 | 왜 지금 못 하는가 |
|---|---|
| **구간 분해** (업로드 / OCR / 추출 / 답변 생성 / 내보내기) | OCR 구간만 계측된다. 나머지 구간의 **경계를 어디로 끊을지가 §3 명세에 있고, 그 명세를 확보하지 못했다.** 임의로 끊으면 보고 수치의 정의가 A가 만든 것이 된다 |
| **사람 작업시간 수집** | 누가·어떤 단위로(문항당? 세트당?)·어떤 방식으로(수동 기록? UI 타이머?) 재는지 정해지지 않았다. **대조군 사람 작업시간을 누가 재는지도 미정이다** |
| **재사용 효과 산식** | 캐시 적중 수는 있으나 "재사용으로 몇 분을 줄였다"로 바꾸는 산식이 없다. 적중 1건당 절약 시간을 A가 가정해서 곱하지 않았다 |
| **단축률의 분모** | 무엇과 비교해 단축인가(사람 수작업? 대조군 AI? 이전 버전?)가 미정이다 |
| UI 타이머 | 지시에 따라 구현하지 않는다 |

## 3. 명세 확보 시 바로 쓸 수 있는 것 / 손봐야 하는 것

**바로 쓸 수 있다**

- 실행 전체 시간, LLM 호출 수·캐시 통계, OCR 요청 통계, OCR 함수별 소요 시간,
  OCR/VLM 캐시 적중·누락 — 모두 `run_stats.json` 하나에 모여 있다.
- 실행 식별은 `audit_trace.generated_at`과 평가 쪽 `run_id`로 묶을 수 있다.

**손봐야 한다**

- 구간 분해: OCR 외 구간에는 계측 지점이 없다. **파이프라인에 측정 지점을 넣는 작업이
  필요하고, 이는 §3 명세 확보 후에 한다.**
- `doctor.py`는 `time.time()`을 쓴다(벽시계). 시간 보정에 영향을 받는다.
  실제 측정에는 `time.monotonic()`을 쓰는 리허설 쪽 경로를 기준으로 삼는 편이 낫다.
- 사람 작업시간은 제품 안에 수집 경로가 **없다.** 별도 기록 서식이 필요하다.

## 4. 계측 기록에 남겨야 하는 것 (이미 정해진 것)

- 호출 수와 토큰 사용량은 실행 기록에 남긴다. `llm` 통계에 호출 수가 있고,
  **토큰 사용량은 현재 `run_stats`에 없다.** 추가가 필요한지 §3 확인 후 판단한다.
- 키 값은 화면·로그·문서·PR에 출력하지 않는다. 기존 `run_stats`에는 키가 들어가지
  않는다(확인함).
- 실행 결과·원본 PDF·캐시·키는 커밋하지 않는다(`outputs/`는 `.gitignore:25`).

## 5. 결론

A-2는 **기존 계측 재사용으로 실행 전체 시간·호출 수·캐시 효과까지는 바로 측정할 수
있고, 구간 분해와 사람 작업시간·재사용 효과 산식은 §3 명세 없이는 만들 수 없다.**
명세가 확보되면 (1) 구간 경계 확정 → (2) 측정 지점 추가 → (3) 사람 작업시간 기록 서식
→ (4) 산식 구현 순으로 진행한다. 그 전까지 미착수를 유지한다.
