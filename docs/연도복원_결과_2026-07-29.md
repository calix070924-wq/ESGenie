## 1. 앵커 노드 해명 — 7,403 vs 70,500 (사용자 재현 실패 건)

사용자 보고: "`17,694 + 52,806 = 70,500 = 앵커 2022(오차 0.000%)`가 재현되지 않는다.
v3 덤프의 2022 폐기물 발생량은 **7,403**이라 70,500과 맞지 않는다."

**두 값 모두 실재하고, 같은 PDF 행의 다른 열이다.** 내가 쓴 앵커는 v3 덤프 노드가
아니라 **OCR 캐시** 메트릭이었다:

| 항목 | 값 |
|---|---|
| 출처 | OCR 응답 캐시, 키 `caba3b8f` |
| metric_hint | `폐기물 발생량` |
| period_raw | `2022 합계` |
| value | `70500.0` |
| 원문 | 모비스 p.70 (0-기준 69) |

같은 행의 열 구성(부착 후 재구성 텍스트, 실측 인용):

```
폐기물 발생량 | ton | 7,403(국내(별도)|2022) | 7,939(국내 자회사|2022) | 55,159(해외 자회사|2022) | 70,500(합계|2022) | 7,807(국내(별도)|2023) | … | 72,875(합계|2023) | … | 72,463(합계|2024)
```

- **7,403** = 2022 `국내(별도)` 열 (부분값)
- **70,500** = 2022 `합계` 열 (전사 총량) ← 내가 쓴 앵커

**v3 덤프에 70,500이 없는 이유**: v3 덤프(mtime 2026-07-26T14:25)가 현재 캐시
(2026-07-26T11:08Z 이후)보다 **앞선 다른 LLM 실행**이다. 그 실행은 12열 중 첫 세트만
뽑았고, 그마저 `국내(별도)` 열이었다. 이것이 이번 작업이 고치려는 현상 자체다 —
라벨이 세 번 `(합계)`로 같아 LLM이 3세트를 1세트로 접었다.

**부착 후에는 합 항등식이 연도까지 맞는다**(§3 인용 참조):
`17,694(합계|2022)` + `52,806(합계|2022)` = `70,500` = 2022 합계 발생량. 오차 0.

| `esgenie/ssot/ssot_pipeline.py` | `_flag_period_inferred` — 대표 노드가 추론 연도면 `confidence_flags`에 `period_inferred` + notes 한 줄. 승격 경로 2곳 모두. |

소비 지점 3곳(요구사항 그대로):
1. **G4 projection 판정** — 추론 연도로는 미래 전망을 판정하지 않는다(명시 가드).
2. **`node_select` 연도 축** — 추론 노드는 **같은 순위 안에서만** 후순위.
3. **`confidence_flags` + 원장 notes** — 원장 표에 '2025 실적'과 '연도 미상'이 갈린다.

**축 순서를 바꾸지 않은 이유**: 추론 강등을 별도 축으로 앞에 두면 상위 축(집계·단위)을
뒤집는다. 튜플 2번째 항으로 두면 동률일 때만 개입한다. 회귀 테스트로 고정
(`test_higher_axes_still_beat_inferred_flag`).

### 작업2 — 2단 헤더 (`esgenie/ssot/ocr_router.py`)

`_attach_column_headers`가 **연도 전용 헤더 행**을 인식한다:
- 판정: 순수 연도 셀(`^20\d{2}$`) 2개 이상 **+ 집계 키워드 0개**. 집계어가 섞이면
  1단 헤더(LG화학 `지표 | 단위 | 2023 | 2024 | 2025`)이므로 대상이 아니다.
- 매핑: 집계 컬럼 x중심 → **최근접 연도 x중심**. 연도 라벨은 자기 그룹의 중앙에 놓인다.
  실측 여유 **1.67배**(그룹내 최대거리 69.1pt vs 차선 연도 최소거리 115.1pt).
- 형식: `17,694(합계|2022)` — `|` 앞은 집계(→`metric_hint`), 뒤는 연도(→`period`).
- 신선도: 연도 행이 `_LABEL_INHERIT_MAX_SPAN`(=2) 행 안에 있을 때만 물린다.

**추가한 안전장치 2종** (기존 3종은 전부 보존):
- 집계 컬럼 수가 연도 수로 나눠지지 않거나 그룹 크기가 서로 다르면 **연도만 생략**
  (집계 부착은 종전대로). 틀린 연도가 미상보다 나쁘다.
- 연도 전용 행이 없으면 아무것도 안 붙는다.

하류 분리:
- `prompts.py VLM_EXTRACT_PROMPT` — `|` 앞/뒤 라우팅 지시 + "값마다 별도 metric으로
  전부 출력" + "period 모르면 추측 말고 빈 문자열".
- `ocr_router._split_hint_year` — LLM이 라벨을 hint에 통째로 복사해도 파싱에서 가른다
  (방어 이중화). period가 이미 있으면 덮어쓰지 않는다.

| 신한지주 | `period_inferred` | 0/59 | **0** | 텍스트 불변이라 반드시 0 |
| NAVER | `period_inferred` | 0/39 | **0** | 텍스트 불변이라 반드시 0 |
| 전체 | 대표 노드 선택 | — | **모비스 외 불변** | 다른 회사 원장값이 바뀌면 실패 |

신한·NAVER·삼성전기·LG화학은 **입력 텍스트가 바이트 단위로 같다**. 그래도 값이 바뀌면
LLM 비결정성(temperature)이지 이 변경 탓이 아니다 — 그 경우 `ocr_diff.py`로 노드 단위
비교를 붙여 원인을 갈라야 한다.

## 6. 작업5 — 합 항등식 (조건부, 라이브 후)

현재 판단: **불필요할 가능성이 높다.** §1에서 보인 대로 부착만으로 항등식이 연도까지
맞는다(`17,694(합계|2022)` + `52,806(합계|2022)` = `70,500`). 라이브에서 세 연도가
모두 노드로 잡히면 별도 항등식 복원 로직 없이 해결된다.

라이브 결과에 여전히 `period_inferred`가 남으면 그때 판단한다. 남는 유형을 먼저 보고,
합 항등식이 그 유형을 실제로 설명하는지 확인한 뒤 착수한다 — 조사 없이 구현하면
§1의 v3/캐시 혼동을 반복한다.
