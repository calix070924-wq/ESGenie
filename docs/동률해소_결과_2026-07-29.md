# 대표 노드 완전 동률 해소 — 값 최빈 tie-breaker 결과 (2026-07-29)

브랜치 `feature/node-select-mode` · 대상 `esgenie/ssot/node_select.py::select_representative_node`

## 요약

전 축이 동률일 때 **id 문자열 순서가 답을 정하던 구멍**을 값 최빈 축으로 닫았다.
축 순서는 `… → 연도(7) → 값 최빈(8) → 최신·고신뢰·id(9)`이고, 최빈은 **최빈값이
유일할 때만** 개입한다.

저장된 5개사 덤프 36개 항목에 오프라인 재적용한 결과 **변경 1건**:

```
현대모비스 E-4-2   10.0 → 12.9  [재생에너지 사용전환율]
변경 1건 / 36개 항목
```

전체 테스트 스위트 **843 passed / 0 failed** (직접 측정한 `main` 기준선 836 + 신규 7건).

## 1. 문제 — 현대모비스 E-4-2

원장이 **10.0%**를 올렸다. 정답은 **12.9%**다(라벨링 §3-5: p.1646 · p.2032 RE100
로드맵 12.9→65→100 · p.2406 표에서 일관 확인).

2024 후보의 축별 점수 — hard 배제(1·2단계) 생존자만:

| 값 | 파생 | 충돌 | 계열 | 분해 | 집계 | 단위 | 연도 | hint |
|---|---|---|---|---|---|---|---|---|
| 12.9 | 0 | 0 | 0 | 0 | 1 | 0 | 0 | 재생에너지 사용전환율 |
| 1.1 | 0 | 0 | 0 | 0 | 1 | 0 | 0 | 재생에너지 사용 비율 |
| 10.0 | 0 | 0 | 0 | 0 | 1 | 0 | 0 | 재생에너지 전환 비율 ← **종전 선택** |
| 12.9 | 0 | 0 | 0 | 0 | 1 | 0 | 0 | 재생에너지 사용·전환율 |
| 12.9 | 0 | 0 | 0 | 0 | 2 | 0 | 0 | 사업장 재생에너지 사용·전환률 (FY2019 기준) |

전부 수식어 없는 유사 항목명이라 계열·분해·단위 축이 하나도 안 문다(`사업장`만
5단계에서 후순위로 밀린다). 연도도 전부 2024로 동률이라 마지막에
`-period → -confidence → str(id)`로 떨어지고, **id 문자열 최소**인
`…__88e0e65572`(10.0)가 이겼다.

같은 지표가 보고서 여러 곳(표·본문·요약)에서 반복 언급되므로 12.9는 3회, 10.0과
1.1은 각 1회다. 이 빈도가 신호다.

## 2. ㄱ/ㄴ/ㄷ 세 형태 실측 비교 ★ 설계 근거

최빈을 **순진하게 넣으면 회귀가 난다.** 저장된 5개사 덤프(36개 항목)에 세 형태를
전부 적용했다. 기준선은 덤프의 `ledger_value`가 아니라 **현재 코드에서 최빈 축만 뺀
결과**다 — 덤프의 `ledger_value`는 이전 규칙 버전에서 저장돼 그 뒤 머지된 변경(부분값
표기·지역어 보강 등)이 섞여 최빈 축의 효과만 분리되지 않는다.

재현: `python3 scripts/replay_node_select.py --compare-modes` (라이브 호출 0회)

```
회사         코드                기준선            ㄱ            ㄴ            ㄷ
------------------------------------------------------------------------------------------------
삼성전기       E-6-2            99.0         99.0         97.0         99.0
NAVER      E-6-1           449.0        378.0        449.0        449.0
현대모비스      E-4-2            10.0         12.9         12.9         12.9
------------------------------------------------------------------------------------------------
  ㄱ) 기준선 대비 변경 2건 / 36개 — E-6-1(NAVER), E-4-2(현대모비스)
  ㄴ) 기준선 대비 변경 2건 / 36개 — E-6-2(삼성전기), E-4-2(현대모비스)
  ㄷ) 기준선 대비 변경 1건 / 36개 — E-4-2(현대모비스)     ✅ 채택
------------------------------------------------------------------------------------------------
✔ 현재 코드(node_select.select_representative_node) = ㄷ) 전 항목 일치
```

| 형태 | 설계 | 결과 |
|---|---|---|
| ㄱ | 정렬 키에 전역 빈도 `-freq[value]` (연도 축보다 앞) | 값이 **연도를 넘어** 반복되면 옛 값이 이긴다 |
| ㄴ | 전 축 동률 그룹 안에서만 최빈 (연도로 좁히기 전) | 삼성전기 E-6-2가 **99.0 → 97.0 회귀** |
| ㄷ | **연도를 먼저 좁힌 뒤 그 안에서만 최빈**, 유일할 때만 | 목표 1건만 수정, 나머지 35개 불변 ✅ |

### ㄱ)이 왜 깨지는가 — 연도를 넘는 우연한 반복

NAVER E-6-1 풀:

```
279 ton 2023  폐기물 발생량      279 ton 2023  폐기물 처리량
378 ton 2024  폐기물 발생량      378 ton 2024  폐기물 처리량
449 ton 2025  폐기물 발생량      446 ton 2025  폐기물 처리량
```

3단계 계열 축이 `발생량 > 처리량`이므로 발생량 3개(279·378·449)가 남는다. 그런데
전역 빈도는 처리량 노드까지 세므로 `freq[378]=2 · freq[449]=1`이 되고, 빈도가 연도
축보다 앞에 있어 **2024 값 378이 2025 값 449를 이긴다**. 보고 연도는 2025다.

### ㄴ)이 왜 깨지는가 — 시계열 정체 효과 ★

삼성전기 E-6-2 풀(hard 배제 후 10개 생존)에는 **같은 hint(`폐기물 재활용률`)로 서로
다른 두 시계열**이 섞여 있다:

```
계열 A: 2021 84 → 2022 89 → 2023 96 → 2024 99 → 2025 99   (상승)
계열 B: 2021 93 → 2022 97 → 2023 97 → 2024 97 → 2025 97   (정체)
```

연도 구분 없이 최빈을 세면 **97.0이 4회로 이긴다** — 값이 여러 번 언급돼서가 아니라
**값이 안 변해서**다. 최빈이 '반복 언급'이 아니라 '시계열 정체'를 집는다.

연도를 먼저 좁히면(report_year=2025) 2025만 남아 99.0 vs 97.0 각 1회 → 빈도 동률 →
**무개입** → 9단계로 넘어가 종전 결과 99.0이 보존된다.

**결론: 연도 축(7)이 최빈 축(8)보다 앞에 와야 한다.** 앞선 작업에서 "period 신뢰도가
낮으니 연도를 최후로 강등"했지만, v3에서 period 폴백이 48%→9%로 줄었고 **최빈보다는
연도가 믿을 만하다**는 게 위 실측의 결론이다. 이 순서를 뒤집으면 회귀가 난다 —
코드 주석과 모듈 docstring에 이유를 남겼다.

## 3. 구현

`sort_key` 한 방(`min(key=...)`) 대신 **단계별 필터**로 바꿨다. 최빈 축이 **그 시점의
생존 집합**을 봐야 하기 때문이다 — 정렬 키에 넣으면 집합을 볼 수 없고, 그것이 ㄱ)의
실패다.

```
1) 파생 배제(hard)      2) 지표 정합(hard)          ← 불변
3) 지표 계열   4) 세부 분해   5) 집계   6) 단위 정합   ← _keep_min 단계별 필터
7) 연도 근접                                        ← 최빈보다 앞
8) 값 최빈 — 최빈값이 유일할 때만. 동률이면 무개입    ← 신설
9) 최신 → 고신뢰 → str(id)                          ← 완전 결정성, 제거 금지
```

사전식 비교와의 **동치**: 상위 축에서 최소가 아닌 후보는 어떤 하위 축 값을 가져도
이길 수 없으므로 미리 떨어뜨려도 결과가 같다. 기존 회귀 전부(836건)가 통과하는 것으로
확인했고, 특히 기존 실측 4사례(E-3-1·E-5-1·E-6-1·E-4-1)를 재실행하는 테스트를 따로 뒀다.

신규 헬퍼 2개(둘 다 `node_select.py` 내부):
- `_keep_min(candidates, rank)` — rank 최소만 남기는 단계별 필터의 단위 연산
- `_keep_value_mode(candidates)` — 8단계. 최빈값이 유일할 때만 좁히고, 동률이면 원 집합 반환

우선순위 1~6단계와 negative keyword 표는 건드리지 않았다.

`-period` 항이 연도 다음이었으므로, 그 항을 8단계 앞으로 끌어올려(최신 연도로 좁힘)
같은 불변식을 지켰다 — 동치 변환이라 기존 회귀는 불변이다.

테스트 헬퍼 `_nid()`를 추가했다. 기존 `_n()`은 id를 `hash()`로 만들어
프로세스마다 값이 달라지는데(PYTHONHASHSEED), 최후 tie-breaker가 `str(id)`이므로
'규칙 없으면 id로 갈린다'를 재현하는 테스트는 **실측 덤프의 id 원본**이 필요하다 —
그러지 않으면 구현 전 실패가 우연히 통과한다.

## 6. 관찰 — 범위 밖, 기록만

**삼성전기 E-6-2 풀에 같은 hint(`폐기물 재활용률`)로 두 개의 서로 다른 시계열이 있다.**

```
계열 A: 2021 84 → 2022 89 → 2023 96 → 2024 99 → 2025 99
계열 B: 2021 93 → 2022 97 → 2023 97 → 2024 97 → 2025 97
```

국내/글로벌이든 일반/지정이든 **구분자가 hint에 없다.** 두 계열이 무엇인지 hint만으로는
판별 불가하고, 그래서 선택 규칙이 어느 쪽을 골라도 근거를 댈 수 없다. 지금은 계열 A의
2025값(99.0)이 뽑히지만 그것이 '전사 총량'인지는 hint가 말해주지 않는다.

이것은 **추출 단계 문제이지 선택 문제가 아니다** — L0가 표의 구분 열(지역·폐기물 종류
등)을 hint에 싣지 못한 결과다. 고치지 않았다. (나) 연도 뭉개짐 작업의 재료다.

NAVER E-6-1도 같은 구조의 약한 사례다(`폐기물 발생량`·`폐기물 처리량`이 연도별로 짝을
이루지만 구분 열 정보가 hint에 없다). 여기서는 3단계 계열 축이 갈라주므로 오선택은 없다.
