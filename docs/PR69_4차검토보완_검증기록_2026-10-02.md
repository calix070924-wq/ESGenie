## 2. 세 결함의 수정 전/후와 일반화한 규칙

### R1 지원 단위를 붙인 정상 0

- 수정 전: `_ZERO_NUMERIC_FACT_TAIL_RE`가 단위를 `[A-Za-z%]+\d*`·한글 1~2글자로 다시 정의해 `0 tCO2eq`
  (`CO2eq`의 숫자 뒤 글자)·`0 백만원`(한글 3글자)이 `UNRESOLVED / interpretation_unknown`으로 지워졌다.
- 수정 후 규칙(`_zero_unit`):
  - 0 뒤 단위를 F1 판독기 `_read_unit`과 단위 사전 `rag_gates.units.normalize_unit`으로 읽는다. 0 전용 단위표는 없다.
  - 분모 표지가 있으면 F1 결과를 그대로 쓴다. 끝까지 읽은 복합 단위는 그 뒤를 서술로 보고, 못 읽으면 `unit_incomplete`다.
  - 단순 단위는 낱말의 **가장 긴 사전 단위 앞머리**를 단위로 본다. 남은 부분이 한글일 때만 조사·서술로 판정한다
    (`건이었으며` → `건` + `이었으며`). 남은 부분에 영문·숫자·기호가 있으면(`tCO2eqx`·`%p`·`m3x`) 사전 밖
    단위(`unit_unknown`)다. 알려진 앞머리만 떼어 채택하지 않는다.
  - 사전 밖 한글 단위(`0곳`)는 원문 표기가 모델 단위와 같을 때만 단위로 인정한다.
  - 조건(`일 경우`·`이라면`)·가정·목표·예상 판정은 단위가 소비한 범위 **뒤**에서 한다. 단위를 읽었다는 이유만으로 채택하지 않는다.
  - `unit_incomplete`·`unit_unknown`은 UNRESOLVED이고, 사실성 미판정(`interpretation_unknown`)과 다른 사유로 남긴다.
    F1의 `SIMPLE_COMPLETE/COMPOUND_COMPLETE/INCOMPLETE/UNKNOWN/ABSENT`는 바꾸지 않았다.
  - 원문 단위 위치를 기록한다(`source_unit`, `unit_location`). 값 뒤는 `after_value`, 행 라벨·열 머리 괄호
    (`산업재해율(‰) 0`)는 `label`, 원문에 단위가 없으면 `""`다. 모델 단위는 원문 단위로 기록하지 않는다.

### R2 데이터 행과 표 머리글

- 수정 전: `_column_header`가 칸 수가 같은 가장 가까운 앞 행을 머리글로 썼다. 그래서 `교육 참여 인원 | 0 | 50`의 `0`이
  산업재해 행의 목표 열 머리가 돼 목표 0을 SOURCE_ONLY로 채택했다. 연도 표에서는 사이 데이터 행 때문에 연도 열을 잃고
  `period_ambiguous`로 지웠다.
- 수정 후 규칙(`_column_header`, `_is_table_header_row`):
  1. 값에 구조화 표의 셀 머리(`0(합계|2026)`, `_attach_column_headers`가 붙인 셀 좌표)가 있으면 그것을 쓴다(`cell`).
     셀 머리 뒤부터 단위·서술을 읽는다.
  2. 평문 표는 **같은 표**(`|`가 든 줄이 이어진 구간) 안에서만 본다. 빈 줄·본문 줄에서 멈춘다.
  3. 머리글 행은 첫 칸 뒤 칸이 모두 비었거나 이름·연도이고, 수량으로 시작하는 칸이나 부정 서술이 없는 행이다.
     데이터 행은 건너뛰고, 구분선(`---`)은 무시한다.
  4. 칸 수가 같은 가장 가까운 머리글 행과 그 바로 위의 머리글 행들(여러 줄 머리글)을 열마다 이어 붙인다(`header`).
  5. 같은 표에 머리글 행이 없으면 열 정보 없음(`none`)이다. 단일 수치 행은 그대로 판정한다.
  6. 머리글 행은 있으나 칸 수가 맞는 것이 없으면 `column_unresolved`(UNRESOLVED)다. 임의로 목표·실적·연도를 고르지 않는다.
- 연도 열은 F4의 기존 범위 규칙을 그대로 받는다. 요청 `2026`(보고 연도)은 `SOURCE_ONLY/report_year_only`라 연간 확정이
  아니다. 열 머리 `2026`의 판정은 문장 `2026년 … 0건`과 요청 4종에서 같다(테스트로 고정).
- 기록: `evidence_column`(열 머리 원문, 0/0이면 `실적`), `column_state`, `evidence_offset`.

### R3 다른 지표의 기간·사업장 차용

- 수정 전: 후보의 문맥이 `인용의 다른 절 전체 + 같은 절의 앞 서술`이었다. 그래서 `산업재해 발생 건수 0건, 2026년 4월
  김해 제1공장 교육 참석 인원 50명`이 교육의 4월·김해 제1공장으로 CONFIRMED가 됐다.
- 수정 후 규칙(`_zero_heading`, `_zero_scope_verdict`):
  1. 기간·사업장은 자기 서술 → 자기 열 머리 순서로 읽는다.
  2. 없을 때만 후보 **앞**의 절·서술 가운데 **공통 머리말**에서 상속한다. 뒤 절은 보지 않는다.
  3. 공통 머리말이란, 날짜·사업장 표기를 뺀 나머지에 숫자·부정 서술이 없고, 낱말이 모두 범위 머리말 낱말
     (`현황·실적·기준·보고·안전·환경…`)·일반 낱말·이 지표의 낱말인 문구다. `교육 참석 인원 50명`·`교육 현황`·`협력사 평가 결과`는
     다른 대상을 가리키므로 머리말이 아니다. 표의 데이터 행도 머리말이 아니다.
  4. 출처를 기록한다: `scope_from`(statement / column / heading / statement+heading / "")·`scope_heading`.
  5. 숫자 0과 부정 서술이 같은 규칙을 쓴다. 자기 범위의 명시적 충돌(`site_mismatch`·`period_mismatch`)은 그대로 거부한다.
- 원장 우회 확인:
  - `_zero_scope_boundary`는 원문 범위가 없으면 경계에 기간·사업장을 싣지 않는다. 모델 경계의 요청 사업장은
    원래 값으로 남고(`requested_period`는 감사 기록), `zero_evidence.status`는 SOURCE_ONLY다.
  - `merge_ocr_extraction → derive_boundary`는 모든 지표에 쓰는 문서 문맥 규칙(`사용기간 …` 머리 등)으로 경계의
    기간·사업장을 채울 수 있다. 이 규칙은 바꾸지 않았다. 대신 그렇게 채워져도 `zero_evidence` 상태가
    SOURCE_ONLY로 남고 `selection`의 `scope_source_only` 플래그가 유지되는지 테스트로 고정했다
    (`test_doc_context_or_model_boundary_never_reconfirms_the_scope`). CONFIRMED로 덮어쓰는 경로는 찾지 못했다.
