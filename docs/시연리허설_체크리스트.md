# ESGenie 시연 리허설 체크리스트

> 목적: **시연 당일 흐름이 반복 가능하게 매끄러운가**를 매 리허설마다 점검한다.
> 데모(2026-08-14) 전 여러 번 돌려 손에 익히는 용도 — 클릭 순서·소요 시간·폴백 대응까지.
>
> **성격 구분**: `docs/라이브검증_체크리스트.md`는 "스택이 라이브로 도는가"를 STRICT
> 커맨드로 **1회 증명**하는 문서다. 본 문서는 그게 통과했다는 전제에서 "시연 흐름이
> 매끄러운가"를 **매 리허설 반복 점검**한다. 겹치는 내용(자주 터지는 지점 등)은 중복
> 작성하지 않고 링크로 참조한다.
>
> **실행 주체**: 라이브 커맨드(STRICT 파이프라인·앱 구동)는 과금·키 사용이 있으므로
> **리허설 담당자가 로컬 PC에서 직접 실행**한다. 본 문서는 커맨드를 적어둘 뿐이다.

## 1. 사전 환경 점검

리허설 시작 전, 셸에서 아래를 확인한다. **키 값 자체는 절대 출력하지 않는다** (존재 여부만).

```bash
cd <ESGenie 폴더>

# (a) .env 키 존재만 확인 (값 노출 금지 — 개수만 본다)
grep -cE 'OPENAI_API_KEY|AZURE_OPENAI_ENDPOINT|UPSTAGE_API_KEY|DART_API_KEY' .env

# (b) STRICT 모드로 리허설할지 결정 — 조용한 mock 폴백을 막아 "진짜 라이브"만 통과시킴
export ESGENIE_STRICT=1

# (c) DP 모델·api_version 기본값이 시연에 맞는지 한 줄로 확인 (⚠️ 필수 항목)
python -c "from esgenie.ssot.ocr_router import UPSTAGE_DP_MODEL; from esgenie.config import SETTINGS; print('DP =', UPSTAGE_DP_MODEL); print('api_version =', SETTINGS.azure_api_version)"
```

**합격 기준**

- [ ] (a) 4개 키 모두 존재 (개수 4)
- [ ] (b) `ESGENIE_STRICT=1` 설정됨
- [ ] (c) **`DP = document-parse-260630`** — 구 alias `document-parse`는 **2026-07-31 지원 종료**,
      시연(8/14)은 그 이후이므로 신버전으로 잡혀야 한다 (**필수**). 구버전이면 리허설 중단하고
      `UPSTAGE_DP_MODEL` 환경변수·`.env` 확인.
- [ ] (c) **`api_version = 2024-10-21`** — GA 버전. preview 버전이 잡히면 대회 당일 종료 리스크.

> 스택이 라이브로 완주하는지(trace `llm`/`embed_backend`, OCR `engine`)는 이 문서 범위 밖 —
> 리허설 전 최소 1회 `docs/라이브검증_체크리스트.md`로 증명해 둔다.

## 2. 경로 A — DART 자동채움 리허설

상장사를 검색해 DART 공시가 자동으로 채워지고, 실시간 조회임이 화면에 드러나는지 확인한다.

```bash
# 리허설 담당자가 직접 실행 (과금·키 사용)
ESGENIE_STRICT=1 streamlit run app.py
```

**흐름 (⏱ 소요 시간 기록)**

1. [ ] 좌측 **"회사 검색"** 입력 → 상장사명 입력 (예: `삼성전자`, `포스코`)
2. [ ] **"검색 결과"** 셀렉트에서 대상 선택 → 회사명·업종·`DART 연동` 체크박스가 **자동채움**되는지
3. [ ] 영역(E/S/G) 선택 후 분석 버튼 → 진단 완주
4. [ ] **출처 배지 확인 (H2 검증)**: 결과 상단 hero 배지 영역에 **`DART 실시간`** 배지(초록/success)가
      뜨는지. `샘플 데이터`(주황)·`수동 입력`·`증빙 기반 (DART 미사용)`이 뜨면 라이브 조회 실패
      → 화면에 `⚠️ DART 실시간 조회에 실패해 대체 데이터로 분석되었습니다.` 경고가 함께 뜬다.
5. [ ] ⏱ **자동채움~진단 완주 소요 시간**: ______ 초

> 배지 판정 근거: 검색 선택 시 `_last_search_corp_code`가 갱신되며 `corp_name_manual`·
> `corp_code_manual`·`use_dart`가 세션에 세팅됨. 배지는 `report.source == "dart_api"` → `DART 실시간`.

## 3. 경로 B — 증빙 업로드 리허설

증빙 세트를 업로드해 진단·그린워싱·다운로드까지, 그리고 **업로드 후 위젯 조작 시 지연이
없는지**(H3)를 확인한다.

**증빙 세트**: `시연증빙세트_한울정밀공업/` 의 `01_전기요금청구서_2026-05.pdf` ~
`20_RBA자가평가체크리스트_2026-06.pdf` (01~20번, `test.pdf`·`00_README`는 제외).

**흐름**

1. [ ] **"증빙 파일"** 업로더에 01~20번 파일을 업로드 → 파일별 채널·문서유형·신뢰도 표가 렌더되는지
2. [ ] 분석 실행 → 진단 완주
3. [ ] **그린워싱 검증** 탭(`🔍 그린워싱 검증`)에서 **🚩** 확인 — 데이터시트의 `검토 필요 (🚩)`
      메트릭 건수 > 0, 그리고 `🚩 제출 전 검토 필요` 섹션이 렌더되는지
4. [ ] **제출 서류** 탭(`📄 제출 서류`)에서 **3종 다운로드** 정상:
      - `📥 통합 보고서 (.pdf)` / `📥 통합 보고서 (.md)`
      - `📥 데이터시트 (.xlsx)`
      - `📥 감사 추적 (.json)`

**⚠️ 필수 항목 — 업로드 후 위젯 조작 시 지연 (H3 세션 캐시 검증)**

Streamlit은 위젯 조작마다 스크립트를 전체 재실행한다. 세션 캐시(`_route_cache`, key=`(파일명, 크기)`)가
없으면 업로드된 스캔본마다 매 rerun에 Upstage DP 1페이지가 재호출되어 지연·과금이 누적된다.

- [ ] 01~20번 **업로드가 유지된 상태**에서 체크박스(`DART 연동` 등)·셀렉트(영역/목적/업종)를 **토글**
- [ ] 토글 시 **수 초 지연("로딩 튐")이 없는지** — 지연이 있으면 재OCR 발생 의심
- [ ] (선택) Upstage 재호출 여부를 확실히 보려면 앱 실행 터미널 로그에 업로드 후 토글 시
      OCR/route 호출 라인이 **더 찍히지 않는지** 확인

> 점검보고서 H3 지정 항목. 정상이면 업로드 직후 1회만 라우팅되고, 이후 토글은 캐시 히트로 즉시 반응.

## 4. 클릭 경로 (현행 3탭 + 전문가 모드)

app.py 실물 기준 탭 구성 (구 6탭 Overview/Analysis 기준 아님):

**기본 (분석 결과 있음)**

1. `📊 진단 결과` — 커버리지·점수·ISSB 갭 등
2. `🔍 그린워싱 검증` — 초안 vs 최종 전후 비교, 위험도, 🚩
3. `📄 제출 서류` — 통합 보고서 / 데이터시트 / 감사 추적 다운로드, 공급망 응답서

**전문가 모드** (사이드바 `🔬 전문가 모드` 체크 → `expert_mode`): 위 3탭 뒤에 2탭 추가

4. `🗂 근거·검증 상세`
5. `🧪 실험실`

시연 클릭 순서 리허설:

- [ ] 회사/증빙 준비 → 분석 → `📊 진단 결과` 설명
- [ ] `🔍 그린워싱 검증`으로 이동해 초안→최종 개선·🚩 시연
- [ ] `📄 제출 서류`에서 3종 다운로드 시연
- [ ] (필요 시) `🔬 전문가 모드` 켜서 `🗂 근거·검증 상세`·`🧪 실험실` 노출

## 5. 폴백 절차 (시연 중 라이브 실패 시)

라이브 호출이 시연 중 터졌을 때의 행동 요령. **당황하지 말고 아래 순서로 우회.**

**(a) 빨간 에러(traceback) 발생 시**

- 분석 실행부는 예외를 잡아 `st.error` + 이전 결과 유지로 방어됨(H1). 화면이 살아 있으면
  이미 렌더된 탭(`📊 진단 결과` 등)으로 **이동해 설명을 이어간다** — 재분석을 그 자리에서 시도하지 말 것.
- 앱 자체가 죽으면 터미널에서 재기동: `ESGENIE_STRICT=1 streamlit run app.py`

**(b) 라이브 API가 계속 실패할 때 → mock으로 전환**

키/네트워크 문제로 라이브가 반복 실패하면, STRICT를 끄고 mock으로 전환해 흐름만 시연한다.
(mock은 실 API 없이 데모용 고정 데이터로 완주 — 배지는 `DART 실시간`이 아니게 되므로 심사에 미리 고지.)

```bash
# STRICT 해제 + mock 강제 후 재기동 (리허설 담당자 실행)
unset ESGENIE_STRICT
ESGENIE_FORCE_MOCK=1 streamlit run app.py
```

**(c) 사전 생성 산출물 백업 위치** (앱이 아예 안 뜰 때 파일로 시연)

- 한울정밀 K-ESG 데이터시트: `outputs/KESG28_자가진단_한울정밀/실사응답서_kesg28_한울정밀.xlsx`
- 공급망 실사 응답서(데모): `outputs/_supplychain_evidence_demo/실사응답서_kesg28_한울정밀공업㈜.pdf`
- 과거 분석 audit_trace: `outputs/audit_trace_*.json` (상장사 005930 등)
- ※ 리허설 때 위 파일들이 실제로 존재하는지 미리 열어 확인해 둘 것.

**(d) 자주 터지는 지점 표**: 증상별 원인·대응은
[`docs/라이브검증_체크리스트.md` "자주 터지는 지점 & 대응"](라이브검증_체크리스트.md#자주-터지는-지점--대응) 참조 (중복 작성 안 함).
