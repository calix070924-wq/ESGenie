## 3. 전달 전에 찾아 고친 유출 1건

`docs/공통답안형식_v1초안_2026-10-06.md` §5의 근거 예시에 실제 증빙 문구(K-ESG 08 노드
재투입률 값이 들어간 인용문)를 써 두었다. 빌드한 ZIP을 풀어 읽는 과정에서 찾아 합성
자리값으로 바꿨고(커밋 `797285c`), **전달한 #1에는 들어가지 않았다.**

경로 기반 금지 검사로는 못 잡는다 — 허용된 문서 **본문**에 인용된 값이기 때문이다. 그래서
두 가지를 남겼다.

1. `_unmarked_quotes()` — 합성 예시 JSON의 `quote`에 합성 표시(`예시`·`합성`·`SYN`·
   `자리값`)가 없으면 빌드가 실패한다. 실제 수치를 코드에 적어 비교하지 않는다(그러면
   그 수치가 저장소에 남는다).
2. **전달 전 내용 검토를 절차에서 빼지 않는다.**

### 3.1 검토 주체 구분 — 자동검사 / AI 내용 검토 / 사람 검토

세 가지를 섞어 적지 않는다. 지금까지 수행된 것은 앞의 두 가지뿐이다.

| 종류 | 무엇을 했는가 | #1 | #2 |
|---|---|---|---|
| **자동검사** | 빌더의 금지 경로·키 표식·빈 서식·인용문 표시 검사, 빌드 후 ZIP 재개봉 해시 대조 | 수행 | 수행 |
| **AI 내용 검토** (Claude) | 압축을 풀어 전체 인용문 8건과 라벨 CSV 4행을 읽고 기대값 인용 여부를 확인 | 수행 — 유출 1건을 여기서 찾았다 | 수행 |

**AI 내용 검토를 사람 검토로 적지 않는다.** 1차 보고에서 "사람 확인"이라고 쓴 것은
정정한다 — 실제로는 AI가 읽은 검토였다. 사람 검토가 필요한지와 누가 할지는 정민 판단
사항이며, 이 문서는 수행 여부만 적는다.

## 4. #2의 재현 검증 (실제로 돌린 것)

기존 worktree 경로와 숨은 로컬 설정에 의존하지 않는지 보려고, **새 임시 폴더에 압축을
풀고 README의 명령을 그대로** 돌렸다. `PYTHONPATH`는 해제했다(`env -u PYTHONPATH`).

| 확인 | 결과 |
|---|---|
| 추출 폴더에 `conftest.py`·`pyproject.toml`·`.pth`·`.env` 없음 | 확인 |
| `import esgenie`가 설치본이 아니라 추출 트리를 가리킴 | 확인 |
| 0) 합성 채점 — venv Python **3.14.6** | 종료 코드 0 |
| 0) 같은 명령 — 시스템 `/usr/bin/python3` **3.9.6** (프로젝트 venv 아님, 설치 없음) | 종료 코드 0, 집계 동일 |
| 1) 공통 형식 문서 검증 | `OK` |
| 2) 어댑터 CLI 기동 | 정상 |
| 독립성 집계 CLI 기동 | 정상 |
| `bucket_counts` | `correct_hold` 1 · `wrong_confirmation` 1 · `unnecessary_hold` 1 · `unresolved` 1 |
| `expected_qids_source` | `file:data/eval/examples/synthetic_run/qids_SYN.txt` |
| 결과에 비율·정확도·종합 점수 키 | **없음.** `metrics_blocked_reason`만 있다 |
| 두 파이썬의 집계 5종 일치 | 전부 일치 |

**이 통과는 평가 결과가 아니다.** 입력이 전부 합성이고, 라벨러는 `SYNTHETIC`, 증빙
인용문은 자리값이다. 산출 불가 지표는 `0`이 아니라 차단 사유로 나온다.
