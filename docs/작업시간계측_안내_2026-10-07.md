# 작업시간 계측 안내 — 기계 시간과 사람 시간 (2026-10-07)

작업지시서 A §3.1~§3.3 구현에 대한 안내다. **UI 타이머는 만들지 않았다**(§3.2). 사람
기록은 CSV로 받는다.

## 0. 세 가지 시간을 섞지 않는다

| 양 | 어디서 나오는가 | 누가 적는가 |
|---|---|---|
| **기계 시간** (파이프라인 단계별 초) | `esgenie/run_timing.py` → `PipelineOutput.timings`, 실행 폴더의 `timings.json` | 코드가 `perf_counter`로 잰다 |
| **사람 작업시간** | worklog CSV의 `처리대기`가 아닌 단계 | **사람이 적는다** |
| **대기시간** | worklog CSV의 `처리대기` 단계 | **사람이 적는다** |

관계는 하나뿐이다:

```
실제 경과시간(elapsed) = 사람 작업시간(human) + 대기시간(wait) + 빈 시간(idle)
```

**기계 시간은 이 식에 더하지 않는다.** 기계가 도는 동안 사람은 `처리대기`를 적고 있다.
둘을 더하면 같은 시간을 두 번 센다. 집계 결과에서 기계 시간은 `machine_total_seconds`로
**따로** 적히고, 사람이 적은 대기보다 길면 `pipeline_exceeds_wait` 경고가 붙는다 — 그때
합산으로 메우지 않고 **기록 누락을 확인한다.**

겹친 구간도 두 번 세지 않는다. 사람 작업시간은 구간의 **합집합** 길이이고, 겹쳐서
덜어낸 양은 `overlap_removed_seconds`로 함께 적힌다. 기다리는 동안 다른 문항을 입력했다면
그 시간은 **사람 작업시간으로만** 센다(대기에서 뺀다).

## 1. 기계 시간 — 무엇이 기록되는가

`timings` 한 행의 모양:

```json
{"stage": "L2_rag_index", "seconds": 1.546, "backend": "sbert", "items": 56,
 "llm_cache_delta": {"failures": 0, "hits": 0, "live_calls": 0, "misses": 0, "successes": 0}}
```

- `_`로 시작하는 행(`_pipeline_total`, `_run_total`, `_probe_total`)은 **합계 행**이고
  `staged_sum`에 들어가지 않는다. 포함하면 합계가 합계를 다시 더해 두 배가 된다.
- `L0_ocr_extract` 행에는 `ocr_cache: {hits, misses, mode}`가 들어간다.
- 실행 폴더의 `timings.json`에는 `cache_profile`이 함께 적힌다 — **실행 모드는 실제
  플래그에서 적는다**(`upstage_replay` / `upstage_replay_live_llm` / `direct_live`).
  추정해서 쓰지 않는다. 이것으로 **캐시 재생 실행과 신규 처리 실행이 갈린다.**

파이프라인 단계(현재 16개): `L0_dart_load`, `L0_ocr_extract`, `L0_graph_build`,
`L1_extract`, `D6_ISSB`, `L2_embedding_backend`, `L2_rag_index`, `L3-L4_verify`(영역별),
`L5_trace_build`(영역별), `v15_artifacts`, `source_review`, `L6_report_export`,
`L5_trace_save`, `_pipeline_total`.
호출 스크립트(`scripts/live_numeric_rehearsal.py core`)가 덧붙이는 단계:
`saq_claims_parse`, `respond_sheet`, `result_json_write`, `evidence_pack_copy`,
`export_xlsx`, `export_pdf`, `_run_total`.

## 2. 사람 기록 양식

양식: `data/eval/worklog_template.csv` (헤더만 들어 있다 — **예시 시간을 넣어 두지
않았다.** 합성 시간이 실제 기록으로 오인되면 안 된다.)

| 열 | 값 |
|---|---|
| `session_id` | 리허설 세션 식별자 |
| `participant` | 참가자 식별자 |
| `method` | `manual` / `esgenie` |
| `request_round` | `1` / `2` |
| `qid` | 문항 ID |
| `step` | `원문확인` / `값입력` / `수정` / `보완자료정리` / `출력` / `처리대기` |
| `start`, `end` | **ISO 8601 날짜+시각** (`2026-10-20T09:00:00`) |
| `reused_from` | 앞 세션 결과를 재사용했으면 그 `session_id` |
| `run_dir` | `esgenie` 방식일 때 대응되는 실행 폴더 |
| `note` | 자유 기술 |

**시각에 날짜를 반드시 넣는다.** 시각만 적으면 자정을 넘긴 구간이 음수가 되고, "다음
날이겠지" 하는 임의 보정이 필요해진다. 그 보정은 하지 않는다 — `23:40`처럼 적으면
`bad_start`로 걸린다.

빈 `end`는 **추정하지 않는다.** `missing_end`로 적고 합산에서 뺀다. 합산 가능한 행이
없는 세션은 `0초`가 아니라 **`산출 불가`(`null`)** 로 적힌다.

## 3. 집계

```bash
python scripts/aggregate_worktime.py data/eval/worklog/*.csv \
  --read-run-dirs --out /tmp/worktime.json
```

`--read-run-dirs`는 `run_dir`의 `timings.json`에서 기계 시간을 읽어 **비교용으로만** 적는다.

절감률·단일 점수는 계산하지 않는다. `manual`/`esgenie`는 나란히 적는다
(§3.2: 1명 리허설 결과로 절감률을 주장하지 않는다). 출력 JSON에 비율 필드 자체가 없다.

## 4. §3.3 통과 조건 — 현재 상태

| 조건 | 상태 | 증거 |
|---|---|---|
| ① 계측 전후 `result.json` 동일성 | **통과** | `scripts/verify_timing_noop.py`를 계측 전 커밋(`d8a0de8`) worktree와 현재 HEAD에서 각각 돌려 두 덤프가 **완전히 동일**. 양쪽 sha256 `1e87143639ddf53a56506e96294d16f139b9d8306cf27b04300237d9de8f67ee` (488,423 bytes) |
| ② 단계 합 ≤ 전체 경과 + 캐시 재생/신규 예시 | **통과(합성 입력)** | `scripts/verify_timing_cache_modes.py` — 공개 DART 샘플 파이프라인 기록 1건 + 합성 LLM 캐시 프로브의 신규·재생 기록 각 1건. 세 기록 모두 `staged_sum ≤ seconds` |
| ③ 집계 스크립트 테스트 | **통과** | `tests/test_eval_worktime.py` 15건 — 겹치는 구간, 빈 `end`, 날짜 넘는 구간, 중복 합산 금지 포함 |
| ④ 리허설 1회 기록 | **미실시** | 사람 참가자가 필요하다. **AI가 시간을 만들어 적지 않는다**(§5) |

② 는 **합성 입력 기준**이다. OCR 캐시의 재생/신규는 실제 Upstage·LLM 호출이 있어야
갈리므로, 실측 예시는 키가 설정된 리허설 실행의 `timings.json`
(`cache_profile.ocr_cache`)에서 나온다. **그 숫자를 지금 만들어 적지 않았다.**
BM 실제 응답은 라벨 확정 전까지 열지 않으므로 ②의 실행 입력에도 쓰지 않았다.

## 5. 리허설 준비 — 사람이 해야 하는 부분

준비된 것: 양식(`data/eval/worklog_template.csv`), 집계 스크립트, 기계 시간 기록, 기록
디렉터리(`data/eval/worklog/`).

사람이 해야 하는 것:

1. 참가자·일정 확정(지민 배정). 참가자 식별자를 정한다 — **이름을 임의로 넣지 않는다.**
2. `manual` 회차와 `esgenie` 회차를 같은 문항 집합으로 수행하고, 단계가 바뀔 때마다
   `start`/`end`를 적는다. 기억으로 나중에 채우지 않는다.
3. `esgenie` 회차에서 실행 폴더 경로를 `run_dir`에 적는다.
4. CSV를 `data/eval/worklog/`에 넣고 §3 명령으로 집계한다.

**AI가 리허설 시간을 만들어 기록하지 않는다.** 이 저장소에는 현재 사람 리허설 기록이
**0건**이고, 테스트·안내에 나오는 시각은 모두 합성 값이라고 해당 파일에 적어 두었다.
