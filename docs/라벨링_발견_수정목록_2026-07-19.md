## 1. D1이 미래 연도 전망 노드를 실적과 비교 (네이버, 확정)

**증상**: 네이버 E 섹션 D1=100. `claim=100,000 vs node=100,000 (Δ=0%)`처럼 값은 맞는데
노드 자체가 미래 전망치.

**역추적** (`audit_trace_00266961_E_20260717_193851.json`):
```
00266961_E-3-1_2040__ocr_unstructured__5f58e770a9  → value 100,000   (2040년)
00266961_E-3-1_2030__ocr_unstructured__665f1eb262  → value 60        (2030년, 60% 감축 목표)
00266961_E-3-1_2026__ocr_unstructured__63c614b21c  → value 40,000    (2026년)
```
원문(p.4043 표)의 실제 Scope1+2 실적은 **151,019 tCO2eq(2025)**. 100,000은 Net Emission
Curve 그래프의 **축 눈금**, 71,385는 **Scope3 Category 1(구매 제품·서비스)** 값.

**원인 2겹**:
1. L0가 전망 곡선/차트 축 숫자를 실적 노드로 등록하면서 period에 미래 연도(2040 등)를 부여
2. `layer3_detect._score_d1_numeric`이 `max(compat, key=lambda n: n.period)` —
   "가장 최신 노드" 규칙 — 으로 **2040 전망 노드를 우선 선택**

**함의**: 2026-07-17에 넣은 목표 문맥 가드는 *문장 쪽* 목표 표현만 검사한다. 노드 쪽이
목표치인 경우는 못 막아 — 대칭이 없다.

**수정 방향**:
- D1: 노드 period > 보고 연도이면 비교 대상에서 제외 (또는 노드에 `is_projection` 플래그)
- 노드 선택을 "가장 최신"이 아니라 "보고 연도와 가장 가까운 과거/당해"로 변경
- L0: 차트 축·전망 곡선 유래 숫자를 실적 노드로 승격하지 않도록 필터

## 2. L0가 차트/그래프 숫자를 데이터로 오인 (네이버 실사례)

축 눈금 100,000이 노드가 됐다. 표와 그래프를 구분하지 못하는 구조적 한계 — 텍스트
레이어에서 숫자만 긁는 방식의 근본 문제. LG화학 용수 표(깔끔한 표)는 잘 읽혔으므로
"표는 되고 차트가 문제"라는 가설이 유력.

## 2-1. 각주 번호를 데이터 값으로 파싱 (삼성전기, 확정)

삼성전기 S-3-1 계열 초안값 **4.0**. 원문 p.6482 표:
```
재해율 4)                 ← "4)"는 각주 마커
        %   0.056  0.04  0.032  0.042  0.033    ← 2025년 실제값 0.033%
```
지표명 뒤 **각주 번호 "4)"를 값으로 읽었다**. 실제 재해율은 0.033%로 자릿수 자체가 다르다.
(예비조사에서 이 4.0이 p.135 각주 정의문 "4) …재해율=(재해건수/임직원 수)*100"에 매칭된 것도
같은 원인.) 표 곳곳에 `근로손실재해율5)`, `도수율6)`, `사망률3)` 등 각주 마커가 있어 재발 가능성 높음.

**§2(차트 축 눈금)와 같은 계열** — 문서의 구조적 요소(각주 마커·축 눈금·단위 표기)를 데이터로 오인.

**수정 방향**:
- 지표명 직후 `\d\)` 패턴은 각주로 간주해 값 후보에서 제외
- 값 sanity check: 항목별 상식 범위(재해율 %는 0~10 등) 밖이면 confidence_flag
- 표 파싱 시 헤더 행/단위 열과 데이터 열을 구분해 데이터 열에서만 값 추출

## 3. 지표 오매핑 — 유사 키워드 계열 혼동 (LG화학 확정)

E-5-1(용수 사용량, ton)에 **용수 재이용률(%)** 값이 들어감. 원장=2023년 2.72, 노드=2025년 7.90.
원문 표에는 "용수 취수량 / 폐수 배출량 / 용수 사용량 / 용수 재이용률"이 나란히 있어
"용수" 키워드만으로 행을 고르면 구분 불가.

**주의**: 두 값이 **같은 연도**였다면 Δ=0%로 무증상 통과했을 것 — "D1 통과 = 정확"이
성립하지 않는다는 반례.

**수정 방향**: 항목 기대 단위(`kesg_items.unit`)로 후보 필터 — 부피 항목(ton)에 % 행 배제.
Phase 2의 `unit_suspect`를 표기용에서 **후보 선정용**으로 앞당기는 것. 단위 사전에 ML·㎥ 미등록도 함께 수정.

### 3-1. 항목이 원문에 없는데도 무리하게 매칭 (네이버, 더 심한 변종)

네이버 E 초안: "용수 사용량은 **634,850.0 m³**". 원문 p.10545 실제 값은
`온실가스 총배출량 합계 tCO₂e 342,782 / 440,595 / **634,850**` — **온실가스 배출량이
용수 코드(E-5-1)로 흘러간 것**. 네이버 원문에는 용수 사용량 정량 표가 아예 없고
(용수는 리스크·정성 서술 위주), 없는 항목을 채우려다 근처 표의 숫자를 집어온 패턴.

LG 사례(키워드 겹침으로 인접 행 혼동)와 원인이 다름 — 이쪽은 **후보가 없을 때 매칭을
포기하지 않는 것**이 문제. 단위 필터(m³ 기대 vs tCO₂e 후보)만 있었어도 차단됐을 케이스.
"매칭 실패 시 미공시로 두기"가 잘못된 값을 채우는 것보다 낫다 — Phase 1 v2 표가 미공시를
정상 표기하므로 비용도 낮다.

### 3-2. 단위가 같아 단위 필터로 못 거르는 오매핑 (삼성전기)

S-3-1(여성 구성원 비율): 초안 **24.2%** vs 노드 **23.8%**. 원문 확인 결과 둘 다 실존하지만
서로 다른 지표:
- 23.8% = 여성 인력 비율(국내) — p.4208 "여성 인력 비율은 국내 23.8%, 해외는 50.4%" → **노드가 정답**
- 24.2% = **성별 임금 격차 중앙값** — p.4249 "성별 임금 격차 중앙값 24.20%" → 초안이 오인

**둘 다 단위가 %라 §3의 단위 필터로는 차단 불가.** "여성" 키워드가 양쪽에 있어 붙은 것으로,
LG 용수(키워드 겹침)와 같은 구조지만 방어선이 없다. 대응은 단위가 아니라 **행/열 레이블
전체 문자열 유사도** 또는 항목별 negative keyword(예: S-3-1에서 '임금 격차' 배제)가 필요.

부수 발견: 원문은 여성 인력 비율을 **국내 23.8% / 해외 50.4%로 분리 공시**하는데 국내 값만
집었다 — §4 스코프 태깅과 같은 범주의 사례.

## 3-3. 검증 루프의 수정 메모가 본문에 잔류 (삼성전자, 신규·심각)

`audit_trace_005930_E_20260717_201856.json` 마지막 문장:
```
- **[D2 표현 절제]** 최상급·과장 수식어를 제거하고 정량 근거가 있는 표현으로 대체하였습니다.
```
검증 루프가 재작성을 지시하면 LLM이 "이렇게 고쳤습니다"라는 **작업 메모를 본문에 써넣고**,
그것이 최종 섹션 텍스트로 남아 audit trace의 문장으로까지 집계된다. 고객 산출물에 내부
작업 로그가 노출되는 문제.

**수정 방향**: 재작성 프롬프트에 "수정 내역을 본문에 쓰지 말 것" 명시 + 후처리에서
`[D\d 표현 절제]`, `수정하였습니다` 류 메타 문장 제거. Phase 1 v2의 `_assemble_section_v2`에
필터를 두면 표·서술 조립 시점에 한 번에 걸러진다.

## 3-4. D5 시계열 방향 오판 (삼성전자)

문장: "온실가스 배출량은 16,700,000 tCO2eq으로 … **감축 추세를 유지**하고 있습니다"
D5 판정: `문장방향=증가 vs YoY=-2.1%` → 위험 발화.

실제로는 배출량이 2.1% 감소했고 문장도 "감축"이라 **양쪽이 일치**한다. 문장에 '증가'라는
표현이 없는데 방향을 '증가'로 파싱한 것 — 방향 추출 로직 버그로 보인다(확신도 중간,
`layer3_detect._score_d5_timeseries` 확인 필요).

## 3-5. 법인별 다중 컬럼 표 — 어느 값이 전사인지 판단 불가 (현대모비스)

E-4-2(재생에너지 사용 비율) 실제값은 **12.9%(2024, 전사)** — p.1646·p.2032(RE100 로드맵
12.9→65→100)·p.2406 표에서 일관 확인.

우리 결과: 초안 47,464(= p.69 **원부자재 사용(구매)량 ton**), 노드 35.0(출처 불명).
**양쪽 다 오염.**

구조적 난점: 이 보고서의 에너지 지표 표(p.2551·2598)는 한 지표를 **법인별 12개 컬럼**으로
나열한다 — 재생에너지 사용·전환율 `0.2 / 0.1 / 11.3 / 5.5 / 4.9 / 3.9 / 15.8 / 9.7 / 4.3 /
2.8 / 22.7 / 12.9` (마지막이 전사). 행 레이블만 맞추면 12개 중 아무 값이나 집을 수 있다.

**수정 방향**: 표 헤더(법인명/연도) 인식 후 전사·합계 컬럼 우선 선택 규칙. 불가하면
다중 후보를 confidence_flag로 남기고 미공시 처리(§3-1 원칙과 동일).

## 3-6. ★최고 심각도★ 목표 감축량을 배출량으로 — 배출량 89% 축소 (현대모비스)

E-3-1 초안값 **382,946 tCO2eq**. 원문 p.2390 확인:
```
누적 온실가스 목표 감축량(Scope 1+2)   tCO2eq   114,884 | 382,946 | 382,946
                                                (2030)    (2035)   (2040)
```
**"목표 감축량"의 미래 컬럼 값**이다. 실제 배출량은 p.2498 `총 온실가스 배출량(Scope1+2+3)
– 지역기반 **3,560,074** tCO2eq`, Scope3만 3,136,024.

같은 문장의 47,464도 원부자재 사용(구매)량 ton(p.69) — §3-5와 동일 건.

**세 결함이 한 값에 중첩**: ①미래 목표치(§1 계열) ②다중 컬럼 오선택(§3-5)
③'목표 감축량'↔'배출량' 정반대 개념 오매핑(§3-2 계열).

**심각도가 최상위인 이유**: 결과가 **그린워싱처럼 보인다**. 실제 356만 톤 → 보고서 38만 톤,
**89% 축소**. 그린워싱 검출 도구가 자기 산출물에서 배출량을 10분의 1로 줄여 쓰는 상황은
제품 정체성에 직결되는 리스크다. 대회 시연 전 반드시 수정.

**수정 방향**: '목표'·'감축량'·'전망' 등이 행 레이블에 포함되면 실적 항목 후보에서 배제
(§1의 문장 가드를 **행 레이블에도 대칭 적용**).

## 3-7. 부분값을 총량으로 — 에너지 사용량 89% 축소 (현대모비스, §3-6과 동일 계열)

E-4-1 초안 **1,005 TJ**. 실제 총 에너지 사용량은 **9,075 TJ**(p.2262 "2024년 에너지 총
사용량은 9,075TJ", p.2534 표 마지막 컬럼도 9,075).
1,005TJ는 p.1457 **"재생에너지 사용 전환량 1,005TJ"** — 총량 자리에 부분값이 들어갔다.
축소율 89%로 §3-6(배출량)과 동일 규모.

같은 문장의 추가 오류:
- "용수 사용량은 3,910**명**" — 3,910은 p.4885 **연령별 임직원 수(30세 미만 합계)**.
  실제 용수 사용량(취수량)은 p.3097 **1,992,921 ton**(2024 합계). **S 영역 인력 데이터가
  E 용수 항목으로 유입**됐고 단위 '명'도 그대로 따라왔다 — Phase 2 `unit_suspect`
  (ton 기대 vs 명)로 차단 가능한 유형. 영역(E/S/G) 간 교차 유입은 후보 필터에
  **항목 area 제약**이 없다는 뜻이기도 하다.
- Scope3 14,160,000 = p.1997 각주 "Scope 3: 1,416만 tCO2eq(원소재 배출 예상치 포함)"의
  **연결기준 예상치**. 실측 표(p.2481)는 3,136,024 — 4.5배 과대.

**패턴 확정**: 총량/실적 자리에 부분값·목표값·예상치가 들어가는 사고가 반복된다
(§3-6 목표감축량, §3-7 부분값·예상치). 행 레이블에서 '목표·전환량·예상·부분' 수식어를
식별해 총량 항목 후보에서 배제하는 규칙이 필요.

## 4. 스코프 불일치 — DART 지주사 vs 보고서 그룹 (신한, 별도 이슈)

S-3-1 노드 25.6%는 DART `empSttus.json`(지주회사 직원 기준) 출신. 지속가능경영보고서에는
그룹 성별 임직원 현황이 없고 별도 DATA PACK에 있음. 값 자체는 정상이나 **모집단이 다른
수치가 같은 코드에 들어감**. 노드에 스코프 태그(법인/그룹/연결)를 부여할 근거 사례.

## 4-1. (대조군) DART 구조화 경로는 정확 — 오염원은 OCR 비정형 경로

라벨링 중 확인된 반대 사례:
- G-1-2 사외이사 비율: 신한 81.8% ↔ 원문 "약 82%(사외이사 9인/총 11인)" = 81.8% **일치**
  네이버 57.1% ↔ 원문 "총 7인 중 4인 독립이사(57%)" = 57.14% **일치**
- S-3-1 신한 25.6%도 DART `empSttus.json` 계산값으로 그 자체는 정상(§4)

DART 구조화 API 5항목(G-1-2·G-1-4·G-3-4·S-2-2·S-3-1)은 API가 준 인원수로 **비율을 직접
계산**하므로 OCR 숫자 추출을 거치지 않는다. 지금까지 발견된 데이터 오류는 **전부**
`__ocr_unstructured__` 노드에서 나왔다(전망치·차트 축·지표 오매핑·억지 매칭).

**함의**: 수정 자원을 OCR 비정형 경로의 후보 선정 로직에 집중하는 것이 옳다.
G-1-2 관련 라벨 건들은 값이 아니라 *비교 대상 선택*이 문제였으므로 "검출기 오탐/교차 매칭".
