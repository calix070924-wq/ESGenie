# 제안(미적용): 임베딩 장문 입력 절단 해소

작성 2026-09-20 · 브랜치 `codex/ocr-rag-result-clarity` · **사용자 승인 전이므로 코드에 적용하지 않았다.**

실측 원본: `outputs/diagnostics/20260920_review/long_input_measurement.json`
재현 스크립트: `outputs/diagnostics/20260920_review/measure_long_input.py` (외부 API 호출 0회, 네트워크 차단)

## 1. 무엇이 문제인가

`VectorIndex._embed()`는 로컬 모델 `paraphrase-multilingual-MiniLM-L12-v2`의
`max_seq_length=128` 토큰에서 입력 뒷부분을 **오류 없이 조용히** 버린다.
현재 분할(`split_documents()`)은 항목별 추가 근거 검색 인덱스에만 적용되어 있고,
기존 영역 검색 인덱스와 D3 의미 대조 인덱스에는 적용하지 않았다.

## 2. 실측 (현대모비스 2025 보고서 저장 코퍼스, 문서 1,080개)

| 측정 | 값 |
| --- | --- |
| 한도(128 토큰) 초과 문서 | 312 / 1,080 (28.9%) |
| 문서 토큰 수 p50 / p90 / p99 / 최대 | 77 / 209 / 329 / 602 |
| 임베딩에서 빠지는 문자 | 46,058 / 208,218 (22.1%) |
| 절단 구간 뒤에만 숫자가 있는 문서 | 303개 |
| 항목별 자동 질의 64개 중 한도 초과 | 0개 |
| **E/S/G 영역 질의 한도 초과** | **3 / 3** (171 · 209 · 186 토큰) |

즉 문서 쪽뿐 아니라 **동의어 사전으로 확장한 영역 질의 3개 전부**가 한도를 넘어
뒤쪽 동의어가 임베딩 질의에서 빠진다. BM25는 전체 문자열을 쓰므로 하이브리드
가중 합(0.55 BM25 / 0.45 임베딩)에서 임베딩 쪽만 손실된다.

### 재현 가능한 "꼬리 사실 유실" 사례

절단 구간 뒤 원문의 앞 12단어를 그대로 질의로 썼다(회사명·정답·청크 ID를 넣지 않음).
303개 중 질의 생성이 가능한 303건을 top-3에서 확인:

| 결과 | 문서 수 |
| --- | --- |
| 절단 인덱스가 원문을 top-3에 못 찾음 | 234 |
| 그중 분할 인덱스가 찾음 | 117 |
| 두 인덱스 모두 찾음 | 69 |

**원문 자체의 문장을 질의로 주었는데도 절단 인덱스는 234건에서 그 원문을 top-3에
올리지 못한다.** 분할하면 그중 117건이 회복된다. 나머지 117건은 분할만으로는
회복되지 않으므로, 분할이 만능이 아니라는 점도 같이 기록한다.

## 3. 비용·처리량 영향

| | 절단(현재) | 분할 |
| --- | --- | --- |
| 임베딩 입력 수 | 1,080 | 1,486 (×1.376) |
| 인덱스 구축 시간 | 1.457초 | 2.028초 |

로컬 임베딩 모델이므로 **외부 API 토큰 비용은 늘지 않는다.** 증가분은 인덱스
구축 시간(+0.57초)과 메모리뿐이다. 모델·배포 용량은 바꾸지 않는다.

## 4. 최소 변경 제안 (승인 시)

세 갈래를 분리해 두었다. 영향 범위가 작은 것부터다.

**제안 1 — 영역 질의 절단만 해소 (영향 최소).** 임베딩 질의를 한도 안의 조각으로
나눠 각각 검색하고 문서별 최대 점수를 쓴다. 문서 인덱스와 청크 ID 체계는 건드리지
않으므로 인용·근거 ID가 그대로다. 기존 임계값(`RAG_R1_MIN` 등)과 가중치는 손대지
않는다. 영향: 임베딩 쪽 점수가 지금보다 높아질 수 있어 tier 승급 시점이 바뀔 수 있다.

**제안 2 — D3 인덱스에만 분할 적용.** D3는 생성 문장과 인용 청크의 의미 대조이고,
절단 문서가 312개다. 다만 D3는 `best_chunk_id`를 근거 ID로 기록하므로 분할하면
자식 ID가 감사 기록에 들어간다. 부모 ID로 환산해 기록하는 보완이 함께 필요하다.
영향: D3 유사도 분포가 올라가 기존 기권(abstain) 비율이 줄어든다. **점수 공식과
임계값은 바꾸지 않되, 분포가 바뀐다는 점이 이 제안의 실질적 위험이다.**

**제안 3 — 기존 영역 검색 인덱스에 분할 적용 (영향 최대).** 회수는 가장 크지만
인용 청크 ID가 전부 자식 ID로 바뀌어 보고서 인용·근거 추적·저장된 과거 결과와의
비교가 모두 영향을 받는다. 제안 1·2를 먼저 확인한 뒤에 논의할 사안이다.

## 5. 결정이 필요한 것

- 제안 1만 적용할지, 1+2를 적용할지, 셋 다 보류할지.
- 제안 2를 적용하면 D3 기권 비율이 줄어드는 변화를 수용할지(점수 공식 변경은 아님).

승인 없이는 어느 것도 적용하지 않는다. 현재 코드는 측정만 했고 동작을 바꾸지 않았다.
