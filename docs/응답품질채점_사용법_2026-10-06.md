# 응답 품질 채점기 사용법 (2026-10-06)

**상태: CLI 구현·합성 테스트 완료 / 실제 채점 미실행.**
실제 정답 라벨과 실행 결과가 없어 아직 한 번도 실제 입력으로 돌리지 않았다.
이 문서의 명령은 모두 합성 입력으로만 확인한 것이다.

채점기: `scripts/eval_response_quality.py`
입력 형식: `docs/공통답안형식_v1초안_2026-10-06.md` (**v1 초안 / 합의 대기**)

## 1. 무엇을 내고, 무엇을 내지 않는가

| 낸다 | 내지 않는다 |
|---|---|
| 행별 분류(응답 판정 × 정답 라벨 → 집계 위치) | **비율·정확도·종합 점수** |
| 판정별·집계 위치별 **건수** | 미정 산식으로 계산한 수치 |
| 값 일치·근거 일치를 **각각 따로** 센 건수 | 값 일치 건수를 "최종 답변 정확성"이라 부르는 요약 |
| 미정 조합의 행별 이유와 건수 | 산출 불가를 `0`으로 채운 칸 |
| 구조 점검(행 수·중복·누락) | — |

분자·분모가 확정되지 않아 비율을 내지 않는다. 결과 JSON의
`metrics_blocked_reason`에 그 이유가 들어 있다. 자세한 미정 목록은
`docs/지표정의표_2026-10-06.md`.

## 2. 필요한 입력

| 입력 | 어디서 오는가 | 현재 |
|---|---|---|
| 정답 라벨 CSV | 사람이 원본 증빙을 보고 작성 → `data/eval/labels/` | **없음** (원본 증빙 미확보) |
| 응답 문서 | 공통 형식 JSON, 또는 ESGenie `result.json` + 어댑터 | **없음** (실행 결과 미확보) |
| 양식 키 | `rba42` (기본값) | 있음 |
| 또는 문항 ID 목록 파일 | `data/eval/framework/rba42_qids.txt` (48행) | 있음 |

라벨 CSV의 열과 값 집합은 `docs/독립라벨링_표본패키지_B_2026-10-06.md` §3에 있다.
빈 서식을 넣으면 `LabelError`로 거부된다.

### 2.1 문항 구성을 어디서 읽는가 — `--framework` vs `--expected-qids`

| 방식 | 읽는 곳 | 필요한 것 |
|---|---|---|
| `--framework rba42` (기본) | 제품 양식 정의 | 저장소 전체 + `openpyxl`·`reportlab`. `esgenie.supplychain` 패키지를 불러오기 때문이다 |
| `--expected-qids PATH` | 문항 ID만 적힌 텍스트 파일 | **표준 라이브러리만** |

`--expected-qids`를 넣은 이유는 **채점 경로에 제품 내보내기 의존성이 필요하지 않게**
하기 위해서다. B처럼 저장소를 설치하지 않은 사람도 채점기를 돌릴 수 있어야 한다.

파일 형식은 한 줄에 문항 ID 하나, `#`은 주석이다. **문항 ID만 들어가고 정답은 들어가지
않는다.** 비었거나 중복이면 거부된다. 양식에서 다시 뽑으려면:

```bash
python scripts/export_framework_qids.py --framework rba42 \
  --out data/eval/framework/rba42_qids.txt
```

결과 JSON의 `expected_qids_source`에 `framework:rba42` 또는 `file:<경로>`가 남아,
어느 쪽으로 채점했는지 나중에 확인할 수 있다.

## 3. 옵션

```
--labels PATH                정답 라벨 CSV (필수)
--out PATH                   채점 결과 JSON 경로 (필수). 실행마다 다른 경로를 준다
--framework KEY              문항 구성을 읽을 양식 키 (기본 rba42)
--expected-qids PATH         문항 ID 목록 파일. 주면 양식 대신 이것을 쓴다
                             (제품 의존성 없이 채점할 때)
--overwrite                  기존 결과 파일을 덮어쓴다 (기본은 거부)

# 입력 방식 ① 이미 공통 형식인 응답
--answers PATH               단계마다 하나. 반복 지정 가능

# 입력 방식 ② ESGenie result.json (어댑터로 변환해서 채점)
--esgenie-result STAGE=PATH  반복 지정 가능 (STAGE는 initial|followup)
--run-id ID                  방식 ②에 필수. 실행마다 달라야 한다
--data-source TEXT           방식 ②에 필수. 응답이 무엇을 보고 나왔는가
--system NAME                변환 시 기록할 시스템 이름 (기본 esgenie)
--model NAME                 변환 시 기록할 모델
--write-common DIR           변환한 공통 형식 문서를 남긴다 (원본 추적용)
```

`--run-id`와 `--data-source`는 방식 ②에서 필수다. 어느 실행이고 무엇을 보고 나온
응답인지 결과에 남지 않으면 나중에 수치를 해석할 수 없다.

### 3.1 처음 한 번 — 합성 입력으로 동작 확인

실제 라벨·응답이 없어도 채점기가 도는지 먼저 확인할 수 있다. 설치할 것이 없다.

```bash
python scripts/eval_response_quality.py \
  --labels data/eval/examples/synthetic_run/labels_SYN.csv \
  --answers data/eval/examples/synthetic_run/answers_SYN_initial.json \
  --expected-qids data/eval/examples/synthetic_run/qids_SYN.txt \
  --out /tmp/eval_syn.json
```

종료 코드 0으로 끝나고 `bucket_counts`에 네 종류가 각각 1건씩 나온다. 행별로 무엇을
확인하는지는 `data/eval/examples/synthetic_run/README.md`에 적어 두었다.

**이 실행이 통과한 것은 평가가 아니다.** 입력이 전부 합성이고, 라벨러는 `SYNTHETIC`,
증빙 인용문은 자리값이다. 실제 평가는 원본 증빙 확보 → 독립 라벨링 → 산식 확정
뒤의 일이다.

## 4. ESGenie 채점 (방식 ②)

```bash
python scripts/eval_response_quality.py \
  --labels data/eval/labels/bm_rba42_v1_labels.csv \
  --esgenie-result initial=<실행경로>/initial/result.json \
  --esgenie-result followup=<실행경로>/followup/result.json \
  --run-id LIVE-61b6167 \
  --data-source "촬영증빙_12건(initial)+보완1건(followup)" \
  --write-common outputs/eval/common/LIVE-61b6167 \
  --out outputs/eval/scores/esgenie_LIVE-61b6167.json
```

- 0-기준 페이지는 어댑터가 **한 번만** 1-기준으로 바꾼다. 채점기에는 변환이 없다.
- `--write-common`을 주면 변환 결과가 남아 원본 `result.json`과 대조할 수 있다
  (`meta.source_ref`에 원본 경로와 sha256이 들어간다).
- `data_source`가 단계별로 다르면(보완 자료 유무) 단계마다 따로 돌리고 각각 적는다.

## 5. 대조군 채점 (방식 ①)

```bash
python scripts/eval_response_quality.py \
  --labels data/eval/labels/bm_rba42_v1_labels.csv \
  --answers <경로>/general_ai_a_RUN-1_initial.json \
  --answers <경로>/general_ai_a_RUN-1_followup.json \
  --out outputs/eval/scores/general_ai_a_RUN-1.json
```

대조군 문서는 어댑터를 거치지 않는다. 페이지가 이미 1-기준이므로 **다시 변환하지
않는다.** ESGenie 전용 `status`가 없어도 그대로 채점된다.

## 6. 반복 실행 5회를 다루는 방법

**단순 반복 호출이다.** 배치 프레임워크를 만들지 않았다.

```bash
for RUN in RUN-1 RUN-2 RUN-3 RUN-4 RUN-5; do
  python scripts/eval_response_quality.py \
    --labels data/eval/labels/bm_rba42_v1_labels.csv \
    --esgenie-result initial=<실행경로>/$RUN/initial/result.json \
    --run-id "$RUN" --data-source "촬영증빙_12건" \
    --out "outputs/eval/scores/esgenie_${RUN}_initial.json"
done
```

지켜야 할 것:

- **실행별 결과를 덮어쓰지 않는다.** `--out`을 실행마다 다르게 준다. 같은 경로가 이미
  있으면 CLI가 거부한다(`--overwrite`를 명시해야 덮어쓴다).
- **여러 실행의 같은 `qid`를 하나로 합치지 않는다.** 한 실행당 한 결과 파일이다.
  같은 단계를 두 문서가 주면 `score_documents`가 거부한다.
- **먼저 1회 실행의 정확성을 본다.** 반복 실행의 편차는 1회 결과를 해석할 수 있게 된
  뒤에 본다. 5회를 평균해 한 수치로 만드는 산식은 확정되지 않았다.

코드 3에서 나온 수치를 보고서에 쓰지 않는다. 형식 문제는 행 누락·중복·자료형 위반처럼
집계를 흔드는 것들이다.

## 8. 결과 JSON 읽는 법

| 키 | 내용 |
|---|---|
| `rows[]` | 행별 결과. `system_verdict`·`label_decision`·`value_match`·`source_match`·`bucket`과 **각각의 이유** |
| `verdict_counts` | 응답 판정별 건수 |
| `bucket_counts` | `correct_hold`·`wrong_confirmation`·`unnecessary_hold`·`unresolved` 건수 |
| `detail_counts` | `missed_mismatch`·`evidence_link_missing` 건수 |
| `value_match_counts` / `source_match_counts` | 값 일치·근거 일치를 **따로** 센 건수 |
| `unresolved_reasons` | 미정으로 남은 이유별 건수 |
| `unscored_pairs` | 라벨은 있는데 대응 응답이 없는 행 |
| `structure` | 단계별 행 수, 기대 행 수, 중복·누락·초과 |
| `documents` | 채점에 쓴 입력 문서들(시스템·실행·단계·자료 출처·형식 버전·원본 해시) |
| `format_issues` | 공통 형식 검증 문제 목록 |
| `metrics_blocked_reason` | 비율·점수를 내지 않는 이유 |
| `label_file` | 쓴 라벨 파일 경로 |
| `expected_qids_source` | 문항 구성을 어디서 읽었는가 (`framework:…` 또는 `file:…`) |
| `expected_qid_count` | 기대 문항 수 |

`unresolved`가 0이 아니면 **그 행들은 어느 지표에도 들어가지 않는다.** 분모를 임의로
채우지 않는다.

## 9. 무엇을 하면 안 되는가

- `unresolved`·`not_applicable` 행을 임의로 어느 집계 위치에 넣지 않는다.
- 산출 불가를 `0`으로 적지 않는다. 산출 불가로 적는다.
- `value_match` 건수를 바로 "최종 답변 정확성"이라고 부르지 않는다. 근거 일치와
  측정 경계가 함께 맞아야 하는지는 확정되지 않았다.
- 채점 결과를 보고 라벨을 고치지 않는다. 라벨은 채점보다 **먼저** 커밋한다.
- 결과 파일·원본 PDF·캐시·키는 커밋하지 않는다(`outputs/`는 gitignore).
